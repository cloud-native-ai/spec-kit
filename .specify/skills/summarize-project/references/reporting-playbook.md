# 项目汇报操作手册 (Reporting Playbook)

`summarize-project` 技能的细则参考：分解深度、估计默认与假设标注、状态推断、图集拆分、两图一致性清单、范围与粒度控制。工作流主框架见 [../SKILL.md](../SKILL.md)；图表语法与渲染以 draw-plantuml 技能的操作指南为准。

## 1. 工作分解深度规则

- **默认三级**：阶段（phase）→ 任务（task）→ 子任务（sub-task，可选）。至少覆盖 阶段 → 任务 两级。
- **叶子即工作包**：叶子节点是可分配、可估算的最小单位；粒度以"一句话能说清交付物"为准。
- **命名规范**：业务语言动词短语（如"完成镜像构建流水线"），不用内部代号；同一工作项在 WBS、甘特图、叙述中**逐字一致**。
- **数量控制**：单图节点 ≤15 时一图呈现；超出按 §4 拆分图集。

## 2. 时间信息的估计默认与假设标注

材料缺少日期/工期时的处理顺序：

1. **有锚点用锚点**：git 标签、发布日期、规格创建日期、迭代周期都可作为锚点。
2. **相对排期**：只知先后顺序时，用相对依赖排期（B 在 A 结束后开始），不给绝对日期。
3. **必须估计时**：按同类任务的常规工期给默认值，并在报告中**逐条显式标注**为估计假设（assumptions），格式：「假设：<工作项> 工期估计为 N 天（材料未提供）」。
4. **猜测会误导时**：转为最多一轮澄清提问（≤4 问），不静默落笔。

## 3. 进度状态推断规则

| 材料信号 | 推断状态 | 备注 |
|----------|----------|------|
| 任务清单勾选完成 / 规格状态 Implemented / 已发布 | completed | 百分比 100 |
| 进行中分支、部分完成清单、规格状态 Planned/进行中 | in-progress | 必须给出百分比及依据 |
| 未启动、无痕迹 | not-started | 百分比 0 |

- 推断依据写入报告叙述或图注；无依据的状态不标注。
- **退化情形**：项目未开始（全部 not-started）或全部完成（全部 completed）时图表仍须正常渲染，叙述中显式说明整体状态。
- **当前日期参照**：项目进行期（同时存在 completed 与 not-started/in-progress）时，甘特图必须标出当前日期参照线。

## 4. 大项目图集拆分

- **触发**：WBS 节点 >15，或甘特条目 >20，或单图宽高比严重失衡。
- **结构**：1 张概览图（只到阶段层）+ 每阶段 1 张下钻子图；概览图标注「▶ 见 图N」交叉引用。
- **一致性**：图集内命名、配色、编号、字号跨图一致；每张子图自足（不读其他图也能看懂该阶段）。
- 拆分技术（方向、配色、图注外置）遵循 draw-plantuml 的图集与大图指南。

## 5. 两图一致性自检清单（交付前必过）

- [ ] 每个带时间信息的 WBS 叶子工作项在甘特图中有且仅有一个同名单元
- [ ] 甘特图中没有 WBS 里不存在的孤儿条目
- [ ] 里程碑与关联工作项的锚定关系与材料一致
- [ ] 三态（completed / in-progress / not-started）在两图与叙述中口径一致
- [ ] 所有估计性时间/状态都已在报告假设区显式标注

## 6. 汇报范围与受众粒度

- **周期限定**：用户给出汇报周期（如"本季度"）时，甘特时间轴与叙述只覆盖该范围；范围外工作省略，或在图中以弱化样式呈现并注明。
- **粒度限定**：高管受众默认只展开到阶段层（任务层以汇总行表示）；技术受众展开到任务/子任务层。
- 无论粒度如何，阶段级结构必须完整呈现，两图一致性清单仍然全量适用。

## 7. 报告组装检查单

- [ ] 概览叙述覆盖：背景、目标、当前进展
- [ ] 每图配一段简要说明（图讲了什么、读者应关注什么）
- [ ] 元信息齐全：生成日期、汇报范围（scope）、估计假设（assumptions）
- [ ] PNG/SVG 双产出、相对路径引用、`.puml` 源文件保留、无内嵌图源码
- [ ] 默认输出位置 `docs/project-summary/`（或用户指定位置），目录内自包含
