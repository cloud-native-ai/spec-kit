# Step 3: 布局规划（场景 JSON 直出路径必做）

Excalidraw 没有自动布局引擎——**所有坐标由你计算**。先规划后编码。

## 网格法（默认策略）

1. **定节点基准尺寸**：普通节点 `200×90`，宽文本节点 `260×90`，小节点 `140×60`。全图统一 1–2 档尺寸，不要每个盒子都不一样大。
2. **定间距**：同层兄弟间距 `GAP_SIBLING ≥ 80`；层间距 `GAP_LEVEL ≥ 100`；分组内边距 `PAD_GROUP ≥ 40`。宁可稀疏不可拥挤。
3. **定方向**：主流向深窄（链式）→ `left to right`；宽浅（分层/管道）→ `top to bottom`。
4. **算坐标**：第 r 行第 c 列节点：
   - top-to-bottom：`x = MARGIN + c × (NODE_W + GAP_SIBLING)`，`y = MARGIN + r × (NODE_H + GAP_LEVEL)`
   - left-to-right：x/y 互换角色
   - `MARGIN ≥ 60`（画布留白）
5. **分组框选**：逻辑分区用大矩形背景（浅色 `backgroundColor` + `fillStyle: "solid"`，置于元素之前使其垫底）或 `frame` 元素；分组矩形尺寸 = 成员包围盒 + `PAD_GROUP`。

## 视觉语义

- **角色即位置**：枢纽/核心居中偏上；入口在左/上，出口在右/下；外部系统靠边。
- **关联即同色**：同子系统同色系（见色板）；跨组关系用对比色箭头。
- **一对多**：一个代表元素 + `×N` 文本标注，不画 N 份复制盒。

## 文本宽度估算（预留容器宽度用）

```
width ≈ Σ(每字符宽) + 左右 padding(2×20)
  CJK 字符 ≈ fontSize × 1.0
  ASCII 字符 ≈ fontSize × 0.6
```

例：`"渲染服务"` 4 个 CJK 字 fontSize 20 ≈ 80 + 40 = 120 → 容器宽 ≥ 140 才不挤。
**容器绑定文本（containerId）无需精确宽度**——渲染服务按真实字体重算并自动居中，容器给足宽度即可。

## 连线路径

- 箭头优先水平/垂直正交走向；`points` 只写折点（相对起点坐标）。
- 两节点同排：直线（2 点）；错位：3–4 个折点绕行，**不要穿过中间元素**——必要时让路（加大层间距）。
- 箭头两端尽量绑定到容器（`startBinding`/`endBinding`），语义更清晰。

## 规划产物

落笔 JSON 前，先用注释/表格列出：每个元素的 (名称, 行, 列, 尺寸, 颜色) 与箭头清单（从 → 到，标签）。这份规划同时是 Step 6 回看比对的验收清单。
