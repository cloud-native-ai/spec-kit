## Result Summary

以基准架构图驱动，对 `draw-plantuml` 技能做了三段式优化，最终产出**通用、抽象**的技能指南（非针对该基准图的专门措施）：

- **Arc-1（纯绘图）**：baseline 0.57 → 0.902。确立大图五步技术栈（×N 折叠、弱化管线突出语义色、字号层级、正交路由+隐藏边控宽高比、legend 细节仓）、连线治理、隐藏脚手架能与不能。诚实结论：纯绘图技巧存在天花板。
- **Arc-2（UML 语义）**：先做 UML 语义分析（确认部署图、修正元素种类/关系类型/构造型/接口），再绘图 → 0.903。UML 正确性与美观兼得。
- **Arc-3（视觉语义 + 结构）**：加入人类视角视觉语义（角色即位置 / 一对多表达 / 关联即同色 / 分组即框选 / 文字即负担）与元素标签最小化规则 → 0.9+。修正了「多实例画成 N 个兄弟盒致乱」的问题（改为单一代表元素 + 多重性）。

评分权重随目标演进重平衡两次（美观优先 → UML 保真作门槛 + 视觉语义一等公民），以纠正早期偏重美观的偏差。

## Lessons（沉淀入技能的可复用结论）

1. 纯绘图技巧有天花板——瓶颈常在建模（UML 语义）与达意（视觉语义），四步顺序：UML 语义 → 视觉语义 → 布局结构 → 对齐着色。
2. 大图：重复结构折叠为「一份代表 + «×N»」收益最大；正交路由+隐藏边控宽高比；长文本沉 legend；元素标签只留最小身份名（去重优先）。
3. 一对多关系：「多」用单一代表元素 + 多重性标注表达，勿画 N 份兄弟盒（会打乱对齐）。
4. 分组：宏观逻辑分区用可见命名框、同类细分组用不可见框（色彩之外的第二重分组）。
5. 反模式：per-element 浮动 note 在嵌套簇大图上会被引擎甩到页边、引长连线，得不偿失。
