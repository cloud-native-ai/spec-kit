## 2. The subset grammar refuses what it must refuse (C-008)

nothing is returned.

is left as it is and stated here.

## 3. The one behavioural repair: E-6 condition (a) counts declarations

**What was wrong.** `data-model.md` § E-6 defines `complete` as three conditions conjunctively, and R-6 states
the red line: *"A declaration file existing is not evidence for (a)"* — (a) is "each of the unit's facts has
**exactly one** declaration passing the schema and subset checks". The engine as first written checked (b) the
pointer and (c) the read point, and its (a) branch tested *required keys present* — a schema question that
`check_fact_schema` had already answered by raising the exit-2 input error, so the branch was unreachable while
looking like a judgement. Consequence, measured: one fact, two declarations, and the unit still read `complete`.

```text
--- pre-fix engine (attempt 1's file) ---
# harness-triple-check — coverage
candidates: 1
pending: 0
unclassified: 0
findings: 1
unit: shared/workflow/feedback-step.md
disposition: in-scope
state: complete
fact: feedback-prompt-threshold
finding: duplicated-fact-literal: feedback-prompt-threshold@shared/declarations/facts/feedback-prompt-threshold-copy.yaml
rc=1
```

```text
--- post-fix engine (this segment) ---
# harness-triple-check — coverage
candidates: 1
pending: 1
unclassified: 0
findings: 1
unit: shared/workflow/feedback-step.md
disposition: in-scope
state: pending
reason: duplicated-fact-literal
fact: feedback-prompt-threshold
finding: duplicated-fact-literal: feedback-prompt-threshold@shared/declarations/facts/feedback-prompt-threshold-copy.yaml
rc=1
```

**Why this is a correction, not a decision.** Exactly one reading is consistent with the recorded intent: (a)
requires *exactly one* declaration, and the fixture `negative-duplicated-fact-literal/` is the tree that
contradicts it. The change is local (one condition inside `completeness`, plus `claimed` being kept from
`claimed_slugs`), reversible, and falsifies no downstream premise — later rows read the state of the same
fixture for the first time in this segment, and the exit code does not move (`1` before and after).

**The reason named is the reason that failed.** A pending unit now carries the code of the condition that broke
it, so a duplicate reads `duplicated-fact-literal` (the `STR-011` code) rather than `third-layer-missing`. The
`verify` action was narrowed the same way — it emits `[[STR-009]]` for a unit only when `third-layer-missing` is
the reason that actually applies, so the duplicate tree does not also acquire a wrong-reason finding:

```text
--- verify, pre-fix and post-fix, byte-identical ---
# harness-triple-check — verify
declarations: 2
candidates: 1
consistency-declarations-to-carriers: 3/3
consistency-carriers-to-declarations: 1/2
residual-literals: delegated: doc-consistency-check.py --faces duplicate (this engine opens no subprocess and never re-scans)
findings: 1
finding: duplicated-fact-literal: feedback-prompt-threshold@shared/declarations/facts/feedback-prompt-threshold-copy.yaml
rc=1
```

**The leg that pins it** — `tests/contract/test_harness_triple_structure.py::test_a_fact_declared_twice_keeps_its_unit_pending`
— asserts `disposition: in-scope`, `state: pending` and `reason: duplicated-fact-literal` on that fixture. It is
red against the pre-fix output above (`state: complete`) and green against the post-fix output. It was added by
this segment, so it did not exist in T005's red run; the before/after readings in this section are the evidence
that replaces a red-first ordering, and they are stated as such rather than presented as one.

## 4. Two reader-CLI corrections (no contract clause moved)

* The CLI printed the same JSON from both arms of an `if args.format == "json"` branch; the branch and the
  `--format` flag are gone, and the CLI now says in one line that it has one rendering because the functions are
  the real surface (C-053). Nothing consumed `--format` on the reader.
* The CLI mapped every typed error to exit `2`. C-055 says the caller owns the exit code and the error carries
  the finding id precisely so a caller can tell the two apart, so it now returns `1` when the error carries a
  finding id (`STR-010` for a construct outside the subset, `STR-014` for an absent fact) and `2` otherwise —
  the degraded-layer case (C-056) keeps `2`.
