## 2. The positives (SC-008's first half)

The assertion requires at least two positive rows, that both the bare form and the
slash form are present, that each positive's `command_target` equals its own name's
command template, and that no command-surface result entered Skill resolution.

| row | raw | form | outcome | command target |
|---|---|---|---|---|
| R01 | `speckit.skills` | bare name | `command-surface` | `templates/commands/skills.md` |
| R02 | `/speckit.skills` | slash reference | `command-surface` | `templates/commands/skills.md` |
| R03 | `speckit.skills/SKILL.md` | canonical path | `command-surface` | `templates/commands/skills.md` |
| R04 | `speckit.skills` (cli operation) | cli | `command-surface` | `templates/commands/skills.md` |

Four positives, four times the same command target: the bare form, the slash form, the
`SKILL.md`-suffixed form and the CLI-operation form converge on one identifier and one
command. `enters_skill_resolution=false` is asserted per positive row, so "reported as
a command" and "never resolved as a Skill" are the same assertion.

## 3. The negative rows (SC-008's second half)

| row | raw | what a wrong reading would say | actual | why the actual is right |
|---|---|---|---|---|
| R06 | `skills/external/create-docs/SKILL.md` | "it has slashes, therefore a command" | `skill` → `skills/external/create-docs` | it is a Skill path; the name channel is decided by the `/speckit.*` set, not by the separator |
| R07 | `create-docs` | "it is a name, therefore a command" | `failure` (`dual-layer`) | nothing about a dot-free bare name is command-shaped; the live tree carries it in two layers, which is a failure, never a command |
| R05 | `speckit.nosuchcommand` | "the command does not exist, therefore not a command" | `command-surface` → `templates/commands/nosuchcommand.md` | the ruling follows the namespace, not the file: an in-namespace name is a command even when the template is absent |
| R20 | `my-draft.md` | "it has a dot, therefore a command" | `failure` | the dot is not a command marker (the module asserts a dotted, slash-free negative row exists) |

R06 is the row that falsifies "a slash means a command"; R20 falsifies "a dot means a
command"; R05 is the boundary case that shows the namespace, not the string's shape or
the file's existence, is the criterion; R07 shows a plain name is never promoted to a
command just because it is a name.

## 4. Recomputing this reading

- Denominator: the matrix fixture's own rows (30). The module prints every row it
  judged, not only the surface segment, so a row that silently changed class would be
  visible here without re-running the fixture.
- `3 passed` = the positive/negative assertion, the flipped-positive negative case and
  the negative-row-ruled-command negative case. The two `tmp_path` cases are the
  guard's own discriminating power (GM-07): relabelling a positive row as `skill`, or a
  negative row as `command-surface`, turns the same assertion red.

## 5. Disclosure

`speckit.skills` is a command-surface row by its namespace, not by the existence of
`templates/commands/skills.md`. R05 is deliberately a name with **no** template: it
records that the ruling does not depend on the file, which is why the module checks the
target's existence only for the row whose target must exist (`/speckit.skills`).
