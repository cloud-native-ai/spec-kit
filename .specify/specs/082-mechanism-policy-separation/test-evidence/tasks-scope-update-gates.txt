=== [C3] `[green:]` attribution is absent by design — the conflict and why it was not "fixed" in the contracts ===
The task-row grammar offers `[green: <contract>#<clause>]`. It is not used on any of the 52 rows.
Cause: all four contracts in this feature carry their clauses as level-2 headings (`## OD-01 — ...`,
`## SW-01 — ...`, `## GR-01 — ...`, `## GM-01 — ...`). The clause-syntax owner
(shared/definitions/contract-clause-definitions.md) classifies that shape as `md-none`, and
validate-tasks.py raises green-dangling (ERROR) for any attribution against an `md-none` contract.
Measured: the first draft carried 52 such tags and validate-tasks.py reported 51 errors, all
green-dangling. The tags were removed; the contracts were NOT re-formed, because changing
contracts/ is outside this stage's commit boundary (this stage commits tasks.md + test-evidence only)
and because `**C-N**` cannot express `OD-/SW-/GR-/GM-` ids without renaming citations across
data-model.md, plan.md and all four contracts.
The alternative that would have satisfied the validator — quoting the tag inside a fenced block —
was rejected: it makes the claim machine-invisible to the coverage accountant, i.e. it deletes the
evidence of the conflict instead of the conflict.
Consequence, stated plainly: the green-attribution checks (green-dangling / green-cross-phase /
green-clause-collision / green-path-divergence) are VACUOUSLY green on this file — zero claims means
zero violations. G2's PASS therefore says nothing about green attribution. The Format section of
tasks.md carries the same disclosure in-place so an implementer reading the file cannot mistake the
absence for an oversight.
