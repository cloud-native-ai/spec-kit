## Summary

`/speckit.team` today exposes three modes, all of which write or execute: create / modify rewrite a team definition, and run registers a run line, dispatches seats and writes a report. "Just show me the team" has no read-only entry, so a reader either opens `team.md`, `runs/` and `items.jsonl` by hand or pays the side effects of a run. This feature adds the fourth mode, **view**, as a strictly read-only presentation:

1. **One carrier** — a new internal skill `view-team` (source `skills/internal/view-team/SKILL.md`, runtime `.specify/skills/internal/view-team/SKILL.md`) resolves the inputs, invokes the deterministic program and presents its output verbatim; `templates/commands/team.md` keeps entry, routing and lifecycle only.
2. **One deterministic reader** — a new read-only program `scripts/python/team-view.py` performs every fixed-rule extraction (definition parsing, archive enumeration, report listing, ledger aggregation, latest-report summary) and composes the engine's declared read actions (`binding`, `list`, `targets --list`) for binding and anchor facts; it never re-implements definition, lifecycle or Target semantics.
3. **One closed output** — the six information groups (identity & binding / static structure / dynamic structure / persistence inventory / recent run state / archive references), each missing fact labelled `缺失` / `为空` / `不可读` / `未记录`, plus an as-of statement. No new user-facing machine-readable format; `--json` is an internal test surface.
4. **One wiring change** — frontmatter, mode table, routing flow, default and ambiguous capability lists in `templates/commands/team.md`; `docs/reference/commands/team.md` gains the fourth mode and the same change corrects its two stale run-mode statements (`run` delegates to `run-team`; the preview is disclosure, not a blocking gate).

No new store, cache, snapshot, registry or run line is introduced. A view run leaves the working tree byte-identical.

## Technical Context

**Language/Version**: CPython `>=3.8` standard library only (the program, its parsers, the test fixtures); Markdown for the skill, command template and docs.
**Primary Dependencies**: none added. The program consumes `scripts/python/goal-utils.py` (`0.0.22`) read actions and the existing `scripts/python/script_interface_cli.py` helper; tests consume the existing `pytest` runner.
**Storage**: no new store. Reads `.specify/teams/<slug>/team.md`, `runs/`, `items.jsonl`, the continuous spine files and — through the engine — `.specify/anchoring/`; writes nothing.
**Testing**: `pytest` through the unique entry `scripts/bash/run-tests.sh` (parallel default; `contract` / `integration` / `unit` markers). Fixtures are built per test under `tmp_path` by `tests/fixtures/team_view_fixtures.py`; the read-only oracle is a path+sha256 snapshot.
**Target Platform**: Linux and macOS developer/CI hosts with Python 3.8+; no bash surface is changed.
**Project Type**: framework toolkit (program + skill + command template + docs + tests) — no application runtime.
**Performance Goals**: the overview is one linear pass over the `team.md` files and spawns no process; a single-team view performs at most three engine reads (`binding`, `list`, `targets --list`). No throughput target is claimed; the bar is "no measurable addition to the suite's runtime".
**Constraints**: strictly read-only (zero writes, zero seat dispatch, zero run-line registration); exit codes closed over `0` / `2` / `3` / `4` / `5`; no third-party import; no user-facing machine-readable format; `.specify/**` is regenerated by `scripts/python/sync-mirrors.py`, never hand-edited.
**Scale/Scope**: 20 live teams and 46 live run reports measured 2026-11-24; 1 new program, 1 new skill, 4 authored text surfaces (`templates/commands/team.md`, `docs/reference/commands/team.md`, `.specify/features.md`, `.specify/features/027-team-management.md`), 3 contracts, 9 data-model entities, 4 new test files.
