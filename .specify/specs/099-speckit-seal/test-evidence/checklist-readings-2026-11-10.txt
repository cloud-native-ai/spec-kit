## L. template archived-record convention
101:2. **The third condition is an existence test over the current record.** It reads `code-review.md` — the record the latest code-segment run wrote — and asks one question: does that file contain at least one `blocking` entry? One such heading blocks the transition. A later run that writes a record carrying zero `blocking` entries no longer blocks, and that is the whole mechanism: there is no clearing action and no cleared state, so no artifact explains how an entry becomes cleared and no run is ever asked to mark one. Archived records (`code-review-<YYYYMMDDTHHMMSSZ>.md`) are never counted — they are history, not this gate's input.
