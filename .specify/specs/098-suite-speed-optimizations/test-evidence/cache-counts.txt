## 2. The probe implementation (C-011)

The probe is the run itself, not a re-run (single-run evidence discipline): `tests/conftest.py`
carries an environment-gated `pytest_sessionfinish` hook that dumps each worker's cache
counters as JSON when `SPEC_KIT_SCAN_CACHE_STATS_DIR` is set (unset in normal runs — no
output, no file). Each entry reports the `(worker, surface, root, variant)` identity plus
`build_count`, `traversals` (calls to the accountant's `_corpus_files` during the build) and
`access_count` (consumer accesses of the entry).

Reading (C-011 / SC-007):

- `framework-specs-corpus`: `build_count = 1` on the worker that consumed it and
  `traversals = 1` — one full-corpus traversal served `access_count = 4` consumers
  (`test_c10`, `test_c26`, `test_c27` and the `form_exit_code_table` payload leg; `test_c20`
  stayed cache-free by design, C-006, and ran its own subprocess scan).
- Per-file traversal bound: the corpus file made **1** managed traversal with **2** workers
  (bound: ≤ worker count), and its consumer count (4) exceeds its traversal count (1) — the
  cache is per session, not per case (FR-012).
- `framework-root-inputs`: `build_count = 1` per worker (`gw0`, `gw1`), each serving that
  worker's receipt cases; the second worker rebuilt because a session-scoped fixture is
  built once per worker — the worker component of the key, never the test count (C-001).
- `gw1` carries no corpus entry because no corpus consumer was scheduled there by
  `--dist load`; that is the expected shape, not a missing measurement.
