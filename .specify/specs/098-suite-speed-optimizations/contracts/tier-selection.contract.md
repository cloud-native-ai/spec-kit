# Contract: Runner Tier Selection (098 increment over 086 C-001…C-016)

**Owner of these propositions**: this file. **Implementation owner**: `scripts/bash/run-tests.sh`
(projected mirror `.specify/scripts/bash/run-tests.sh`, regenerated by
`scripts/python/sync-mirrors.py --write --only scripts`; never hand-edited).
**Relation to 086**: incremental. C-001…C-016 of
`.specify/specs/086-efficient-test-execution/contracts/runner-contract-086.contract.md` are NOT reopened or
reworded. This contract adds the tier dimension and states, clause by clause, how it lands inside the
existing clauses.

## A. Tier definition

- **TS-01**: Two tiers exist and only two: `fast` (the default; slow-marked tests excluded) and `full`
  (every collected test). A tier is a selection composition over the existing runner, never a second
  runner, a second selection source, or a stored test list (FR-001, FR-007, FR-008).
- **TS-02**: With no caller `-m` and no `--full`, the runner MUST run the caller's selection with the
  default exclusion [[STR-002]] applied (FR-007).
- **TS-03**: A caller-supplied marker expression MUST be detected in all accepted spellings (`-m <expr>`,
  `-m=<expr>`) and MUST suppress the default exclusion entirely. The runner MUST NOT rewrite, merge, split
  or emit a second `-m`; the caller's single `-m` owns the selection. The mode line reports `tier=caller`
  and `excluded_slow=0` (FR-009).
- **TS-04**: Paths and `-k` do not suppress the default exclusion; the tier applies first and the
  path/`-k` narrows within it. `--full` is the only switch that turns the default exclusion off (FR-007,
  FR-009).
- **TS-05**: `--full` ([[STR-003]]) MUST be a declared runner flag, documented in `--help`, that runs the
  full selection and changes no other parameter's semantics. An undeclared option keeps being rejected
  non-zero per the script interface contract (FR-008, FR-022).

## B. Composition with the serial two-pass model

- **TS-06**: In parallel mode with serial-marked members, the fast tier composes orthogonally: the parallel
  pass runs `-m "not serial and not slow"`, the serial pass runs `-n0 -m "serial and not slow"`. In the
  full tier the existing expressions are unchanged: `-m "not serial"` then `-n0 -m serial` (FR-007).
- **TS-07**: `--serial` changes execution shape only. In the fast tier its single pass runs `-n0` with the
  default exclusion; in the full tier it runs `-n0` with no marker injection; with a caller `-m` it runs
  exactly as today. `--serial` never selects a tier (FR-009).
- **TS-08**: A test carrying both `serial` and [[STR-001]] is excluded from both fast passes and executed
  only by a full-tier serial pass; the two markers MUST NOT absorb one another (edge case in
  requirements § Edge Cases).

## C. Disclosure and counts

- **TS-09**: The excluded count MUST be measured by marker enumeration over the caller's selection
  (`pytest --collect-only -q -m slow` with `-q`/`--quiet` normalised away, exit 5 treated as zero), never
  read from a hardcoded list (FR-007; same method as 086 C-011).
- **TS-10**: The mode line keeps the 086 C-002 prefix and appends `tier=<fast|full|caller>` and
  `excluded_slow=<n>`; the header line keeps 086 C-003 truthfulness and includes the injected marker
  expression when one is passed; the failed-name line is unchanged (086 C-014) (FR-023).
- **TS-11**: When the fast tier's selection **after exclusion** is empty while the caller's unexcluded
  selection is non-empty, the runner MUST print `# test runner: error=empty-selection-after-tier-exclusion
  tier=fast excluded_slow=<n>` and exit 2. In the two-pass model the condition is judged on the combined
  result (both passes empty); a run whose parallel pass is empty but whose serial pass executes marked
  tests is NOT this error, and 086 C-012's exit-5 semantics stay unchanged (FR-007).

## D. Compatibility and registration

- **TS-12**: Every 086 clause keeps its meaning under the tier dimension: C-001 (default parallel mode with
  the tier filling the selection when the caller supplies none), C-002/C-003 (disclosure lines, now with
  appended fields), C-004…C-006 (serial escape hatches; `--serial` semantics unchanged), C-007/C-009
  (worker and `--dist` resolution unchanged), C-010/C-011 (serial exclusion model unchanged), C-012…C-015
  (exit and name-list semantics unchanged), C-016 (projected mirror regenerated, never hand-edited)
  (FR-022, FR-023).
- **TS-13**: `pyproject.toml` MUST register the [[STR-001]] marker with a description stating its meaning
  and that the default tier excludes it. Missing registration or a different marker name MUST turn the
  contract test red (FR-005).
- **TS-14**: The existing runner contract suite (`tests/contract/test_run_tests_runner_contract.py`,
  40 cases) MUST remain green after the change; it is run before and after as the compatibility baseline.

## D2. Non-regression and measurement

- **TS-15**: The full-tier collected id set after the change MUST equal the implement-start full-tier
  `--collect-only -q` reading, except for tests this feature adds and a per-test disposed list recorded in
  `test-evidence/`. Deleting or renaming an existing test MUST turn the guard red. The baseline is the
  implement-start baseline slot reading (FR-011, SC-001).
- **TS-16**: The tier wall-clock criterion MUST be measured as: default-tier wall ≤ 50 % of the
  implement-start full default-parallel baseline, and full-tier wall ≤ 110 % of the same baseline, on the
  same host, same day and same runner shape; the command, exit code, complete output and duration are
  recorded, and an anti-measurement that re-merges the marked set into the default tier is recorded. No
  third full run is added for measurement; permitted component measurements are targeted and recorded
  (FR-020, SC-004, SC-005).

## E. Test obligations

New cases live in `tests/contract/test_suite_tier_contract.py`, on throwaway fixture trees (no wall-clock
assertions):

1. Default tier on a tree with one slow test: mode line `tier=fast excluded_slow=1`; the slow test does
   not run; a `--full` run executes it.
2. Tree with no slow tests: selection equals the full selection; `excluded_slow=0`.
3. Caller `-m <expr>`: tier=caller, no second `-m`, selection equals the caller's expression.
4. Caller path / `-k` only: tier=fast still applies inside the narrowed selection.
5. `--full` together with caller `-m`: tier=caller, no exclusion.
6. `--serial` × {fast, full, caller}: single pass, correct marker arguments.
7. One test marked both `serial` and `slow`: excluded from fast parallel and fast serial passes; included
   by a full serial pass.
8. All tests slow: default run exits 2 with the named error line; a two-pass run whose parallel pass is
   empty but whose serial pass has tests keeps exit 5 (C-012); an empty non-tier selection stays exit 5.
9. `--help` lists `--full`; an undeclared option still exits non-zero.
10. Header line carries the injected expression when one is applied.
11. Full-collection equality: the implement-start full-tier ids and the changed full-tier ids differ only
    by tests this feature adds plus the recorded disposed list; deleting/renaming an existing test turns it
    red (TS-15).
12. Wall-clock evidence (TS-16) is recorded at implement/closure (targeted measurement records; not a
    unit-test assertion).
