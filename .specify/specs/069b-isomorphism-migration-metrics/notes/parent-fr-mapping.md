## Numbering Rule

- **切片内连续编号**：切片正文使用自己的连续 ID 空间（FR-001–FR-014、SC-001–SC-005）。`validate-requirements.py` 的 `id-contiguous` 把任何编号缺口判为「行被删除或从未写」，父编号区间在切片内必然留缺口（本切片缺席 001–017、023–032），因此切片不沿用父编号。
- **父映射表**：切片 ID → 父 ID → 主题的对应只在本文件与切片正文的来源说明中出现；切片正文的交叉引用一律使用切片本地 ID，父编号以「父编号 NNN」文字形式出现，避免被判为悬空 ID。
- **父仍是权威**：父 `requirements.md` 的 41 条 FR / 13 条 SC 编号与条目数未变，仍是唯一规范来源；切片编号只是投影。父正文已在 2026-10-24（069a review-fix B）回写过 069a 的补强规则，因此本切片读到的父不是旧文本。
- **不是删除/合并/重排**：编号变化不改变任何要求的语义、范围、SC 取值或验收标准，不构成对父条目的删除、合并或重排；父规格中的编号区间不变。

## Handling values

| 取值 | 含义 |
|------|------|
| 逐字沿用 | 切片文本与父文本语义相同（不因编号投影而改写） |
| 切片本地化 | 父文只做引用形态调整或状态描述调整（跨切片引用改文字指针；「新建」改「已落盘」），语义未变 |
| 父内派生 | 切片把父文件里分散在其他条目 / Key Entities / Edge Cases 的**既定语句**收敛为一行；MUST NOT 用来承载新约束 |

**禁止**：把新增约束标成「父内派生」，或在语义有差异时标成「逐字沿用」——这两条正是 069a review F6 实测到的失真形态（10 个采样行里 8 行与父不一致）。本切片同一轮内已自检：三值标记与文本逐条对得上。
