## 2. Recitation check (fresh-context reader)

Method: one read-only subagent (Explore) that had no part in this feature was given only the
five paths above and asked two questions. It was not told the expected answers, and it was
instructed to answer only from those files.

Question A — *why does a long-running task that never registers a line keep showing
`nothing-running` while it is actually running?* Reader's sentence:

> Because line visibility in `/speckit.status` comes solely from the Line Registry — the
> digest's liveness probe only checks PIDs already recorded on a registry entry and never
> discovers an unregistered process — so a run that never registers is absent from the digest,
> and `nothing-running` is an accurate statement that no live line exists in the registry, not a
> missed report.

Question B — *what must a batch script's operator do so that the running batch script becomes
visible in that digest?* Reader's sentence:

> The operator must wrap the batch script with `scripts/bash/line-run.sh` (register → execute →
> close by result), which registers a line in the registry at start, so the registered entry —
> not process scanning — makes the run visible.

The reader also located every surface (owner § 九/§ 9.2, status template line 52, template
bullet, live bullet, run-team §5/§6/§7) with no surface reported as "none found".

Judgement (baseline reader per `shared/guidelines/user-facing-comprehension.md`): both
sentences are correct — neither claims the digest scans processes, and both name the carrier
plus the registry as the sole visibility source.

Verdict: SC-008 `pass`.
