## Implementation Strategy

### MVP First

The MVP is **US1 + US3** at the same P1 priority: a faster default that is untrustworthy in the three escape-hatch situations is not a shippable increment, and US3 is the property 067 RC-03 already pinned. US1 + US3 together are independently valuable and independently testable. US2 is a separate P1 increment (downstream distribution), US4 a preservation increment, US6 the parallel-safety close, US5 the ledger close.

1. Phase 1 → Phase 2 (the substrate).
2. US1 + US3 → validate from `test-evidence/`.
3. US2 → validate by the pointer guards plus the downstream init render.
4. US6 → validate by the enumerable marker and a clean parallel name diff.
5. US4 + US5 + Phase 9 → the closure measurement and the final records.

### Incremental Delivery

1. Setup + Foundational → the runner has its interface, the marker exists, the parser knows the flags.
2. US1 → default parallel with a parity record (deliverable, demoable).
3. US2 → the principle ships in four pointers plus its owner (deliverable to downstream).
4. US3 → escape hatches demonstrated (deliverable: the "always runnable" guarantee).
5. US6 + US4 + US5 → safety, preservation, ledger (closing the open ends).
6. Phase 9 → closure, records, gates.
