## 3. M-8 — the separated/attached classification matrix

`command_suffix(line)` is the parser's classification surface; `positionals` replays the same token
walk with the module's own flag sets (the check the contract's consequence clause needs — a flag VALUE
must never be read as a path).

| case | control: suffix / positionals | M-8: suffix / positionals | M-9: suffix / positionals |
|---|---|---|---|
| separated `-n 4` | full-run / `[]` | **NOT-full / `['4']`** | full-run / `[]` |
| attached `-n4` | full-run / `[]` | full-run / `[]` | full-run / `[]` |
| `--numprocesses=auto` | full-run / `[]` | full-run / `[]` | full-run / `[]` |
| separated `--dist loadfile` | full-run / `[]` | **NOT-full / `['loadfile']`** | full-run / `[]` |
| `--dist=loadfile` | full-run / `[]` | full-run / `[]` | full-run / `[]` |
| `--maxprocesses=8` | full-run / `[]` | full-run / `[]` | full-run / `[]` |
| runner default shape (`-n auto --dist load`) | full-run / `[]` | **NOT-full / `['auto', 'load']`** | full-run / `[]` |

**M-8 reading**: the three **separated** forms go red exactly as T051 requires — `-n 4` and
`--dist loadfile` are no longer full runs and their values leak into the positional list, and the shape
the runner actually emits degrades to a targeted run against two paths named `auto` and `load`. T051's
pass condition is met for the separated `-n 4` case it names.

**Disclosed, not glossed**: M-8 leaves the **attached** forms green. This matches the note already in
`notes/red-first-evidence.md` — the pre-change parser drops any unknown `-x=value` token, so reverting
`VALUE_FLAGS` alone does not reach them. That is precisely why M-9 exists as a separate leg: the two
legs together cover the separated and attached surfaces, neither covers both alone.

## 4. M-9 — the attached-form leg, measured at the token level

The attached forms are classified by `is_attached_value_flag`, so the discriminating probe is at that
surface, which is exactly what `test_attached_parallel_forms_carry_a_value` asserts:

| token | control | M-9 |
|---|---|---|
| `-n4` | True | **False** |
| `-n=4` | True | **False** |
| `--numprocesses=auto` | True | **False** |
| `--dist=loadfile` | True | **False** |
| `--maxprocesses=8` | True | **False** |
| `-n` (separated) | False | False |
| `--dist` (separated) | False | False |
| `-q` (not a value flag) | False | False |

**M-9 reading**: with `ATTACHED_VALUE_FLAGS = ()` all five value-carrying attached tokens go False, so
the case citing them fails; the negative half (the three non-attached tokens stay False) is unchanged,
so the case is not passing for a degenerate reason. M-9 is therefore discriminating.

Note why the verdict column of § 3 cannot see M-9: with only the separated handling intact, an attached
token still starts with `-` and is dropped by the `token.startswith("-")` line, so `command_suffix`
returns "full-run" and no positional leaks. The defect is invisible one level up, which is why the
contract puts this leg on the token-level case rather than on the classification verdict. Recorded here
so the green column in § 3 is not mistaken for M-9 being non-discriminating.
