## The contaminated execution — trigger and targeted disproof

Execution 1's two extra names, both from `tests/contract/test_isomorphism_map.py`:

```
tests/contract/test_isomorphism_map.py::test_no_second_document_claims_map_ownership
tests/contract/test_isomorphism_map.py::test_no_second_map_or_boundary_table_exists
```

Mechanism: both cases walk every Markdown file under the repo root (`_md_files()`) and exclude the
declared owner. The executor's mutation sandbox was a detached `git worktree` of this branch at
`.specify/.tmp/086/mutations/sandbox/` — inside the repository root, matched by `.specify/.gitignore`'s
`.tmp/` rule, therefore invisible to `git status` but **not** invisible to a filesystem walk. The
sandbox carried a full second copy of `shared/definitions/flow-class-definitions.md` and
`.specify/shared/definitions/flow-class-definitions.md`, so both cases saw a second claimant. The
assertion messages named the sandbox paths directly, which is what identified the cause rather than
merely counting it.

Targeted disproof, executed after removal: with the sandbox gone and no other change,

```
$ bash scripts/bash/run-tests.sh -q tests/contract/test_isomorphism_map.py
27 passed
```

— the same 27 passed twice (once through the runner, once through the bare engine). The names were
never red on this tree; they were red on a tree that had an extra copy of the tree inside it.

The baseline did not carry them because the T050 run happened before the sandbox existed.

**What this file does not do**: it does not amend execution 1's numbers, does not delete them, and does
not present the clean run as if it were the only execution. The slot-2 record is execution 2; execution
1 stands as the disclosed `in-slot-rerun-attempt` that triggered it.
