```

   (no output)
```

- Arm-to-arm symmetric difference: **empty** — the two arms produce the identical 19 failure names.
- New names vs the T050 baseline (`baseline-failed.txt`): **0** for both arms.
- Wall clock: arm 2 / arm 1 = 204.99 / 201.34 = **1.02×** — `-n 8` + `loadfile` is not faster on this
  host; the 8-worker cap is not justified. `loadfile` changes distribution (per-file grouping), not the
  failure set.

## Decision (A13)

**Keep the default `-n auto` + `--dist load`.** Neither arm introduces a new failure name, and the
alternative is not faster; no worker cap and no scheduler switch is adopted. The default therefore
stays as shipped in C-001, and this file is the evidence attached to that decision (T016 asks for it
either way).

## Runner guard repair enabling this arm (driver-authorised, disclosed)

Before the repair, `--workers 8 --dist loadfile` produced `-n 8 --dist load --dist loadfile` and the
mode line said `dist=load`: the runner appended its default `--dist load` while the caller guard
(C-009) covered only `-n`/`--numprocesses`. The arm could not have measured `loadfile`.

The root-cause repair, landed in this worktree as part of C1:

- `scripts/bash/run-tests.sh` (+ byte-identical `.specify/scripts/bash/run-tests.sh`): the caller scan
  now also recognises `--dist <value>` / `--dist=<value>`; when the caller supplies a scheduler the
  runner appends only `-n <effective>`, forwards the scheduler verbatim, and reports
  `dist=<caller value>` in the mode line.
- `tests/contract/test_run_tests_runner_contract.py`: two new C-009 cases pin both `--dist` forms
  (exactly one scheduler switch, `-n 2` unchanged, mode line `dist=loadfile`); 40/40 runner-contract
  tests pass.
- `contracts/runner-contract-086.contract.md` C-009: the proposition now owns the scheduler guard.

This is the one-line decision the WP-C1 executor flagged as not its own; the driver took it because
the alternative — declaring a different T016 arm — would abandon the recorded A13 question rather
than answer it.
