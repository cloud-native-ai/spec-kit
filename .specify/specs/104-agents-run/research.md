## Decisions

| ID | Decision | Rationale / FRs |
|----|----------|-----------------|
| R-01 | **Merge strategy for the command reference**: keep copy 1 (the only one describing the current surface) as the base, delete copies 2 and 3, then add the run additions and drift corrections to the single body. | Copies 2/3 are older subsets; rewording them would preserve three bodies and the drift. One body is the FR-018 requirement; the other files follow the template/skill (FR-018, SC-004). |
| R-02 | **The three syntax faces carry [[STR-001]] verbatim**: `argument-hint: "[create|refine|run] [agent-name] [task]"` in the template, the same argument-hint grammar string in the `run-agent` input contract, and the same string in the command reference Syntax block (beside the concrete `run <agent-name> [task]` line). | SC-001 demands verbatim agreement; the sibling commands (`team.md`, `goal.md`) put the mode set in `argument-hint` and the concrete forms in Syntax (FR-001). |
| R-03 | **Missing-name is a command-layer stop; missing-task is a skill-layer stop**: the template reports `missing agent name` + three capabilities + usage and dispatches nothing; the skill presents the resolved agent and reports `missing task`, then waits. | The command owns routing, the skill owns resolution; a missing name never reaches resolution, and a missing task must not become an empty brief or fall into the no-argument listing (FR-003, FR-004, A-4). |
| R-04 | **Role disclosure rides the existing presentation**: step 2 keeps the config disclosure from `execution-config.py` and adds the three role elements (this session = the edge's superagent/root, child label, return channel) as pointers to the 095 owner. | FR-007 wants disclosure, not a gate; FR-023 classes it as behavior — the truth-source text is the evidence (FR-007, FR-023). |
| R-05 | **Downlink/uplink items are named, semantics stay by pointer**: the skill lists the seven field names and the five uplink element names, each pointing at `superagent-definitions.md` § The super↔sub Protocol; no owner rule text is copied. | The owner owns the field table; the skill must make the items checkable without restating semantics (FR-008, FR-010, FR-022②). |
| R-06 | **Child label reuses the existing dispatch label**: `dispatch.sh <label>` = the dispatch `run_id` for `exec-quant.py --action collect-dispatch` = the `<label>.{live.log,jsonl,status}` triplet prefix; a retry is a new label with the old artifacts kept; no generator and no child registry. | Clarify adjudication; the engine reads exactly this carrier (B-08). Adding a generator would create a second identity source (FR-011, FR-012, A-6). |
| R-07 | **The SDD probe gains an applicability sentence, not a new gate**: the skill states it runs only when the payload assigns or names an SDD driver, and points at the narrowed predicate owner; a normal run is not blocked by a missing team/seat. | The predicate is owned by `subagent-definitions.md`; the skill currently states the probe unconditionally (B-07), which makes normal runs undecidable (FR-016, A-7). |
| R-08 | **Multi-child visibility is a pointer, not a new surface**: the skill points at the artifact triplet, `exec-quant` records and the `status-digest` role view (`parent` / `roles` / `role_set_marker` / `depth`); no store, registry or renderer is added. | FR-012 and the 095 owner's visualization section already define the carriers; a new surface would violate zero-second-mechanism (FR-015). |

## Resolved unknowns

- **U-01 — Does the engine accept a run-agent edge without a team report?** Yes: the dispatch-record carrier (`memory/exec-quant/records/*.json` + triplet confirmation) is an independent carrier, and `root` is the root literal (B-08). The SC-002 fixture therefore builds two dispatch records under one parent instead of a team report.
- **U-02 — Is the command template's `scripts:` block needed?** No: the command is pure routing; the setup script is the plan command's own concern, and `agents.md` has no `scripts:` key today (B-02). None is added.
- **U-03 — Does the docs merge need a generator?** No: `docs/reference/commands/agents.md` is hand-authored and has no mirror or generator (B-06). The merge is a direct edit; the test pins the single-copy count.
