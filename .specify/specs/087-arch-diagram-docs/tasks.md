## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel — different write targets, no dependency on an incomplete row in the same phase
- **[Story]**: the user story the row belongs to (`[US1]`…`[US5]`); Setup / Foundational / Polish rows carry none
- **[blockedBy: T027,T029]**: the row MUST NOT start until every listed row is `[X]`; the tag always names concrete row ids, never a placeholder
- **[green: <contract>#<clause>]**: this row is the one that turns that contract clause green; each clause is claimed exactly once across the file, and within one contract the clause ordinals run forward with the rows. One row MAY carry several `[green:]` tags: the claim belongs to the **test file** the row authors, and one file is one green point, so all clauses that file's assertions pin are claimed on the row that authors it. Clauses are partitioned by **actual clause subject**, never by matching numbers (`C-006` determinism is claimed by the determinism row, not by the payload row)
