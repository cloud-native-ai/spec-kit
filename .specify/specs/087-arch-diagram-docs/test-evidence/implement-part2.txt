## 3. The one remaining red — declared, not patched

`test_sc005_surfaces_reach_by_reference` asserts that `skills/external/create-docs/SKILL.md`,
`skills/external/improve-docs/SKILL.md` and `templates/commands/docs.md` name `skills/external/draw-diagram` by
path. That pointer text is delivered by T037–T044 (`create-docs/SKILL.md`) and T048/T049
(`improve-docs/SKILL.md`, and the `docs.md` dispatch sentence by T054). T031 lists no `[blockedBy]` on any of
them, so at T031 the assertion is red **by construction**, and its red is the evidence that the pointer is not
yet delivered.

Writing the pointer into the skill files from T031 was considered and rejected: it would execute T037–T044 out
of order and outside this Part's territory. The assertion's second half — no surface restates a routing row or
the `ldm_summary` schema — already holds on all three files and is re-checked on every run, so the assertion is
not vacuous while red.

## 4. A corrected premise (correction, disclosed)

`test_sc005_engine_domain_is_single_owner`'s first draft asserted `assert changed` over the changed-file set
after excluding drawn-diagram's tree, `tests/` and `docs-utils.py`. That set is empty for this feature (the only
non-excluded change is `docs-utils.py` itself), so the premise could never hold and the assertion failed with
`assert []` instead of measuring anything. It was rewritten so the **population** (`tracked_files()`, non-empty,
an empty read now means the scan broke) and the **claim** (no file this feature authored enumerates two or more
engine layers) are two separate readings, plus a containment check that the scan never reports a path outside
the scanned roots.
