# Contract — Artifact Schemas (the four structured artifacts)

**Status**: designed (this stage); implemented by `/speckit.implement`
**Owner of the schemas**: `shared/workflow/acceptance-hardening.md`. This contract states **where each schema must live**, **what it must be parseable as**, and **the one-source duty** that keeps it from being copied.

## `Path` marker on Success Criteria

- **AS-01**: `requirements.md` SC definition lines MUST carry `**Path**: final` or `**Path**: supporting` as the last token, exactly once per line, for every SC.
- **AS-02**: `scripts/python/validate-requirements.py` MUST judge the marker as a sixth check label named `path-marker`, reported with file and line, and it MUST keep its existing five labels' meanings unchanged.
- **AS-03**: An `execution`-class feature MUST carry ≥1 `final`-path SC; an `expression`-class feature MUST NOT be required to produce one.
- **AS-04**: Any consumer that cannot parse the marker MUST fail as an input error (exit `2`), never as a judgement about the feature.

## Runtime Stack & Dependency Ownership (requirements)

- **AS-05**: `requirements.md` of an `execution`-class feature MUST carry the table with the fixed column set `ID | Capability | Form | Owner | Pin | Contract | Joint acceptance | FR | Premises` and rows `RS-NNN`. `Contract` (the contract path) and `Premises` (the `EP-NNN` ids the row's FRs depend on) are **separate cells read by column name**; recovering either from `Owner` prose is a violation, because prose is what the contract-path check was unable to read before. The section's three shapes have three verdicts: absent ⇒ input error; present with zero data rows ⇒ `runtime-dependency-not-owned: runtime-stack`; a data row with a required-but-empty cell ⇒ `runtime-dependency-not-owned: RS-NNN`.
- **AS-06**: `Form` MUST be drawn from `in-scope` / `signed-contract` / `user-waived`; an `expression`-class feature MAY use `not-required` with a stated reason. **Each out-of-domain or unfulfilled `Form` shape has a stated class, none is left to interpretation**: a `Form` value outside the domain, `not-required` on an `execution`-class feature, a `Premises` cell naming an absent `EP-NNN`, and a `signed-contract` `Contract` path that does not resolve are **input errors (exit 2)** — defective cells; a `user-waived` row that cites no user ruling, a `user-waived` row whose residual-risk field is empty, and a `not-required` row with no reason are `runtime-dependency-not-owned: RS-NNN` — they are conclusions about the feature's acceptability, not about the cell's shape. `user-waived` MUST cite the user ruling and state the residual risk; the adjudication that separates the two lists is FR-009's, recorded there once.
- **AS-07**: `in-scope` MUST satisfy three separately judgeable obligations — (1) its `FR` cell is non-empty and resolves to an FR **defined in this spec**; (2) at least one `tasks.md` row quotes that FR; (3) `verification.md` carries a joint-acceptance row naming that `RS-NNN`. **The three obligations are judged at three different points, because a stage that cannot read an artifact cannot judge an obligation about it**: ① at the **requirements** stage, ② at the **tasks** stage and only by a **line-level** match (`^- \[.\] T\d{3}.*\bFR-0NN\b` — the FR appearing in a table row or in prose is not a task row), ③ at **closure**, since no stage gate takes `verification.md` as input. A stage that cannot see the carrier artifact MUST NOT report the obligation as satisfied. The judgements align with the closed reason set and MUST NOT grow it: a missing or unresolvable `FR` cell is an **input error (exit 2)** — a defect of the artifact, never a `block` about the feature — while a missing task row or a missing joint-acceptance row is `runtime-dependency-not-owned: RS-NNN` ([[STR-011]]), the same reason as the prose-only case. `signed-contract` MUST carry a `Contract` cell (a repo-relative path that resolves), a measured pin and a named joint-acceptance owner or command; a pin recorded from a run transcript is valid only while re-reading its `--version` reproduces it, so at a baseline comparison a mismatch between the freshly read `pytest --version` / `git --version` and the recorded pin makes **that comparison invalid** (input error, exit 2) and MUST NOT be read as new failures (obligation owner: `requirements.md` FR-023). `user-waived` MUST cite the user ruling and the residual risk.
- **AS-08**: A capability whose provider is external to this repository MUST NOT be recorded `in-scope`; a capability that has only prose and no row MUST be reported as `runtime-dependency-not-owned: RS-NNN` ([[STR-011]]; the canonical spelling is owned by `requirements.md` § Shared Strings). **"Only prose" is decidable, not a reading**: inside the runtime-stack section, fenced code blocks and headings are removed, and a remaining `- **Runtime dependency**: <capability> — <owner>` line is a prose declaration — with an `RS-NNN` it yields the reason, without one it is an input error naming the line; a narrative line without that marker is not a declaration. The marker is the rule; without it "prose" would be a judgement and the obligation would only bite on hand-written fixtures. A section with **zero data rows** is the degenerate case of this clause and yields `runtime-dependency-not-owned: runtime-stack` (the reserved argument, `requirements.md` § Shared Strings).

## Execution Premises and Inherited Blockers (plan)

- **AS-09**: `plan.md` of an `execution`-class feature MUST carry `§ Execution Premises` with the fixed column set `ID | Premise | Evidence | Status | Decision`, `Status` drawn from `verified` / `unverified` / `falsified`, and `Decision` present and drawn from `resolve-in-scope` / `fallback` / `user-waiver` whenever `Status` is `falsified`. The obligation that every runtime-dependent FR cites a premise is carried by the `Premises` cell of the runtime-stack row (AS-05), so it is checkable: each `EP-NNN` there MUST exist in this table and obey this clause.
- **AS-10**: `plan.md` MUST carry `§ Inherited Blockers`, whose rows name `<feature>:<row>` for every extracted dependency record and disposition it as `resolved` / `inherited` / `not-applicable` with evidence. **Extraction set (closed, three sources)**: `## Deferred` rows, `verification.md` rows in `blocked` / `deferred` / **`partial`**, and **non-empty** `deferred_tasks=` lists — `partial` is in because this feature's dependencies carry `partial` rows and nothing else. **Row locator (single grammar)**: `<feature-id>:<row-locator>`, no whitespace, `<row-locator>` ∈ `SC-\d{3}_status` / `deferred_tasks` / `deferred:<slug>`; it is the **join key**, so a locator disposed twice is an input error. The three dispositions' obligations are owned by `requirements.md` FR-011; the one this contract points at is `inherited`: its `Carrier` MUST parse as exactly one of `task:<T-ID>+test:<repo-relative test path>` (a mandatory task row of this slice **and** its test module — conjunctive, one reading) or `gate:<GATE-ID>`, MUST resolve, and MUST NOT be a deferrable `supporting`-path SC; its `Carrier slice` MUST be `this-slice` or a later slice id, and a later slice is legal only while the parent feature is `Blocked` and that slice is in `plan.md` § D10's table, in which case the row reads **`inherited-later`** — disclosed, neither blocking nor resolved. In such a row the `Carrier` is `test:<repo-relative test path>` **alone**: the task id belongs to a `tasks.md` that does not exist yet, and writing one anyway would be a fabricated id; `Carrier slice` supplies the slice, and the row MUST be re-read at that slice's closure, where the carrier MUST be completed to `task:<T-ID>+test:<path>` and resolve, or it becomes an undisposed row **in the owning slice** under the same reason. A missing, unresolvable, or deferrable-carrier `inherited` row is judged exactly as an undisposed row, under the same reason (`inherited-blocker-undisposed: <feature>:<row>`, [[STR-013]]) — the closed set does not grow.
- **AS-11**: Every FR that consumes a runtime capability MUST cite a premise ID — the carrier is the `Premises` cell of the runtime-stack row that names that FR (AS-05), not prose in the plan; a known negative conclusion MUST NOT be recorded as an out-of-scope note instead of a `falsified` premise.
- **AS-12**: The A13 boundary MUST be stated once in the owner and referenced: plan premises = planning-time facts; plan inherited blockers = dependency-inherited records; `tasks.md` § Environment Prerequisites = task-generation probe verdicts (each with probe command and ISO date). The same fact in two of the three carriers is a defect; the second occurrence MUST be converted into a pointer.

## One-source duty for the new schemas

- **AS-13**: The column names, value domains and thresholds of AS-01…AS-12 MUST appear in exactly one place — the owner document — and every template, command, skill and driver doc MUST reach them by path plus section anchor.
- **AS-14**: A guard test MUST mechanically derive the literal set from the owner's tables and assert that, across `templates/` and `shared/`, the number of non-owner occurrences equals an explicit exemption list (zero un-exempted hits). The exemption list MUST be enumerated in the test, never inferred. It has **four** members: `data-model.md` and `contracts/` (projection surfaces), `requirements.md`'s FR-003 (the declaration site), and `templates/plan-template.md` (the skeleton carrier — an empty table must carry column names or every future plan invents its own, which is precisely what the skeleton exists to prevent). Each member carries its own assertion, so an exemption can expire visibly: the projection may only narrow a domain, the declaration site carries no transition table, and the skeleton carries **column names only** — zero value-domain literals.
- **AS-15**: The plan skeleton for these two tables lives in `templates/plan-template.md` (so every future plan has the columns), while the schema semantics stay in the owner; the skeleton MUST NOT carry the domains or the invalid-row rules. It is therefore the owner doc's fourth **declared carrier**, with the same narrowing duty as the other three: it may repeat the column set and nothing else.
