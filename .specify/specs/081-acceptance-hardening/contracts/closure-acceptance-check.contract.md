# Contract — Closure Acceptance Check (`scripts/python/closure-acceptance-check.py`)

**Status**: designed (this stage); implemented by `/speckit.implement`
**Owner of the schema consumed here**: `shared/workflow/acceptance-hardening.md` § Closure Verdict. This contract fixes the **calling surface**; it never redefines the reason set's meaning.

## Purpose

One deterministic source of truth for "may this feature be called `Implemented`?" — called by `/speckit.implement` (before `Planned → Implemented`), `/speckit.review` (before `Implemented → Ready for Review`) and the `sdd-loop-driver`'s closure/merge step. A caller MUST NOT decide the question another way.

## Calling surface

- **C-01**: The entry point MUST be `scripts/python/closure-acceptance-check.py`, runnable as `python3 scripts/python/closure-acceptance-check.py …` from the repository root, importable-free (no `sys.path` assumptions about `src/`), stdlib-only, and read-only.
- **C-02**: It MUST accept `--spec-dir <dir>` (required) and MUST exit `2` with a message naming the path when the directory does not exist or a required input (`requirements.md`, `plan.md`, `tasks.md`, `verification.md`) is missing or unparsable. A missing file MUST NOT be reported as `block`.
- **C-03**: It MUST accept `--feature-detail <path>` or `--feature-registry <path>` to locate the claimed feature status. When neither is given, the resolution order MUST be: the spec directory's **own** claim carriers (`feature-detail.md`, then `feature-registry.md`), then `.specify/memory/features.md` by the spec directory's key. The spec-local layer is what lets a declarative fixture — whose key is not a registry row — still carry a determinable claim; a caller that names a carrier explicitly is never silently overruled. It MUST exit `2` if the claimed status cannot be determined from any of these.
- **C-04**: It MUST accept `--audit-existing`, which switches to the read-only audit mode of C-10.
- **C-05**: It MUST accept `--json` (machine-readable on stdout) and `--json-out <path>` (identical payload written to a file); the default human output MUST include the verdict, every reason, and the `final_path` counts (all six buckets plus `total`, in the owner doc's order).
- **C-06**: It MUST accept repeatable `--waive <CODE>:<TARGET>` entries using the same `<check>:<path>:<line>`-style waiver grammar as `pre-analyze-check.py`, and a waived reason MUST be absent from the blocking set while still being counted as waived in the summary.

## Verdict and counts

- **C-07**: The verdict MUST be exactly one of `accept` / `block`. There is no third value, no severity scale, and no advisory tier.
- **C-08**: The payload MUST carry `final_path = {pass, blocked, deferred, partial, fail, unknown, total}` computed by this script — the shape is the owner doc's `§ Closure Verdict` record, not this contract's invention, and it is closed: a seventh bucket requires revising the owner. `unknown` counts a criterion with **no status row**; `partial` counts one **measured** `partial`. No caller, template or report MAY recompute those counts; the report copies them.
- **C-09**: Every `block` MUST carry at least one reason drawn from the seven-member closed set. The seven literals are **templates** owned by `requirements.md` § Shared Strings (`STR-008`…`STR-014`); an emitted reason is an **instance** of one template, i.e. `prefix + ": " + argument` where the prefix is byte-identical to the template's and the argument satisfies that template's grammar (`SC-\d{3}` for `STR-009`/`STR-010`, `RS-\d{3}` **or** the reserved literal `runtime-stack` for `STR-011`, `EP-\d{3}` for `STR-012`, `<feature>:<row>` for `STR-013` where `<row>` is the FR-011 locator grammar `SC-\d{3}_status` / `deferred_tasks` / `deferred:<slug>`; `STR-008` and `STR-014` take no argument). `runtime-stack` is the reserved argument for the zero-data-row shape (C-13): that shape has no `RS-NNN` to name, and no-argument silence is exactly the false green the finding exists to catch. Membership is the two-part test — template match plus valid argument — and it is the only test: a bare prefix of an argument-taking template is not a member, and no third spelling, trailing colon or re-spelled placeholder is admitted. A reason outside the set (or an instance with a malformed argument) is a defect of the checker, not a finding about the feature.

## Exit codes and modes

- **C-10**: Exit codes MUST be `0` = `accept`, `1` = `block`, `2` = input missing or unparsable. In `--audit-existing` mode the exit code MUST reflect input validity only: `0` whenever the inputs parse, regardless of how many features the audit reports.
- **C-11**: `--audit-existing` MUST perform zero writes — no file created or modified anywhere, verified by `git status --porcelain` being unchanged across the run — and MUST NOT alter any historical feature status or verification record.
- **C-12**: The audit output MUST list, per affected feature, the claimed status, the computed verdict and every reason, so the list can be read without re-running the checker.

## Inputs and their readers

- **C-13**: From `requirements.md` it MUST read the SC definition lines and their `**Path**` markers, and the rows of `§ Runtime Stack & Dependency Ownership` **by column name** — the contract path is the `Contract` cell and the premise ids are the `Premises` cell, never text recovered from `Owner` prose. It MUST treat an unparsable `Path` marker as an input error (C-02), never as a `block` reason. **The runtime-row class has exactly three shapes and three verdicts, and silence is not one of them**: (a) the section is absent ⇒ input error (C-02), because the artifact is incomplete; (b) the section is present with **zero data rows** ⇒ `runtime-dependency-not-owned: runtime-stack` (block, C-09's reserved argument) — zero rows is the most complete form of "no table row" and MUST NOT be read as "this feature has no runtime dependency"; (c) a data row whose `ID` / `Capability` / `Form` / `Pin` / `Contract` / `Joint acceptance` / `FR` cell is empty where its `Form` requires it ⇒ `runtime-dependency-not-owned: RS-NNN`. A `Form` value outside the closed domain, a `Premises` cell naming an `EP-NNN` that does not exist in `plan.md` § Execution Premises, and a `signed-contract` `Contract` path that does not resolve to a file in the checkout are **input errors** (defective cells), never `block` reasons — a cell that cannot be parsed is a fact about the artifact. The `in-scope` duties are split by judgeable stage, and this script judges only the third: duty ③ (a `verification.md` row naming that `RS-NNN`) is a closure reason (`runtime-dependency-not-owned: RS-NNN`), while duty ② (a **line-level** `tasks.md` row reference) belongs to the tasks-stage gate (`requirements.md` FR-009 / `contracts/gate-wiring.contract.md` GW-06) and duty ① is an input error (C-13's defective-cell rule).
- **C-14**: From `plan.md` it MUST read `§ Execution Premises` rows and `§ Inherited Blockers` rows; both sections MUST be present for an `execution`-class feature, and their absence is an input error (the plan artifact is incomplete, not the feature failing). The `§ Inherited Blockers` table is read by column name: `Source row`, `Disposition`, `Carrier`, `Carrier slice`, evidence/note — and `Carrier slice` is part of every `inherited` judgement (C-17).
- **C-15**: From `tasks.md` it MUST count `[ ]`, `[>]` and `[~]` rows.
- **C-16**: From `verification.md` it MUST read each `SC-NNN_status`, the five measurement-ladder fields by their `SC-NNN_`-prefixed names (`SC-NNN_blocked_at`, `SC-NNN_reduced_measurement`, `SC-NNN_reduced_measurement_run`, `SC-NNN_why_reduced_insufficient`, `SC-NNN_unblock`) and the three smoke fields; it MUST evaluate V-5/V-6 of `data-model.md` (a missing ladder field, or `SC-NNN_reduced_measurement` non-empty while `SC-NNN_reduced_measurement_run=no`).
- **C-17**: From the dependency features' details it MUST extract a **closed three-source set** — `## Deferred` rows, `verification.md` status rows whose status is `blocked` / `deferred` / **`partial`**, and **non-empty** `deferred_tasks=` lists (an empty value yields no row) — and it MUST require each extracted row to appear with a disposition in `plan.md` § Inherited Blockers. `partial` MUST be in the set: this feature's two parent dependencies carry `partial` rows and nothing else, so excluding it makes the extraction set disjoint from the disposition set and the fourth finding can never fire. **The join key is the source row** and its grammar is single: `<feature-id>:<row-locator>` matching `^\S+:\S+$`, where `<row-locator>` is `SC-\d{3}_status`, `deferred_tasks`, or `deferred:<slug>` (`<slug>` = `[a-z0-9][a-z0-9-]*`; the label of the bullet, lowercased with whitespace collapsed to `-`, else `row-<n>` by 1-based position in the section). A locator that appears in two disposition rows is an **input error** (the key is not unique, so no disposition can be joined to it). **`inherited` rows are judged on three limbs, and only the first two can block**: (1) the `Carrier` MUST parse as exactly one of `task:<T-ID>+test:<repo-relative test path>` or `gate:<GATE-ID>` — the task form is **conjunctive** (a mandatory task row of this slice *and* its test module, never one of the two), (2) the named carrier MUST resolve — the task id exists in this slice's `tasks.md`, the test path appears verbatim in that row's description, the gate id exists in this slice's completion gates — and the carrier MUST NOT be a deferrable `supporting`-path SC; (3) the `Carrier slice` cell MUST be `this-slice` or a later slice id. A limb-1 or limb-2 failure is judged **exactly as an undisposed row**, under `inherited-blocker-undisposed: <feature>:<row>` (the closed set does not grow). A later-slice `Carrier slice` is legal **only** when the parent feature's claimed status is `Blocked` and that slice is listed in `plan.md` § D10's slice table; such a row is then reported as **`inherited-later`** — disclosed and non-blocking, counted separately from resolved carriers, never as an undisposed row and never as a resolved one. An `inherited-later` row's `Carrier` is `test:<repo-relative test path>` alone (the task id belongs to a `tasks.md` that does not exist yet, and a written id would be fabricated); the row is re-read at the carrier slice's closure, where the carrier MUST be completed to `task:<T-ID>+test:<path>` and resolve, else it is an undisposed row in that slice under the same reason. Any other `Carrier slice` value is an input error.
- **C-18**: The prose-only declaration rule MUST be mechanical and MUST exclude code blocks: inside § Runtime Stack & Dependency Ownership, fenced code blocks and heading lines are removed first; a remaining line whose shape is `- **Runtime dependency**: <capability> — <owner>` is a **prose declaration** — carrying an `RS-NNN` it yields `runtime-dependency-not-owned: RS-NNN`, carrying none it is an input error naming the line. A narrative line without that marker (for example an explanatory paragraph that mentions `RS-004`) MUST NOT be read as a declaration; the marker is what makes the rule decidable, and the exclusion is asserted by a fixture, not assumed.
