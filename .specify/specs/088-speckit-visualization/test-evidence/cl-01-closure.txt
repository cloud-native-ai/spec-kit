**Why test files are not a finding, stated rather than waved away.** C-50 scopes itself to "any delivered script …
on a delivery path", and `ownership-map.contract.md` C-49/C-50 both speak of what the *changed-file set
introduces*. A test that runs the delivered script under `subprocess` introduces no runtime machinery into any
delivered surface: nothing in `shared/`, `skills/`, `scripts/` or `templates/` imports those test modules, and no
product code path reaches them. The alternative — banning `subprocess` in tests — would forbid testing the
delivered script's exit codes at all, which is the opposite of the clause's intent. The guard's own RO-13 reads the
**delivered script's AST** for exactly this reason (`status-digest.py` `_delivered_script_spawns`), and it reports
`pass` (§ 3).
