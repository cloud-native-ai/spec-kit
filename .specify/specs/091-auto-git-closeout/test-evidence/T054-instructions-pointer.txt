## The T004 reading this row decides on

1. the mechanism list names "close-out" among the unattended mechanisms;
2. the pointer chain `.specify/workflow/git.md` → the `git-utils` skill (scope A) → its

What is not reachable from that section is the new reference *file* by name.

## Decision: "no edit"

Why the gap is not a defect:
- the section owns a **pointer**, not a procedure (`shared/guidelines/one-source-of-truth.md`):
  it names the state file as the single source of truth and hands the procedure to the skill;
- adding "see `skills/external/git-utils/references/closeout-commands.md`" would put a third
  hop of the same pointer chain into the instructions template, a file every project receives —
  i.e. it would copy a project-level path into a shipped template, which
  `closeout-verification.contract.md` C-7 and the shipped-text neutrality rule both forbid;
- the reader is not stranded: the skill's own § Resources list names the reference (T049), and
  every unattended mechanism's file points at the owner directly (T053's guard).
