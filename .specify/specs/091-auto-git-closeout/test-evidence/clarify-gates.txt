### Is this clarify's fault? Measured, and NO.

(a) The same error reproduces on a copy of the file in an unrelated spec dir with an
    unrelated repo root (/tmp), so it does not depend on anything clarify wrote:
    $ sed 's|...annotated Contract cell...|`pyproject.toml`|' requirements.md > /tmp/.../requirements.md
    $ pre-analyze-check.py --spec-dir /tmp/req091/.specify/specs/091-x --stage requirements --repo .
    pre-analyze-check: stage=requirements decision=pass errors=0 advisories=0 waived=0
    {"...", "summary": {"errors": 0, "advisories": 0, "waived": 0, "fr": 28, "sc": 8, ...}}
    EXIT=0
    Replacing the ONE annotated cell with a bare path makes the identical post-clarify
    artifact pass. Every clarify addition (FR-028, SC-008, 3 edge cases, 9 assumptions) is
    present in that passing copy.

(b) The requirements stage recorded decision=pass on this row at 02:26:40Z
    (requirements-gates.txt § pre-analyze-check). The text of that cell did not change in
    clarify; what changed is the newline the table row sits on (236 -> 177). The gate is
    therefore not reproducible across a byte-identical cell, which is itself the defect.

### Root cause (mechanism read from pre-analyze-check.py:559-565, 791-800)

    def clean_cell(value):
        return (value or "").strip().strip("`").strip()

`str.strip("`")` removes an UNPAIRED backtick at either end. The RS-001 Contract cell is
    `pyproject.toml`（本仓 Python 包的依赖面；`git` 按宿主提供，不列为 Python 依赖）
Three backticks: leading ` is stripped, trailing char is '）' so the right side is untouched,
leaving `pyproject.toml`（...）` with a stray inner backtick. The `os.path.exists` check on
that string fails and the checker raises InputError (= exit 2, "cell that cannot be parsed").

DEFECT (framework): a PAIRED inline code span followed by prose in a Runtime Stack cell is
parsed as a path. The cell's *path* is the paired span, not the strip()-residue. Impact
extends past this feature: any spec that annotates its `Contract` cell the same way gets a
false input error, and exit 2 reads as "argument or environment error" rather than as a
findings verdict.

### Disposition (fast-fail)

The defect is in the GATE, not in the artifact; its repair is a change to the driver skill
(the owner of pre-analyze-check.py), which this stage is forbidden to touch and which the
assignment scoped as "requirements.md + evidence + wrap-up + one commit". Recorded here as
evidence plus a framework observation on return; the cell text is left exactly as the
requirements stage produced it (no silent rewrite to make a gate green).
