# Contract: 动作分解与双技能路由

**Requirement**: `048-docs-reconcile` → Feature 037 Docs Command
**Date**: 2026-09-01

## A-1 动作四要素

每个调协动作 MUST 携带:`类型`、`目标对象`、`owning 技能`、`确认层级`(FR-005)。内容类动作 MUST 额外携带 `证据`。干跑计划的每一行 MUST 可读出这四(五)项。

## A-2 路由表(机械推导,非判断)

| 动作类型 | 判据 | owning 技能 |
|----------|------|-------------|
| 结构 | 放置/命名/新建/搬迁/归档/索引行/frontmatter/链接修复 | `create-docs` |
| 内容 | 已正确就位文档的准确性/过时/完整性/可读性 | `improve-docs` |
| 用户委托 | 用户输入分解出的额外要求 | 按其本质归入上两类(新建文档→create-docs;既有文档改写→improve-docs) |

路由 MUST 由类型机械推导,MUST NOT 逐例判断。同一动作 MUST 恰好一个 owning 技能。

## A-3 容忍带先行

差异计算 MUST 先过容忍带:带内差异标记"已一致(容忍)"且 MUST NOT 生成动作(反 churn)。验证(SC-004):无证据指瑕的文档在连续两次全量运行中被改写次数 MUST 为 0。

## A-4 内容动作的证据义务

内容动作 MUST 有具体证据(确定性 `docs-utils.py --action validate` 发现 / feedback 条目 / 用户陈述 / 已核实过时信号)。MUST NOT 为"无证据全文重读找茬"生成动作。无证据即标记容忍(FR-007)。

技能侧"无发现即停"的返回 MUST 如实进入残差报告,MUST NOT 视为运行失败。

## A-5 单文档约束与顺序分发

内容动作 MUST 逐文档顺序分发,MUST NOT 合并为跨文档批量改写。唯一例外是 improve-docs 自身允许的**单一机械维度有界批次**,使用时 MUST 显式声明该维度与文件清单。

## A-6 无上限与规模告知

单次运行的内容动作量 MUST NOT 设上限,MUST NOT 隐式截断(FR-008)。分发开始前 MUST 告知计划分发的文档数。

## A-7 中止语义

用户 MUST 能在分发开始前中止;每份文档之间为可中止点。中止后 MUST:保留已完成的逐文档结果(不回滚);未开始项标记 `pending` 进入残差报告,由后续运行继续收敛。

## A-8 报告分列

残差报告 MUST 按 owning 技能分列:各技能执行了什么、容忍了什么、待人工决策什么、pending 什么。审计日志在零收敛时 MUST 照写("全维度在容忍带内")。验证(SC-002):每个动作的执行技能归属 MUST 可从报告回查,路由正确率 100%。

## A-9 叠加不取代

用户附加输入产生的动作 MUST 与基线调协动作在**同一次运行**内交付,MUST NOT 相互挤占(FR-009)。写作委托必须同时产生内容计划与唯一落位计划:内容计划综合目标读者、任务语境、用户输入、仓库证据与边界;落位计划先检索同主题 owner,存在则转为内容更新,不存在才创建并维护人类/Agent 固定检索路径(FR-016…FR-018)。验证(SC-003/SC-007):已收敛空间上的带参调用须同时产出"调协侧零收敛的如实报告"、内容/落位证据与可发现的新文档;缺一即不达标。
