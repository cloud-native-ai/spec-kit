# Data Model: /speckit.docs 三段式调协编排

**Requirement**: `048-docs-reconcile` → Feature 037 Docs Command
**Date**: 2026-09-01

本特性不引入数据库、不新增引擎存储。以下实体是**既有文件形态之上的结构化描述**:声明是一份受管块 Markdown,动作与批次是一次运行内的编排结构(体现在干跑计划、审计日志、残差报告三件既有产物中)。

## 实体总览

| 实体 | 物化形态 | 生命周期 | 归属 |
|------|----------|----------|------|
| 目标结构声明 (Target Structure Declaration) | `.specify/docs/target-structure.md`(受管块) | 跨运行长存 | `/speckit.docs` 编排层 |
| 调协动作 (Reconcile Action) | 干跑计划行 → 审计日志条目 → 残差报告行 | 单次运行内 | `/speckit.docs` 编排层 |
| 分发批次 (Dispatch Batch) | 干跑计划的分组 + 分发前告知 | 单次运行内 | `/speckit.docs` 编排层 |

**复用的既有产物**(reconcile-pattern.md 四件强制产物,本特性不改其定义):观察快照(inline)、干跑计划(`.specify/docs/plans/<ts>-plan.md`)、审计日志(`.specify/docs/audit/<ts>-docs-audit.md`,经 `docs-utils.py --action audit` 追加)、残差报告(inline)。

## 1. 目标结构声明 (Target Structure Declaration)

项目专属文档结构契约,每次调协的期望态锚点。

**路径**: `.specify/docs/target-structure.md` —— 运行工作区**根级单文件**。与按次产物子目录 `plans/`、`audit/` 处于不同层级,这一结构差异即 FR-002a 要求的"可区分"实现方式:任何按目录轮转/清理按次产物的操作都不会触及根级文件。

**字段(受管块内)**:

| 字段 | 必填 | 取值 / 形态 | 约束 |
|------|------|-------------|------|
| `项目形态` | 是 | 自由文本一行(库/CLI/应用/框架/混合) | 来自项目实测,非模板复述 |
| `目标读者` | 是 | 自由文本一行或列表 | 至少一类读者 |
| `静态基线引用` | 是 | 指向 `.specify/skills/create-docs/SKILL.md` § Desired-State Baseline 的引用行 | **MUST 为引用,MUST NOT 复制**保留文件名清单/六类目录名等枚举(FR-002,SC-005) |
| `项目专属扩展` | 是 | 表:目录/文件 · 用途 · 依据 | 只写基线之外的项目层决定;为空时写显式"无扩展"行 |
| `内容盘点摘要` | 是 | 表或列表:主题聚类 → 归属目录 | 反映现有文档实况,用于同主题 owner 搜索与去重 |
| `固定检索入口` | 是 | 表:消费者 · 入口 · 刷新方式 | 至少覆盖人类索引入口与 Agent instructions 的 Documentation Map；只保存项目专属路径/刷新指针,不复制 create-docs 基线枚举 |
| `最后确认` | 是 | 日期 + 确认方式(随计划批准 / 显式重设) | 用于 FR-004 复用判定与 FR-015 脱节检测 |

**标记**: `<!-- DOCS_TARGET_STRUCTURE_START -->` … `<!-- DOCS_TARGET_STRUCTURE_END -->`(成对,沿用 `.specify/git-workflow.md` 先例)。标记之外的内容为人工可加注区,写入时**字节保持**。

**骨架来源**: `templates/docs-target-structure-template.md`(占位符形态),经 templates 镜像对同步到 `.specify/templates/`,并由 `specify init` 装入下游项目。

### 状态机

```
(不存在) ──设计+随计划批准──> 已确认 ──实质性修订(经确认)──> 已确认(新版)
                                  │
                                  └──检测到与项目实态脱节──> 提议重设计(FR-015,不自动改)
```

- **不存在** → 走 US-1 首次设计;同时若空间也为空,调协作用域解析为 Bootstrap。
- **已确认** → FR-004:后续运行直接复用,不重新设计(防抖)。
- **标记残缺/不可解析** → 视为"存在但不可用":停止收敛,报告标记状态并请求人工处置或授权重建;**不静默重写**(避免覆盖人工加注)。
- **脱节** → 仅提议,经确认后转入新版;绝不每次运行静默重设。

## 2. 调协动作 (Reconcile Action)

一次运行中从"现状 vs 目标"差异分解出的最小执行单元。

| 字段 | 必填 | 取值 | 说明 |
|------|------|------|------|
| `类型` | 是 | `结构` \| `内容` \| `用户委托` | 决定 owning 技能(见 action-routing 契约) |
| `目标对象` | 是 | 仓库相对路径,或"待创建:<拟定路径>" | 单一对象;多对象须拆为多动作 |
| `owning 技能` | 是 | `create-docs` \| `improve-docs` | 由类型机械推导,不由判断决定 |
| `确认层级` | 是 | `安全本地写` \| `搬迁/归档/重组` | 沿用既有分级门禁(FR-011),不新增层级 |
| `证据` | 内容类必填 | 确定性发现 / feedback 条目 / 用户陈述 / 已核实过时信号 | 无证据的内容动作**不得生成**(FR-007) |
| `来源` | 是 | `基线调协` \| `用户输入` | 用于残差报告分列与 FR-009 叠加语义核验 |
| `执行结果` | 执行后 | `已收敛` \| `已容忍` \| `待人工决策` \| `未开始(pending)` \| `技能报告无可改进` | 进入审计日志与残差报告 |

**不变量**:
- 每个动作恰好一个 owning 技能(路由无歧义)。
- 内容类动作恰好一个目标文档(守 improve-docs 单文档/次约束,FR-008);机械单维度批次是唯一例外且须显式声明维度。
- 容忍带内的差异**不生成动作**(反 churn,FR-007 / SC-004)。

## 3. 分发批次 (Dispatch Batch)

同一 owning 技能的动作聚合,是"分发前告知 + 可中止"的载体。

| 字段 | 必填 | 取值 | 说明 |
|------|------|------|------|
| `owning 技能` | 是 | `create-docs` \| `improve-docs` | 批次键 |
| `计划动作数` | 是 | 整数 | 内容批次**必须在分发开始前告知**(FR-008) |
| `顺序` | 是 | 有序动作列表 | 内容批次按严重度排序后顺序分发,不并发、不合并 |
| `中止点` | 是 | 分发开始前 + 每份文档之间 | 中止后:已完成项保留(不回滚),未开始项标 `pending` 入残差报告 |

**无上限**(FR-008):批次规模不设截断;下游实现 MUST NOT 引入隐式上限。成本可控性由"告知 + 可中止"承担,不由截断承担。
