## 2. Fix shape
- proposition_ro_04 reads each population path with `_read_any(path_text)` instead of
  `_read_text(Path(path_text))`. `_read_any` is the helper the module already documents for caller-supplied
  paths: an absolute path is opened as given, a relative one is resolved against REPO_ROOT.
- Three outcomes are now distinct instead of two:
    content carries no reporter seat, or more than one   -> fail   (a real defect)
    content passes the seat check                        -> pass
    path cannot be read at all                           -> not-evaluated, with the path in the reason
- An unreadable path is no longer appended to `defects`; it lands in its own `unreadable` list, so an unreadable
  input is never booked as an absent seat and never as a pass. A genuine defect still outranks unreadability
  (`fail` beats `not-evaluated` when both are present).

## 5. Outside-repository roster readings (SC-002 unblock path)
Two caller-supplied forms were exercised over a roster that lives outside the repository:

  a. absolute path      $ status-digest.py --action guard --roster /tmp/.../outside-team.md
     _read_any  -> TEXT     RO-04 pass           1 roster path(s) in population, no named defect
     The content decides the verdict: removing the reporter seat from the same file turns RO-04 to `fail`
     with "absent reporter seat" in the reason (asserted in the same test).

  b. non-absolute path naming an outside file (dash-encoded /tmp/... form, which no absolute-path rule can
     recover into a readable file)
     _read_any  -> None     RO-04 not-evaluated  roster path(s) in the population are unreadable, so the
                                                 seat check cannot be made: -tmp-...-dash-team.md
     This is the second new test's subject: unreadable is reported as `not-evaluated` with the path, never as
     `fail` on "absent reporter seat", and the guard exits 0 (a not-evaluated proposition is not a finding).

## 6. Red-first check (run against the exact pre-fix code, then reverted)
The pre-fix body was restored for one measurement only — `_read_text(Path(path_text))` back in place and

1 failed, 1 passed, 41 deselected in 0.30s

So the unreadable-path case is the paired red: on the old code an unreadable population path is a `fail`;
on the fixed code it is `not-evaluated` carrying the path in its reason.

**Premise correction (finding F2 as written).** The outside-repository *absolute* case does NOT go red on the
old code, and the reason is measured, not assumed: Python's `Path("/repo") / Path("/abs")` discards the left
operand, so `_read_text` already opens an absolute path verbatim. F2's "`_read_text` prefixes `REPO_ROOT`, so an
outside roster is misread as unreadable" therefore holds only for a path whose string form is not absolute; for
the absolute form SC-002's unblock step produces, the old code was already correct. The fix is still right and
still worth landing (`_read_any` states the caller-supplied-path contract in one place instead of relying on
`pathlib`'s joining rule, and the three outcomes are now separable), but the *defect class* F2 claims is narrower
than the finding states. Both halves of the error handling are covered by a test; only the second is
red-on-old-code.
