### 2.1 The RO-12 read is what this Part changed, and why

The delivered reading above passes RO-12 through `--carrier` because no run record is passed to that invocation.
The first `carrier-value-altered` run against the **pre-change** implementation reported `pass` on an obviously
illegal carrier: the module-level helper `_read_text` prefixes the repo root onto the path it is given, so a
`--run-record` path a test placed under a temp directory silently failed to read and the flag was never consulted.
Two changes were made, both **inside C-46's stated reading surface for RO-12** ("a run record's carrier value
against the two legal forms"):

1. a caller-supplied path is now opened as given (absolute) or against the repo root (relative), so `--run-record`
   reads the file the caller named instead of a repo-root-relative lookalike;
2. `--carrier` is authoritative when given, and the run record supplies the value when it is not. Precedence runs
   **flag first** deliberately: a reading that preferred the record would make a wrong `--carrier` unobservable —
   a green check that cannot go red proves nothing. The reason string names which surface answered (`from
   --carrier` / `from run record <path>`), and `mode` is echoed when the record carries it, so a reader can see the
   two surfaced together rather than take it on trust.

No literal from the test fixture is encoded in the framework source: the illegal carrier the fixture supplies is a
**test-side** value only, and `status-digest.py` neither names it nor special-cases it — the same `fail` is the
generic "matches neither legal form" branch that any illegal carrier reaches.
