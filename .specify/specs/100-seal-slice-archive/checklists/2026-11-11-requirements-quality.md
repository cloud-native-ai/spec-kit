## 一、Clarity（清晰度：术语、指称与谓词只有一种读法）

- [ ] CHK001 - 「命中」的计数单位是否被定义——同一行出现两处路径提及时算一条记录还是两条，且 FR-016 的算术与 SC-007 的「每条命中恰有一行」使用同一单位？[Clarity, Req §FR-012, §FR-016, §SC-007] — **pass**：FR-012 要求「每条命中 MUST 落入 `live-rewrite` / `dated-preserved` 二值之一」，FR-016 要求「每条命中一条记录」，SC-007 要求「每条引用命中在台账中有且仅有一行」；契约 C-204 把同一判据写成「每条扫描命中 MUST 恰有一行；二值互斥」，单位是逐次命中而非逐行。
- [ ] CHK002 - FR-006 的「父 spec 与分片范围内无本流程之外的未提交改动」是否被操作化为可判的路径集（哪些路径参与、哪些改动算「本流程之外」）？[Clarity, Req §FR-006] — **观察**：需求只给范围名词；契约 C-102 ④ 把它落为 `git status --porcelain -- <parent> <slices>`，流程位置由 C-107 固定为「merge 批次提交 → archive → archive 批次提交 → seal 判定」。判据在下游契约，需求正文未复述。
- [ ] CHK003 - `pinned_commit` 是否被定义为 apply 开始前的 `HEAD`（而不是更早的 merge 提交），使 FR-011 的回滚能逐字节恢复？[Clarity, Req §FR-005, §FR-011, §SC-010] — **观察**：需求只写「钉住的归档前提交」；契约 C-201 定义为「apply 开始前 `git rev-parse HEAD` 的 40 位小写十六进制值；apply 本身 MUST NOT 提交」。定义可判，落点在契约。

- [ ] CHK005 - FR-020 的「MUST NOT 查询 `archive-gate`」是否被操作化为可判谓词（调用 / 读取 / 导入分别算不算），使边界可静态审计而不是靠读者信任？[Clarity, Req §FR-020] — **观察**：需求正文只给禁令名词；静态审计由 FR-028 的写路径白名单与契约 C-001 的六动作集合结构性保证（动作表内无 archive-gate 入口、无 `.specify/archive/` 写路径），SC-005 以写面审计取证。禁令本身无独立检测器。
- [ ] CHK006 - FR-022 的「文档同步」是否量化到具名文档路径，并为「经既有副本生成器产生的逐工具副本」指定漂移守卫？[Clarity, Req §FR-022] — **观察**：需求点名「命令参考文档与 quickstart」两类载体与「按指针引用判定 owner」；具体路径与副本漂移由 docs owner 与命令副本生成器的既有 `--check` 机制承担（plan 的交付面表逐文件列出四条副本与 `regen-command-copies.py --check`）。需求正文按指针抵达，不复述路径表。

## 二、Decidability & Measurability（可判性：义务可由程序求值）

- [ ] CHK008 - FR-006 的五个前置合取项是否各自映射到**唯一**退出码（`1` 拒绝 vs `2` 输入缺陷），而不是留下「拒绝或按输入缺陷退出」的二选一？[Decidability, Req §FR-006, §FR-008] — **fail**：FR-006 与契约 C-102 都只写「任一不成立 MUST 拒绝（`1`）或按输入缺陷退出（`2`）」；FR-008 封闭了退出码的语义（`1` = 前置条件拒绝，`2` = 输入或环境错误），但没有一条把五个合取项逐一分配到 `1` 或 `2`。同一个 dirty 树与同一个缺清单状态可由两名读者判出不同退出码，FR-024 的测试无法钉住哪一支。
- [ ] CHK009 - 源 / 目标存在性的全部组合（两端皆在、两端皆无、跨分片混合）是否各自被分配到唯一退出码与具名理由？[Decidability, Req §FR-006, §FR-010, §SC-002, §SC-004, §Edge Cases] — **fail**：Edge Cases 相邻两条对「同一分片两端同时存在」给出互相冲突的处置——一条把它归入「部分归档 … 按输入缺陷退出 `2`」，另一条把它归入「目标目录已存在且源也存在 … `destination-exists` 拒绝（退出 `1`）」；FR-006 的「每个分片恰好存在一侧」按分片判定，无法区分跨分片混合。需求正文因此不能唯一决定该状态的退出码。
- [ ] CHK010 - 「git 变更视图 MUST 呈现重命名对」的**比较基**与命令形态是否被指定（对哪个提交、`git diff` 还是 `git diff --cached` / `git diff HEAD`、`git mv` 后是否先暂存）？[Decidability, Req §FR-003, §SC-001] — **fail**：US1 Independent Test 与契约 C-106 都写 `git diff --name-status -M`，但 `git mv` 本身会把重命名写入索引，此时 `git diff`（工作树 vs 索引）对已暂存的移动不呈现重命名对；需求未点名比较基或暂存步骤，「无纯删除」的断言在不同命令形态下可得出相反读数。
- [ ] CHK011 - FR-016 / SC-007 的三组算术（扫描命中 = live + dated；runtime-updated + absent = 运行期载体数；移动文件行数 = files 行数）是否各有明确计数单位，且每侧可只凭清单复算？[Decidability, Req §FR-004, §FR-016, §SC-007] — **pass**：三组等式在 FR-016 与 SC-007 逐条写出；命中单位由 C-204 钉为「每条扫描命中恰有一行」，文件行数由 C-203 钉为 `file_count = files 行数`，运行期载体数由被声明的载体名册决定；三组两侧都只读清单即可复算。
- [ ] CHK012 - 「零新增红（按失败 node-id 名单比对）」的基线是否在具名时点、以具名产物捕获，且比较单位固定为 node-id 集合？[Decidability, Req §FR-024, §FR-025] — **观察**：需求正文只说「按失败 node-id 名单比对，既有红不修不掩」；基线 owner 由 tasks GATE-1 / T046 钉为 `/speckit.implement` step 6 的 `**Test runs**`（`--names-out` 捕获、`comm -13` 比对），本流程只消费、不另立第二路径。判据可判，落点在 tasks 与实现入口。
- [ ] CHK013 - 「未解析引用 = 0」的扫描根是否被声明为封闭集，且**排除项**（归档清单自排除、父 `seal.md` 排除）与包含项同样显式？[Decidability, Req §FR-015, §SC-003] — **观察**：FR-015 只说「覆盖契约声明的扫描根」，FR-012 把载体名册与扫描根的 owner 委派给本特性契约；契约 C-301 给出 live / dated 封闭名册并明写父级 `seal.md` MUST NOT 作为 live 载体，C-308 给出改写规则。判据落在契约，需求按指针抵达。
- [ ] CHK014 - 清单**读取侧**对未知 / 缺失 / 不可解析字段的行为，是否在需求正文中作为规范义务存在（而不是只出现在 Clarifications 的问答里）？[Decidability, Req §FR-005, §FR-008, §FR-010] — **观察**：FR-005 只封闭写侧（未知字段 MUST NOT 写入）；读取侧「未知或缺失字段以 exit `2` 拒绝」由 Clarifications Q3 与契约 C-202 给出，且 C-112 把「清单存在但不可解析」映射到 `archive-manifest-invalid`。判据可判，规范形态在澄清记录与契约，未升为 FR。
- [ ] CHK015 - `archive-drift`——契约 C-103 的封闭 exit `2` 理由之一——是否属于需求正文的封闭理由词汇表，还是需求只声明了三个退出码而未声明理由集？[Decidability, Req §FR-009, §FR-027, §SC-009] — **观察**：需求只封闭退出码 `0/1/2` 与少数具名结局（`already-archived`、`not-applicable`）；完整理由集由契约 C-103 的封闭清单拥有（拒绝 6 值 + 错误 9 值，含 `archive-drift` / `partial-archive`）。需求未声明理由集即未与契约冲突，但读者从需求正文读不出该词。
- [ ] CHK016 - 运行期 line registry 的两种结局（`runtime-updated` / `absent`）是否各自可判，且 `absent` 的原因（状态根不可解析 vs 记录缺席）被分别记录？[Decidability, Req §FR-017, §SC-008] — **pass**：FR-017 逐条给出两种情形与对应清单行，要求缺席时「记 `absent` 并说明原因」且不阻断；SC-008 要求两种情形各有夹具、把缺席改成阻断时测试转红；`.specify/state/**` 的 git-ignored 属性在同一 FR 内声明，与 FR-026 的「零 diff」相容。
