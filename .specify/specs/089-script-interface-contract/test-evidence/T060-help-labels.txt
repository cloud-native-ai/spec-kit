T060 — the four help labels on every applicable python script (2026-11-07)
==========================================================================

Owner of the rule: shared/definitions/script-interface-definitions.md section 2 (the four
labels are a closed set). Criterion: `--help` and `-h` exit 0 and the body carries
`usage:`, `options:`, `side-effects:`, `exit-codes:` (criteria contract C-7).

MECHANISM (one helper owns the text; scripts only name their parser)
--------------------------------------------------------------------
`scripts/python/script_interface_cli.py` gained two public entry points:

* `configure_parser(parser, *, effects=None, codes=None)` — for an argparse script. Writes
  the two label LINES argparse cannot produce into `parser.epilog`, appends after an existing
  epilog rather than replacing it, and switches the formatter to
  `RawDescriptionHelpFormatter` only when the caller left argparse's default. `usage:` and
  `options:` come from argparse itself.
* `fill_help_labels(help_text, *, effects=None, codes=None, update=None)` — for a hand-rolled
  help body (`_HELP = """..."""`), which no parser owns. Additive and idempotent; a body that
  already states a label keeps its own text.

Honest generic defaults (used when a script does not say otherwise):

  side-effects: writes only through the options it documents; a flag-only invocation writes nothing
  exit-codes: 0 success; 1 a documented check failed; 2 argument or environment error

GENERATOR (one-time, applied once, not kept in the tree)
-------------------------------------------------------
`/var/tmp/086-pkg4b1/gen_help_labels.py` (217 lines, AST-based, run with `--apply`):

  * found every module-level `argparse.ArgumentParser(...)` assignment;
  * inserted `configure_parser(<name>)` right after the CONSTRUCTION, at the construction's
    own indent, using the assignment's `end_lineno`;
  * skipped fragments (`parents=[...]` without a `prog`/`description` of their own), parsers
    built with `add_help=False`, and `add_parser(...)` results spent on a subcommand;
  * inserted `from script_interface_cli import configure_parser  # noqa: E402` after each
    module's `_SIG_DIR` sys.path setup (a header import fails: the helper is not on the path
    until then), shifting downstream lines by one when the import landed above them;
  * was re-run only on files it had not already patched; the three files whose call had
    landed on a fragment (`history-utils.py`, `record-retention.py`, `run-determination.py`)
    were corrected by hand onto the parser each script actually prints.
