## E2 异常 (Anomaly)

**基数**: 每次运行 0…n

| 字段 | 形态 | 约束 | 来源 FR |
|---|---|---|---|
| 发现点 | 单元 + 动作标识 | 必填;用于同一性键 | FR-010 |
| 被证伪的预期 | 一句散文 + 其来源路径 | 必填;用于同一性键 | FR-010 |
| 所属异常类 | E3 的 ID(`FF-n` / `RP-n`)或"未归类" | 未归类时按存疑从严归快速失败 | FR-012, FR-016 |
| 爆炸半径 | 工件集合 | 判据 = 是否超出当前动作的声明范围(D-14);声明范围来源按 territory → plan 源码树/镜像义务行 → 命令产出声明 的优先级,三者皆无则为当前文件 | FR-073, FR-010(d) |
| 是否可逆 | 二值 | 委托 `shared/guidelines/confirmation-gates.md` 的判据,MUST NOT 在本纪律内复述 | FR-016 |
| 分流结论 | E4 | 必填 | FR-009 |

**同一性键(2026-09-23 用户裁定:拆为两个键)**: **复发键 = `被证伪的预期` 单键**,供 FR-014 的"同一异常第二次出现"判定——复发看的是同一个被推翻的预期,与在哪里再次撞到它无关;**独立键 = `(发现点, 被证伪的预期)` 二元组**,供 FR-044 的"两次独立观察"判定——独立性恰恰要求发现点不同。二者 MUST NOT 混用:初版共用一个二元组,使 FR-014 在跨发现点复发(最常见形态)下不可达,该不可达性由两位独立评审者各自发现(取证 `notes/sc001-dual-review.md` §2)。没有键,"同一"无从认定,两振升级与生长阈值都不可实现。

**关系**: 归属恰好一个 E3;产出一个 E4;若 E4 = 快速失败则产出一个 E6,若 = 顺手修复则产出一个 E7。

## E3 异常类 (Anomaly Class)

**物化位置**: `shared/guidelines/fast-fail.md` 的两份清单节内,每类一行  
**基数**: 首版 ≥ 9(FF 侧)+ ≥ 6(RP 侧);**总数不设钉子**(可生长)

| 字段 | 形态 | 约束 | 来源 FR |
|---|---|---|---|
| ID | `FF-n` / `RP-n` | 前缀实测零命中;`n` 在同侧唯一 | D-11 |
| 类名 | 短名词 | 必填 | FR-019 |
| 判据 | 一句可复现的认定条件 | **必填**——没有判据的条目使"每条携判据"退化为"该节非空",即 STR-006 禁止的空转断言 | FR-019, FR-076 |
| 实证 | 路径或教训小节 | 首版条目 MUST 指向本仓已实测的失效,MUST NOT 用假想案例 | FR-016, FR-021 |

**条目语法**(固定,守卫据此枚举):

```
- **FF-n <类名>** — 判据:<一句> | 实证:<路径或小节>
```

**点名 7 项的落位**(FR-016 + SC-002 的分母):盲检四成因 = `FF-2`…`FF-5`;`git diff` 三形态 = `FF-6`…`FF-8`。守卫按**这 7 项逐项可定位**断言覆盖,MUST NOT 按清单总条数断言。

**关系**: 被 E2 归属;被 E9(清单移动)在两极间迁移。

## E19a 编排者 (Orchestrator) / E19b 子代理 (Subagent)

**物化位置**: 无持久制品;其所有权分层由 E1 的 `## 子代理派发注入` 节载明  
**基数**: 每次派发 1 : 1…n

| 角色 | 拥有什么 | MUST NOT |
|---|---|---|
| E19b 子代理 | **异常事实**(经 E14 回抛) | MUST NOT 假定自己拥有用户通道;MUST NOT 就地修平后交回看起来干净的结论;MUST NOT 在子代理内自行消化需裁定的异常 |
| E19a 编排者 | **上送件**(E6 的组装) | 收到 E14 的异常停 MUST NOT 原样重派或要求"再试一次";MUST NOT 把缺 E14 的回传读作干净 |

**异常停 ≠ 普通失败**:异常停 MUST NOT 被计入既有的**任何**失败规则——包括两振停滞、"连续两次派发失败即降级"(二者针对 upstream error 与结构性停滞)、以及"非并行任务失败即停 / 并行任务成功者继续、失败者上报"。它是一次**上送**,不是一次失败。

**并行派发下的一处异常**:与该异常无关的其余子代理按既有并行规则处理,但汇总 MUST 把该异常呈现为**未决项**,MUST NOT 因多数已回传而把结果当作完整。

## 校验规则

### V1 三标记互斥(FR-063)

`[fast-fail]`(E8)、`fast-fail-clause`(E12)、`ANOMALY:`(E14)与纪律路径 `shared/guidelines/fast-fail.md` **两两互不为子串**。

**实测**(六对组合逐一验证,2026-09-23):零违规。  
**为何必需**:引擎按大小写不敏感子串匹配,若 `fast-fail` 作标记,则任何提到纪律路径的反馈行都被计为观察命中,FR-041 的"干净运行不追加空洞条目"在机械上不可判别。  
**守卫形态**: 断言四个字面量的两两子串关系为空集(纯字符串运算,不依赖制品存在)。

### V2 子句副本字节相等(FR-052)

对每个 E16 制品与 E15 通道三的落点:以成对定界符提取区间内文本,与 E1 拥有者区间的文本 `==` 比较。

**守卫形态**: 复用房子惯用法 `read_bytes()` 相等,但比对单位是**提取出的子串**而非整文件——这是本特性与 051 守卫的唯一形态差异,且该差异由定界符使其可机械断言。  
**漂移修复**: 从拥有者手工重灌,MUST NOT 就地改写副本。

### V3 子句长度与门控中立(FR-048 / FR-036 / D-2)

E12 的拥有者字面量 MUST ≤ 10 行且 ≤ 1,200 字节;其每一行 MUST NOT 命中 `BLOCKING_RE`。

**守卫形态**: 行数与字节数直接度量;`BLOCKING_RE` MUST 以 `importlib` 从 `scripts/python/scan-confirmation-gates.py` 载入取真,**MUST NOT 重抄 17 条模式**(重抄即副本,会漂移)。  
**实测**: 草稿子句 8 行 / 933 字节 / 0 命中。

### V4 清单条目语法与 7 项覆盖(FR-076 / FR-016 / SC-002)

两份清单的每行 MUST 匹配 `^- \*\*(FF|RP)-\d+ `,且 MUST 含 `判据:` 分隔符;`FF-2`…`FF-8` MUST 逐项可定位并分别对应盲检四成因与 `git diff` 三形态。

**守卫形态**: 枚举 + 逐项断言。MUST NOT 退化为"该节非空"。  
**反空真哨兵**: 断言"未点名项集合为空"时,MUST 同时断言"7 项中至少一项命中"——否则"空因为对"与"空因为盲"不可区分。

### V5 常驻章节位置与不内联(FR-005 / FR-006 / D-1)

`## Fast Fail Discipline` 在模板与活动指令文件中**各出现且仅出现一次**;其位置 MUST 满足 `Token Efficiency < User-Facing Comprehension < Fast Fail < Dogfooding`(严格排序);MUST NOT 落在 Documentation Map / Proactive Flow Trigger / Fact Checks 三节连续窗口内;模板 MUST NOT 内联 E1 的任何 H2 节名。

**守卫形态**: 与既有 `test_c7` / `test_c8` 同形,新增一节断言本章节的相邻关系。

### V6 双落点与四钉上调(FR-031 / FR-032 / D-7)

宪章模板原则数 13 → **14**;活动宪章原则数 15 → **16**;命令 `MUST include` 条目 7 → **8**;活动宪章版本 ≥ **1.13**。四处钉子在**同一批**变更中上调。

## 状态机

### S1 异常的分流(E2 → E4 → E6/E7)

```
发现异常
  ├─ 命中 E5b 且 FR-010 四条全成立 ────────────► 顺手修复 ──► E7 披露条目(并入收尾)
  ├─ 需裁定 / 证伪下游前提 / 半径越界 ──────────► 快速失败 ──► E6 上送件 ──► E10 裁决记录
  ├─ 两侧清单均未命中 ─────────────────────────► 快速失败(存疑从严)
  ├─ 同时命中两侧 ─────────────────────────────► 快速失败(上送极优先)
  └─ 同一异常第二次出现(按同一性键)──────────► 快速失败(两振升级)
```

**终止条件**: 快速失败终止该动作链;上送通道不可用时 E6 MUST 落盘为失败报告,MUST NOT 转为静默继续。

### S2 清单条目的生长(E8/E11 → E9 → E5a/E5b)

```
观察累积
  ├─ ≥2 次独立观察(E8) 或 1 次用户直接纠正(E11)
  │     └─► proposed
  │           ├─ 证据成立 ──► moved  ──► 修订真源文档 + 原处措辞收敛为指针
  │           └─ 证据不足 ──► rejected(如实记录,MUST NOT 静默调参)
  └─ 方向由证据决定:朝上送极 = 升级,朝修复极 = 降级(两侧资格对称)
```

**不变量**: 每次 `moved` MUST 留痕到 E8 的条目 ID 或一次可定位的 E11;`rejected` MUST 被记录。

### S3 子代理派发的一跳(E13 → E15 → E19b → E14 → E19a)

```
编排者准备派发
  ├─ E13 自检:outgoing 提示/载荷含 STR-009 ?
  │     ├─ 否(派发前发现)──► 补齐(顺手修复)──► 收尾披露 ──► 派发
  │     └─ 是 ─────────────────────────────────────────────► 派发
  ├─ 派发经 E15 三通道之一(可叠加),对 E17 三模式同等成立
  ├─ E19b 执行
  │     ├─ 撞见需裁定的异常 ──► 停在本层 ──► E14 行首 ANOMALY: 回抛
  │     └─ 无异常 ────────────────────────► E14 明写「未发现异常」
  └─ E19a 消费回传
        ├─ 有 ANOMALY: ──► 判为异常停 ──► 组装 E6 ──► MUST NOT 原样重派
        ├─ 明写未发现异常 ──► 判为干净 ──► 正常消费
        └─ 缺 E14 ──► 判为**不完整** ──► MUST NOT 消费其结论(存疑从严)
```
