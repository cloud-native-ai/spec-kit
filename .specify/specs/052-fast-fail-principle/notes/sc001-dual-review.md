## 2. 检出的判据缺陷(S9,已由两位评审者独立发现)

**缺陷**: `## 分流判据` › `### 三条裁决顺序` 的**两振升级**规定"同一异常在一次运行内第二次出现 MUST 升级为快速失败",并把"同一"认定为 `(发现点, 被证伪的预期)` 二元组。但一次复发**通常出现在不同的发现点**——二元组因此不相等,计数不增,**升级规则在最常见形态下不可达**。

**双方原话**:
- A:「两振升级把「同一」按 `(发现点, 被证伪的预期)` 二元组认定,而本场景第二次出现在**不同**发现点,严格读来二元组不相等、计数不增」
- B:「按 `发现点` 的字面义,这是另一处异常、第二次计数不成立,升级规则在该形态下不可达。我按场景自身"同一异常第二次出现"的断言判为升级,这是在两种读法间的选择而非推导,故如实上报」

**同一性键的拥有者不在本文件**:该二元组由 `requirements.md` 的 Key Entities › 异常(Anomaly)定义,并明文规定"FR-014 的『同一异常第二次出现』与 FR-044 的『两次独立观察』**都按此键判定**"。故修复它是一次**上游规格改动**,不是一次就地纠正 ⇒ 按本纪律自己的判据属**快速失败**,已上送用户裁定(见本次运行的收尾报告)。

**为何这是"裁定"而非"纠正"**:至少三种读法都与已记录意图相容,无一种被工件选定——(甲)FR-014 改用 `被证伪的预期` 单键、FR-044 保留二元组(两条规则本就需要不同粒度:独立性要求发现点不同,复发性要求预期相同);(乙)保留单一键,接受 FR-014 只在同一发现点复发时生效;(丙)把 `发现点` 的定义放粗到"单元/动作"之上的层级。选择哪一种会改变 FR-014 与 FR-044 的可达范围,故 MUST 由用户裁定。

## 3. 两位评审者共同上报的第二处异常(本次取样的方法学限度)

A 与 B **各自独立**上报:真源文档开篇声明它拥有"双向生长规则、与相邻纪律的边界"等,但 `## 子代理派发注入`、`## 生长闭环`、`## 与相邻纪律的边界`、`## 冲突裁决顺序`、`## 范围限制` **五节当时均为空标题**(源与镜像同为 13452 字节,故不是镜像漂移)。

**这是本次取样的已知限度,如实记录**:T013 排在 Phase 3,而那五节由 T028 / T040 / T044–T046 在 Phase 6–8 才填。故本表度量的是**已写成的判据面**(分流判据 + 两份清单 + 上送件与披露),S1–S12 全部落在此面内,判定有效;但涉及跨节裁决顺序的问题(评审者自陈"本应记在空的 `## 冲突裁决顺序` 里")当时只能退回 `### 三条裁决顺序`。

⇒ **T054 的复跑义务**:Phase 8 把九节填实后,MUST 以同一份场景表复跑本取样,并把两次结果并列;若复跑后规则级一致率仍非 100%,SC-001 MUST NOT 记为达成。
