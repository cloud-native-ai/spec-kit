## Decisions (R-series)

- **R-01 — Owner amendment shape (FR-001…FR-011, FR-023…FR-027, FR-034).** § Termination is rewritten into the single owner of: the closed seven-value set and its three semantic classes; the per-value positive-evidence requirement (one row per value, including what explicitly does **not** count); the settlement-time liveness rule; the "start record or `unknown`" rule; the reaction obligations (report / retry / stop; fast-fail escalation for `silent-end`/`unknown`; no silent repair; retry = new attempt/new label); the additive `settlement_version` field and the legacy/no-compliance rule; the carrier evidence table (C1…C6) as pointers; and the extended closed violation set (four edge kinds unchanged + `settlement-unrecorded` / `settlement-out-of-set` / `settlement-unbacked`). All rewritten text is worded to add **zero** new blocking-pattern hits to `scan-confirmation-gates.py` (design avoidance; the existing gate-027 line may stay or go, but no second hit may appear).
- **R-02 — Judgment engine (FR-028, FR-029, FR-032).** Add `--action settle` to `role-edge-check.py`. It consumes the existing roots plus the new attempt/end records; its output has its own schema (`schema_version`, `action=settle`, `attempts[]`, `findings[]`, `violations[]`, `summary`) and does **not** touch `report`/`query` output. Exit codes reuse 0 / 1 / 2: 0 = every attempt judged (including correctly derived `silent-end`), 1 = settlement violations, 2 = unreadable evidence (the `unknown` findings, naming the unreadable pointers). Three settlement violation kinds are closed: `settlement-unrecorded`, `settlement-out-of-set`, `settlement-unbacked`. "Unknown treated as pass" is structurally impossible because unreadable input exits 2.
- **R-03 — C2 evidence (FR-015, FR-016).** `dispatch.sh` writes `<label>.attempt` before starting the CLI (attempt id = label, carrier `c2-subprocess`, parent identity from the caller, `started_at`, `pid` = wrapper shell `$$`, `pid_start_ticks` from `/proc/<pid>/stat` where available, `settlement_version: 1`), and writes `<label>.end` on normal exit **and** on TERM/INT/HUP traps (`exit`, `signal`, `ended_at`, `settlement_version`). SIGKILL cannot be trapped — that is the silent-end evidence path. `.status` keeps its exact format and the script keeps its `-h`/`--version` guard. A parent may add `<label>.settlement` (a claim with verdict + evidence pointers + version) after independent verification; the engine audits claims but derives a verdict even without one.
- **R-04 — C4 native (FR-018, FR-019).** `run-agent` writes the same attempt record (carrier `c4-native`) into the existing dispatch log directory before handing the task to the host; on return it verifies the five elements and settles; host error → `failed`; declared wait deadline passed with no return and no live signal → `silent-end`; missing any five-element item → `failed` (incomplete), not consumed. If the host exposes **no** background form, the mode is declared foreground-terminal — the tool return is the termination event and **no** settlement edge is created. `virtual` is explicitly excluded (no detachable edge) while the "unfinished virtual work MUST NOT be reported completed" duty is kept in the same paragraph.
- **R-05 — C3 report (FR-017).** The mapping table gains additive `end_state` and `evidence` columns (7 total) for **new** reports; the engine accepts the exact 5-column legacy header and the exact 7-column header, nothing else. `## Verification` gains a settlement-coverage declaration. A 7-column row with an empty `end_state`/`evidence` is `settlement-unrecorded`; a `completed` claim without an evidence pointer is `settlement-unbacked`. The "no success voice over a silent-end/unknown seat" sentence is behavior-class (review/mutation), not a prose parser.
- **R-06 — Version / legacy (FR-034, FR-035).** `settlement_version: 1` is an additive field on every new settlement-bearing record (attempt, end, claim, report). Records without it are judged from raw evidence, annotated `legacy` in the audit output, never counted as compliant, never rewritten, and never cause a failing exit code. Incompatible live-surface changes are forbidden by FR-033 (empty allowed-delta set); the incompatible-change ledger for this feature is **empty**, and the future-rule (migration/refusal + test) is stated in the owner and pinned by a test that asserts the ledger is empty.
- **R-07 — Enforcement and mutation (FR-029…FR-032, FR-041).** Six contract modules: definitions/pointers; engine (schema, violation kinds, exit codes, determinism, zero writes, red-first fixture matrix); carriers (C2 live/dead/SIGKILL/TERM, C3 5/7-column, C4/C5/C6 text pins); migration (versioned/legacy, no rewrite, refusal semantics, empty ledger); preservation (watcher token/exit/sentinel equality vs `fbab7a45c`, `--self-test` 100 %, confirmation-gate per-file no-new-hit, five-element/seven-field text unchanged); scope (no second mechanism, closed carrier inventory, each C-ID referenced by ≥1 test). The mutation drill is an implement-stage evidence artifact: remove/weaken each of the four detections (silent-end detection, liveness requirement, unknown-never-pass, evidence-pointer requirement) and record at least one red per drill. Behavior-class clauses (fresh-review liveness, parent-settles-before-report, reaction wording, success-voice) are listed in `contracts/enforcement-and-migration.contract.md` and are **not** claimed as contract-covered.
- **R-08 — Preserved surfaces (FR-033, FR-039, FR-040).** No edit to `watch-target.sh`, `stage-runner.sh`, `exec-quant.py`, the five-element uplink, the seven-field downlink, the confirmation discipline or the two-slot budget. Wording in new normative text avoids the gate scanner's patterns; the verification is a per-file hit-set comparison (EP-005 fallback), not an absolute `== 27` claim.
