# Contract: 语气、输入解析与文件行为（tone-input-file）

**Feature**: 062 | **FR 覆盖**: 见文末可追溯性表（该表为唯一权威映射，头部不复制枚举）
**性质**: 行为契约——技能承载的输入解析、语气处理与文件安全义务。结构面由契约测试钉扎；行为面由 E8 语料中的文件行为测试与语气矩阵承载。

## 语气与受众

- **C-24**: 未指定语气时使用缺省语气 `professional`——专业、自然、面向一般读者，不注入强烈个性或情绪；缺省语义在技能体有明确指令落点（FR-014, SC-004）。
- **C-25**: 技能接受封闭语气集合 [[STR-002]] 与自由文本受众描述；语气与受众只调整词汇、句式节奏、解释深度与例子选择，即只作用于表达层。技能体内联集合字面并注明其真源为规格 [[STR-002]]（宿主无法解析 STR 引用，须内联最小操作事实）（FR-015）。
- **C-26**: 语气与受众 MUST NOT 覆盖保真底线：所请求语气会要求改变事实、结论或造成误导性强调时，保留保真所需的表达并向调用者报告该限制（FR-016）。
- **C-27**: `--tone` 取值大小写不敏感，规范化为小写后 MUST 严格属于支持集合 [[STR-002]]；集合外取值（含空值与纯空白）时报告该值与支持集合；不静默替换为另一种语气，不声称已应用所请求的语气（FR-015, FR-017）。

## 输入解析与拒收

- **C-28**: 每次调用恰接受一个输入源，并采用确定性调用语法（FR-018）：选项仅 [[STR-004]]；选项解析只发生在内容之前；`--` 终止选项解析，其后全部为逐字内容；无 `--` 时，遇到第一个不可识别为选项的 token 即停止解析，其余全部为内容（内容以 `--` 开头时必须使用 `--` 分隔）。文件输入判定：`--file <path>` 优先；内容整体为单行且解析为存在、可读、扩展名受支持的普通文件时视为文件输入；`--inline` 强制按内联内容处理。`--file` 与非空内联内容同给 → 拒绝并说明「一次只接受一个输入源」；多文件或目录路径 → 同一拒收面（首版不支持批量处理）；既无文件也无非空内联内容（含无任何输入的调用）→ 拒绝；内联内容为空或仅含空白字符 → 拒绝，不产生任何输出文件（FR-018）。
- **C-29**: 文件输入支持格式 [[STR-003]]（扩展名匹配大小写不敏感）；路径必须解析为可读普通文件；路径不存在、指向目录、扩展名不受支持、内容为二进制/非 UTF-8 文本或文件为空时，以清晰消息拒绝并指出问题与支持格式；不输出乱码文本。UTF-8 BOM 被容忍且不计入正文；仅有 frontmatter、无正文的 Markdown 视为空输入拒绝（FR-019）。

## 文件安全默认

- **C-30**: 未显式给出输出路径时不创建、不修改任何文件；不写隐式同目录副本；不原地覆盖输入文件。同路径判定按真实路径：写入前将输出路径与输入路径分别解析真实路径（展开符号链接）；解析结果相同，或两者指向同一底层文件（含硬链接别名）→ 拒绝原地覆盖（首版显式排除）（FR-020, FR-021）。
- **C-31**: 显式输出路径行为（覆盖确认的显式形式是 `--force`，[[STR-004]]）：目标不存在且父目录可写 → 写入完整改写文本并在会话报告写入位置；目标已存在且未获 `--force` → 拒绝覆盖、目标文件逐字节不变、报告冲突。写入 MUST 采用「临时文件 + 原子重命名」；写入失败（父目录缺失、权限不足等）→ 报告失败、不声称成功、删除临时文件、不留部分输出、已有目标文件逐字节不变（FR-021, SC-005）。
- **C-32**: 输出格式跟随输入格式：Markdown 输入产出 Markdown，纯文本输入产出不含 Markdown 专有语法的纯文本；写文件时保持对应格式。`--output` 目标扩展名仅接受 `.md`/`.markdown`/`.txt`（大小写不敏感，[[STR-003]]）且 MUST 与输入格式族一致（Markdown → `.md`/`.markdown`；纯文本 → `.txt`）；扩展名不受支持或与输入格式族不一致 → 拒绝，不创建、不修改目标。纯文本核验用「Markdown 专有语法」封闭清单：行首标题 `#`、成对强调 `**`/`__`/`*`/`_`、行首列表 `- `/`1. `、代码围栏、行内反引号、链接、表格 `|` 行、行首引用 `>`；自然文本中合法出现的连字符与星号不在此限（FR-022）。
- **C-33**: Markdown 文件的 YAML 或 TOML frontmatter 逐字保留（FR-008 的 YAML/TOML 承诺在文件级维持，不收窄为 YAML），仅正文进入改写；frontmatter 中的键值不因正文改写而变化（边界场景的义务面；FR-008 的文件级实例）。
- **C-34**: 敏感与机密内容：不发起任何外部传输；改写只在执行该命令的 agent 上下文内完成——本条款是 FR-028 在调用者数据上的实例化（FR-028）。
