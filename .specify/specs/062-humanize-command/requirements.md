## Assumptions（对输入中开放点的缺省裁决，clarify 阶段可推翻）

- **Related Feature 已绑定**（clarify 2026-10-19 裁决）：新建 Feature 062「Humanize Command（人性化改写命令）」，注册行与详情文件同批落册；绑定依据见 `## Clarifications` 会话记录。
- **执行技能分类**：按 `.specify/memory/glossary.md` 的技能分类标注，`humanize` 是无 spec-kit 内部依赖的通用内容能力，缺省归为 `external`；plan 若发现分类判据冲突可修订。
- **默认语气**：未指定语气时使用 `professional`（专业、自然、面向一般读者），不注入强烈个性或情绪。
- **默认落盘行为**：默认只把改写结果返回会话，不创建、不修改任何文件；仅在调用者显式给出输出路径时才写文件。
- **不做原地覆盖**：首版不支持原地覆盖输入文件；更新文档时写入新路径，由调用者自行替换。该选择优先安全默认，后续可另立特性扩展。
- **支持格式**：首版只承诺 Markdown（`.md`、`.markdown`）与纯文本（`.txt`）；PDF、DOCX、HTML、二进制、图片与 OCR 不在范围内。
- **单输入源**：一次调用只接受一个输入源；`--file` 与非空内联内容同时出现视为歧义并拒绝。内联内容整体为单行且解析为受支持的普通文件时按文件输入处理，`--inline` 强制按内联内容处理——判定语法由 FR-018 承载（repair round 1 裁定）。
- **不做翻译**：输出语言跟随输入主语言；技术术语、专有名词与代码标识符按原样保留。
- **不承诺检测器结果**：降低 AI 痕迹只以词汇与句式多样性、去除公式化表达衡量，不承诺通过任何 AI 内容检测器，也不提供检测器评分。
- **长文档处理**：允许分段处理，但必须覆盖全文并重组为单一连贯结果；执行限制导致无法完成时，必须报告未处理部分而不是静默截断。
- **不新增运行时**：改写由执行该命令的 AI agent 完成，不调用新的外部服务、模型 API 或网络能力（宪法 IX）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 内联内容的人性化改写 (Priority: P1)

使用者把一段机器生成的内容、结论或报告直接交给 `/speckit.humanize`。命令在保持事实与结论不变的前提下，从语气自然化、上下文与逻辑补全、格式可读性、降低 AI 痕迹四个维度改写，并把完整结果返回会话。未指定语气时使用专业、自然的默认语气。

**Why this priority**: 这是命令的核心价值，也是最小可用切片；不依赖文件读写或语气选项即可独立交付。

**Independent Test**: 用固定双语夹具直接内联调用，按质量量规检查四个维度，并对受保护内容（事实、数字、引文、代码、链接）做逐项差异比对。

**Acceptance Scenarios**:

1. **Given** 一段含 "In conclusion" "It is important to note" 等套话、且段落密集的中文报告，**When** 以内联方式执行且未指定语气，**Then** 输出为中文，套话被删除或明显减少，长段落被拆分，核心结论在不改变含义的前提下前置，且所有事实、数字、名称与结论仍在输出中。
2. **Given** 一段英文机器输出，**When** 执行改写，**Then** 输出为英文，四个维度均被应用，且技术术语与专有名词保持原样。
3. **Given** 仅一句结论（例如包含一个百分比与一个原因），**When** 执行改写，**Then** 输出为一段自然的说明文字，结论、百分比与因果关系不变；不得新增原文没有的例子、统计数字、来源或事实。
4. **Given** 输入包含代码块、行内代码、引文、URL、版本号与文件路径，**When** 执行改写，**Then** 这些受保护内容逐字保留或语义完全等价，且不产生新的链接或引用。
5. **Given** 输入包含两条互相矛盾的陈述，**When** 执行改写，**Then** 两条陈述都被保留，冲突被明确报告给调用者，命令不得自行选择一方或编造一个统一结论。
6. **Given** 输入为空或仅含空白字符，**When** 执行改写，**Then** 命令拒绝执行并给出清晰原因，不产生任何输出文件。
7. **Given** 一段已经自然、无明显机器痕迹的文本，**When** 执行改写，**Then** 命令至多做轻微润色，并明确说明没有需要实质性修改的内容；不得为显示工作量而降低原文质量。

### User Story 2 - 外部文档的安全改写 (Priority: P1)

使用者给出一个外部文档路径（Markdown 或纯文本）。命令读取全文，按同样的四个维度改写，默认把完整结果返回会话且不修改源文件；当使用者显式给出输出路径时，把完整结果写到该路径；目标文件已存在时，未获显式覆盖确认不得覆盖。

**Why this priority**: 外部文档是源需求明确要求的输入形态；文件安全默认直接决定该命令能否被放心用于真实资料。

**Independent Test**: 在临时目录中准备 Markdown、纯文本、带 frontmatter、超长与异常文件夹具；执行后对源文件做逐字节比对，并检查写入、拒绝与错误路径。

**Acceptance Scenarios**:

1. **Given** 一个含标题、列表、代码块、表格与 YAML frontmatter 的 Markdown 文件，**When** 只给出该路径，**Then** 命令读取全文并把完整 Markdown 改写结果返回会话，源文件逐字节不变，frontmatter 逐字保留。
2. **Given** 一个纯文本文件，**When** 执行改写，**Then** 输出为纯文本，不使用 Markdown 专有语法，源文件逐字节不变。
3. **Given** 一个不存在的输出路径且父目录可写，**When** 显式给出该输出路径，**Then** 命令把完整改写文本写入该路径并报告写入位置，源文件仍逐字节不变。
4. **Given** 输出路径已存在且调用者未给出显式覆盖确认，**When** 执行改写，**Then** 命令拒绝覆盖，目标文件逐字节不变，并报告该冲突。
5. **Given** 路径不存在、指向目录、扩展名不受支持、内容为二进制/非文本或文件为空，**When** 执行改写，**Then** 命令以清晰消息拒绝并说明问题与支持的格式，不创建任何输出文件。
6. **Given** 同时给出内联内容与文件路径，**When** 执行改写，**Then** 命令以「一次只接受一个输入源」为由拒绝，不猜测使用哪一个。
7. **Given** 一个多章节长文档，**When** 执行改写，**Then** 每个章节都在输出中有对应内容，跨章节口径一致，且输出被重组为单一完整文档；若执行限制导致某部分未处理，命令明确报告未处理部分，不得把部分结果说成完整结果。

### User Story 3 - 语气与受众控制 (Priority: P2)

使用者指定语气与受众。命令支持 `professional`、`humorous`、`empathetic`、`colloquial` 四种语气，并接受自由文本的受众描述；语气与受众只调整表达层，不改变事实与结论。未指定时使用专业、自然的默认语气。

**Why this priority**: 语气与受众决定改写是否适合目标读者，但核心改写在没有该能力时仍可独立交付，因此排在 P2。

**Independent Test**: 对同一夹具分别以四种语气和缺省语气执行，由两位独立评审判断语气可区分且得体，并对受保护内容做逐项差异比对。

**Acceptance Scenarios**:

1. **Given** 一段中性报告文本，**When** 指定 `humorous` 语气，**Then** 输出可被识别为幽默风格，同时所有事实、数字与结论不变。
2. **Given** 同一段文本，**When** 指定 `empathetic` 语气并给出受众描述「非技术管理者」，**Then** 词汇、句式与解释深度适配该受众，且不新增原文没有的事实或例子。
3. **Given** 同一段文本，**When** 指定 `colloquial` 语气，**Then** 输出使用口语化表达，同时保留原文的专业术语与技术含义。
4. **Given** 未指定任何语气，**When** 执行改写，**Then** 输出使用 `professional` 默认语气，表现为专业、自然、面向一般读者。
5. **Given** 调用者给出不在支持集合内的语气值，**When** 执行改写，**Then** 命令报告该值不受支持并列出支持集合，不静默替换为另一种语气，也不声称已应用所请求的语气。
6. **Given** 调用者要求用某种语气弱化一个负面事实或结论，**When** 执行改写，**Then** 命令保持事实与结论不变，只调整表达方式，并报告语气请求与保真底线之间的限制。

### User Story 4 - 框架集成、分发与可发现性 (Priority: P2)

框架维护者与下游项目获得该命令：薄命令模板、单一执行技能、按工具生成副本、逐命令参考文档、特性注册表与详情、契约与行为测试，以及对既有能力的非回归保证。

**Why this priority**: 没有分发与登记，命令无法到达用户；但它以前三个故事的行为为前提，因此排在 P2。

**Independent Test**: 检查模板源、按工具副本、文档页、注册表与技能委派关系；运行生成检查与既有测试基线比对，不依赖真实用户文档。

**Acceptance Scenarios**:

1. **Given** 框架源码树，**When** 检查命令面，**Then** `templates/commands/humanize.md` 存在，所有受支持 AI 工具的生成副本都包含该命令，且副本由生成脚本产出而非手改。
2. **Given** 文档树，**When** 打开 `docs/reference/commands/humanize.md`，**Then** 该页说明输入形态、默认不写文件的行为、支持的语气、保真边界，以及不承诺检测器结果。
3. **Given** 特性注册表，**When** 检查 `062`，**Then** 存在注册行与详情文件，规格路径指向本规格。
4. **Given** 命令模板与技能目录，**When** 审计执行流，**Then** 命令是薄入口，执行逻辑由恰好一个技能承载，命令模板不复制技能工作流。
5. **Given** 改动前冻结的失败测试名单，**When** 运行契约、集成与既有测试，**Then** 排序后的失败节点名单零新增；生成面与镜像检查零新增漂移。
6. **Given** 源码与依赖清单，**When** 检查新增面，**Then** 没有新增外部服务、网络调用、模型 API、第三方依赖或后台常驻进程。

### Edge Cases

- `--file` 与非空内联内容同时给出 → 拒绝并说明「一次一个输入源」；既无文件也无非空内联内容（含无任何输入的调用）→ 拒绝。
- 内联内容为空或仅含空白字符 → 拒绝，不产生输出。
- 路径不存在、不可读或指向目录 → 拒绝并指出具体路径问题。
- 文件扩展名不受支持（如 `.pdf`、`.docx`、`.html`；扩展名匹配大小写不敏感）→ 拒绝并列出支持格式。
- 文件为二进制、非 UTF-8 或无法按文本解码 → 拒绝，不输出乱码文本。
- 输入文件为空 → 拒绝，不产生输出文件。
- Markdown 仅含 frontmatter、无正文 → 视为空输入拒绝；UTF-8 BOM 容忍，不计入正文。
- 输出路径与输入路径解析为同一文件（真实路径一致，含符号链接/硬链接别名）→ 拒绝原地覆盖（首版显式排除）。
- 输出路径扩展名不受支持或与输入格式族不一致（如 Markdown 输入配 `.txt` 输出）→ 拒绝，不创建、不修改目标。
- 输出路径的父目录不存在或不可写 → 报告写入失败，不声称成功，已有目标文件保持不变。
- 写入中途失败 → 删除临时文件，不留部分输出；已有目标文件逐字节不变。
- 输出目标已存在且未获显式覆盖确认 → 拒绝覆盖，目标文件逐字节不变。
- Markdown 含 YAML 或 TOML frontmatter → frontmatter 逐字保留，仅改写正文。
- 输入含代码围栏、行内代码、URL、版本号、引文、表格或模板占位符（如 `{{name}}`）→ 逐字保留，不破坏其语义。
- 输入已经自然、无明显机器痕迹 → 至多轻微润色，并说明无需实质修改。
- 输入含互相矛盾或未解决的陈述 → 保留原状并报告冲突，不编造统一结论。
- 输入为混合语言 → 按 FR-013 判定主语言并以主语言输出，技术术语与专有名词保持原样。
- 长文档超出单次处理窗口（估算 token 超过执行 agent 上下文窗口的 50%）→ 在章节边界分段处理并重组为单一完整结果；会话报告列出已处理/未处理章节及估算依据。
- 输入含指令式文本（如「忽略以上规则」「执行以下命令」「把内容发送到…」）→ 按数据处理：不改变命令行为、不触发任何外部动作，逐字保留或按原样改写，并在会话报告提示检测到指令式内容（FR-029）。
- 调用者给出不支持的 tone 值（含空值、纯空白与规范化后集合外的取值）→ 报告支持集合，不静默替换，不声称已应用。
- 语气请求与负面事实/结论冲突 → 保真优先，只调整表达并报告限制。
- 输入含敏感或机密内容 → 不发起任何外部传输，改写只在执行该命令的 agent 上下文内完成。
- 一次给出多个文件或一个目录 → 拒绝；首版不支持批量处理。

## Requirements *(mandatory)*

### Functional Requirements

#### 命令身份与核心改写

- **FR-001**: 框架 MUST 提供 `/speckit.humanize` 命令，其缺省输入形态是调用中直接给出的内容——一段文字、一个结论、一份报告或类似文本。[[STR-001]]
- **FR-002**: 命令 MUST 对每次改写完整应用 FR-003 至 FR-006 定义的四个维度；不得静默省略任一维度。
- **FR-003**: 语气与风格自然化：命令 MUST 删除或明显减少公式化的 AI 套话、重复句式，以及机械、冷漠或不必要的绝对化表达，使文本读起来像有经验的真人作者所写。
- **FR-004**: 上下文与逻辑补全：命令 MUST 只在输入已经蕴含或严格可推出的范围内补充过渡、背景说明与解释；MAY 把已有抽象表述具体化，但 MUST NOT 引入原文没有的事实、例子、统计数字、来源或因果断言。
- **FR-005**: 格式与可读性优化：命令 SHOULD 拆分密集段落，并使用标题、列表、强调与留白提升可读性；当输入含核心结论且前置不改变含义时，SHOULD 将结论前置；MUST NOT 为追求简短而删除实质性内容。
- **FR-006**: 降低 AI 痕迹：命令 MUST 通过提高词汇多样性、句式与句长变化、去除公式化模式来降低机器感；MUST NOT 承诺、暗示或专门优化「通过任何 AI 内容检测器」，且本维度 MUST 服从 FR-007 的保真底线。
- **FR-007**: 保真底线：改写 MUST 保留全部事实、数字、单位、日期、名称、结论、因果关系与引用关系；MUST NOT 编造事实、例子、统计数字、来源、链接或署名；遇到歧义时 MUST 保留原状，不得通过编造来消除歧义。
- **FR-008**: 受保护内容：引文、代码块与行内代码、命令、文件路径、URL、标识符、公式、模板占位符（`{{...}}`、`${...}` 形态）、YAML/TOML frontmatter 与表格数据 MUST 逐字保留或语义完全等价；其外围格式 MAY 调整，但其内容 MUST NOT 改变。
- **FR-009**: 最小改动：命令 MUST NOT 降低原本已自然文本的质量；当没有实质性改进依据时，MUST 至多做轻微润色，并明确说明没有需要实质修改的内容。
- **FR-010**: 矛盾与未决信息：当输入含互相矛盾或未解决的陈述时，命令 MUST 保留这些陈述并向调用者报告冲突；MUST NOT 用编造的统一结论掩盖冲突。
- **FR-011**: 完整性：命令 MUST 处理全部输入内容，MUST NOT 静默截断、用摘要替代正文或跳过内容。单次处理窗口 = 执行该命令的 agent 可用的上下文窗口；当输入的估算 token 超过该窗口的 50% 时，命令 MUST 分段处理（分段规则见 FR-023），不得以「执行限制」为由跳过。仅当分段处理后仍无法完成的残余部分，才构成「执行限制导致无法完成」，此时 MUST 报告未处理的部分及估算依据，且 MUST NOT 把部分结果呈现为完整结果。
- **FR-012**: 主要输出：命令 MUST 以完整改写文本作为主要输出，而不是差异列表、提纲或修改说明；MAY 附加简短的变更说明，但改写文本本身 MUST 可独立阅读。
- **FR-013**: 语言保持：输出 MUST 使用输入的主语言。主语言按以下可复现规则判定：先剔除受保护内容（代码块、行内代码、URL、标识符、frontmatter、表格数据）与纯数字/符号；对剩余自然语言按书写系统分别计数（中文字符数 vs 拉丁词数）；占比最高者为主语言；并列时取首个非空正文段落的主语言。输出 MUST 使用主语言（中文输入输出中文，英文输入输出英文，混合语言按上述判定结果处理）；技术术语、专有名词与代码标识符 MUST 保持原样；翻译不在本命令范围内。

#### 语气与受众

- **FR-014**: 未指定语气时，命令 MUST 使用 `professional` 语气——专业、自然、面向一般读者。
- **FR-015**: 命令 MUST 接受可选的语气值 `professional`、`humorous`、`empathetic`、`colloquial`（以 `--tone <value>` 传入），以及可选的自由文本受众描述（以 `--audience "<text>"` 传入，只作用于表达层）。`--tone` 取值大小写不敏感，规范化为小写后 MUST 严格属于支持集合；空值与纯空白同样不满足集合成员，按 FR-017 拒绝。语气与受众 MUST 只调整词汇、句式节奏、解释深度与例子选择。[[STR-002]] [[STR-004]]
- **FR-016**: 语气与受众 MUST NOT 覆盖 FR-007；若所请求的语气会要求改变事实、结论或造成误导性强调，命令 MUST 保留保真所需的表达，并向调用者报告该限制。
- **FR-017**: 当调用者给出不在支持集合内的语气值时，命令 MUST 报告该值与支持集合，MUST NOT 静默替换为另一种语气，也 MUST NOT 声称已应用所请求的语气。

#### 输入与文件行为

- **FR-018**: 每次调用 MUST 只接受一个输入源，并采用确定性调用语法（选项集见 [[STR-004]]）：选项解析只发生在内容之前；`--` 终止选项解析，其后全部为逐字内容；无 `--` 时，遇到第一个不可识别为选项的 token 即停止解析，其余全部为内容（内容以 `--` 开头时必须使用 `--` 分隔）。文件输入判定：`--file <path>` 优先；若内容整体是单行且解析为存在、可读、扩展名受支持的普通文件，则视为文件输入；`--inline` 强制按内联内容处理。`--file` 与非空内联内容同时出现时 MUST 拒绝（单输入源）；既无文件也无非空内联内容（含无任何输入的调用）MUST 拒绝；内联内容为空或仅含空白字符时 MUST 拒绝。
- **FR-019**: 文件输入 MUST 支持 Markdown（`.md`、`.markdown`）与纯文本（`.txt`）；扩展名匹配大小写不敏感。[[STR-003]] 路径 MUST 解析为可读的普通文件；路径不存在、指向目录、内容为二进制/非文本、扩展名不受支持或文件为空时，MUST 以清晰消息拒绝，并指出问题与支持的格式。UTF-8 BOM MUST 被容忍且不计入正文；仅有 frontmatter、无正文的 Markdown 视为空输入，MUST 拒绝。
- **FR-020**: 除非调用者显式给出输出路径，命令 MUST NOT 创建或修改任何文件；MUST NOT 写入隐式同目录副本，也 MUST NOT 原地覆盖输入文件。原地覆盖的判定口径按 FR-021 的真实路径规则执行。
- **FR-021**: 覆盖确认的显式形式是 `--force` 标志（[[STR-004]]）。调用者显式给出输出路径且目标不存在时，命令 MUST 把完整改写文本写入该路径并在会话中报告写入位置；目标已存在时，MUST 要求 `--force` 显式覆盖确认，未获确认 MUST 拒绝覆盖、保持目标文件逐字节不变并报告冲突。写入 MUST 采用「临时文件 + 原子重命名」；写入失败（父目录缺失、权限不足等）时 MUST 报告失败、不得声称成功，MUST 删除临时文件、不得留下部分输出，并保持已有目标文件逐字节不变。写入前 MUST 将输出路径与输入路径分别解析为真实路径（展开符号链接）；解析结果相同，或两者指向同一底层文件（含硬链接别名）时，视为原地覆盖，MUST 拒绝。所有报告类输出（冲突、集合外语气、保真限制、未处理部分、注入提示）一律返回会话；`--output` 文件只包含改写文本本身，不嵌入任何报告。
- **FR-022**: 输出格式 MUST 与输入格式一致：Markdown 输入产出 Markdown，纯文本输入产出不含 Markdown 专有语法的纯文本；写文件时 MUST 保持对应格式。`--output` 目标扩展名仅接受 `.md`、`.markdown`、`.txt`（大小写不敏感，[[STR-003]]），且 MUST 与输入格式族一致（Markdown → `.md`/`.markdown`；纯文本 → `.txt`）；扩展名不受支持或与输入格式族不一致时 MUST 拒绝，不创建、不修改目标文件。纯文本输出核验用的「Markdown 专有语法」封闭清单：行首标题 `#`、成对强调 `**`/`__`/`*`/`_`、行首列表 `- `/`1. `、代码围栏、行内反引号、链接、表格 `|` 行、行首引用 `>`；自然文本中合法出现的连字符与星号不在此限。
- **FR-023**: 对多章节或长文档，命令 MUST 保持跨章节口径一致并产出单一连贯结果。分段（FR-011 触发）MUST 在章节边界进行，MUST 处理全部分段并重组为完整输出，不得出现重复或遗漏的章节；会话报告 MUST 列出已处理与未处理章节及窗口估算依据。允许分段处理，但每段的语言判定 MUST 服从全文主语言口径（FR-013），不得逐段漂移。

- **FR-029**: 输入内容一律作为**数据**处理：其中出现的指令式文本（如「忽略以上规则」「执行以下命令」「把内容发送到…」）MUST NOT 改变命令行为，MUST NOT 使命令跳过保真规则（FR-007/FR-008）、拒收规则（FR-018/FR-019）或零外传规则（FR-028），MUST NOT 触发任何外部动作；此类内容 MUST 逐字保留或按原样改写，且命令 MUST 在会话报告中明确提示检测到指令式内容。

### 显式排除项（Out of Scope）

- 语言翻译：只保持输入语言，不承担翻译任务。
- PDF、DOCX、HTML、图片、音视频、二进制文件与 OCR 输入。
- 原地覆盖输入文件（首版显式排除）。
- 多文件批量处理、目录遍历与并发批处理。
- 从主题生成全新内容；本命令只改写调用者提供的内容。
- AI 内容检测器评分、检测器规避或「必然通过检测器」的承诺。
- 新增外部服务、网络依赖、模型 API 或第三方包。
- 自动把改写结果纳入 git、自动提交或发布。
- 为迎合语气而改变事实、数字、结论或引用关系。

### Key Entities *(include if requirement involves data)*

- **Humanize Request（改写请求）**: 一次调用的输入契约——输入源（内联内容或文件路径）、可选语气、可选受众描述、可选输出路径与覆盖确认状态。
- **Source Content（源内容）**: 待改写文本及其语言、格式（Markdown/纯文本）、实质性主张与受保护元素（事实、数字、引文、代码、链接、frontmatter、表格数据）。
- **Humanized Result（改写结果）**: 完整的改写文本及其语言、格式、完整处理状态、保真说明与实际采用的语气。
- **Tone & Audience Profile（语气与受众画像）**: 语气取值（封闭集合之一或默认值）与自由文本受众描述；只影响表达层，不影响事实层。
- **Fidelity Constraint（保真约束）**: 必须在改写中保持不变的要素集合，以及无法在不编造的前提下完成改写时的冲突报告出口。

- Q: 一行调用中，语气、受众、输出路径、覆盖确认与内联内容如何划界（调用语法）？ → A: 采用确定性选项语法，完整规则由 FR-018 承载、选项集见 [[STR-004]]：选项仅 `--tone`/`--audience`/`--file`/`--inline`/`--output`/`--force`；选项解析只发生在内容之前，`--` 终止选项解析（其后全部为逐字内容），无 `--` 时遇到第一个不可识别为选项的 token 即停止解析（内容以 `--` 开头必须用 `--` 分隔）；文件输入 `--file` 优先，内容整体为单行且解析为存在、可读、扩展名受支持的普通文件时视为文件输入，`--inline` 强制按内联处理；`--file` 与非空内联并存 → 拒绝，既无文件也无非空内联 → 拒绝。`--tone` 大小写不敏感、规范化为小写，集合外（含空值、纯空白）→ 拒绝并列出支持集合，不静默替换；`--output` 目标扩展名仅接受 `.md`/`.markdown`/`.txt` 且与输入格式族一致，目标已存在须 `--force`；`--audience` 为自由文本、只作用于表达层。引用形态对齐：FR-014 的单值缺省语气不再引用集合 [[STR-002]]，直接写值（集合引用只用于封闭集合）。
- Q: 混合语言的「主语言」如何可复现判定？ → A: FR-013 定义：先剔除受保护内容（代码块、行内代码、URL、标识符、frontmatter、表格数据）与纯数字/符号；剩余自然语言按书写系统分别计数（中文字符数 vs 拉丁词数）；占比最高者为主语言；并列时取首个非空正文段落的主语言；技术术语、专有名词与代码标识符保持原样。允许分段处理，但每段语言判定 MUST 服从全文主语言口径（FR-023），避免逐段漂移。
- Q: 受保护内容的「保留」按什么口径比对，集合成员有哪些？ → A: 按 SC-002 的归一化口径：数字/单位/日期去除千分位分隔符、统一空白、同一日历日等价，不做单位换算；百分比、版本号、标识符、URL、代码 token 逐字比较；新增句必须逐条标注「输入蕴含」依据。集合成员：FR-008 增补模板占位符（`{{...}}`、`${...}` 形态）；YAML/TOML frontmatter 的 FR 层承诺维持，下游不得收窄为 YAML；受保护 token 清单由 FR-008 集合、模板占位符、代码标识符与 URL/版本号构造。
- Q: 文件行为与各类「报告」的投递位置？ → A: 所有报告类输出（冲突、集合外语气、保真限制、未处理部分、注入提示）一律返回会话；`--output` 文件只包含改写文本本身，不嵌入任何报告（FR-021）。写入采用「临时文件 + 原子重命名」，失败时删除临时文件、不留部分输出、既有目标逐字节不变（FR-021）。输出扩展名仅 `.md`/`.markdown`/`.txt`（大小写不敏感）且与输入格式族一致，冲突 → 拒绝且不创建、不修改目标（FR-022）。同路径按真实路径判定：写入前对输出与输入路径解析真实路径（展开符号链接），解析结果相同或指向同一底层文件（含硬链接别名）→ 拒绝原地覆盖（FR-020/FR-021）。输入侧：扩展名大小写不敏感，UTF-8 BOM 容忍且不计入正文，仅有 frontmatter、无正文的 Markdown 视为空输入拒绝（FR-019）；纯文本输出的「无 Markdown 专有语法」按 FR-022 的封闭清单核验。
