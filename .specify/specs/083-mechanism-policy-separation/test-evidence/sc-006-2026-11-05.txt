## 2. The reading line and its denominator

    rows=30 matched=30 failed=0

- `rows` is the fixture's own row count, not a number typed into the module or into
  this file: the module iterates `matrix["rows"]` and prints its length. The frozen
  lower bound is `MIN_ROWS = 12` (SC-006 / GM-13); the fixture carries 30.
- `matched` counts rows with **zero** discrepancies. A row with any problem is not
  matched, so `matched=rows` is the only passing shape; a mismatch also fails naming
  the row.
- `failed` counts discrepancies, not rows-with-discrepancies, so it cannot be
  recomputed from `rows - matched` alone.

## 3. What each row is compared on

Per row: the decision class (`outcome`), the normalized identifier, and
`decision_class == outcome`; for failure rows also `failure_class` plus every required
report item (`raw`, `normalized`, …); for the dual-layer and case rows `layer` /
`case_pass`; for command-surface rows the `command_target` and the zero-entry into
Skill resolution. Structural rules are checked for every row whatever its expectation
says: segment membership in {surface, normalize, failure}, outcome membership in the
closed three, failure-segment rows closing as `failure`, command-surface rows naming a
target, failure reports carrying both halves of the pair.

## 5. Recomputing this reading

- Re-run the same fixture through the same implementation: the command in § 1.
- The negative case in the same run mutates **one** `normalize` row's expected
  normalization in memory and asserts `matched == rows - 1` with that row named — i.e.
  a single changed expectation cannot pass as "the rest passed". `3 passed` in § 1 is
  the population assertion (three disjoint segments, ≥ 12 rows, unique ids), the
  recomputation itself, and that negative case.

## 6. Disclosure

- The `live` rows read the current tree's layer distribution; that is why two names
  (`create-docs`, `humanize`) close as `dual-layer` failures rather than as `skill`.
  The criterion is the layer, never the path literal (§ Disambiguation rules (c)), so a
  future tree that removes one copy changes these rows' *outcome class* and must
  change the fixture in the same commit — the module would go red otherwise, which is
  the intended behaviour.
