## 3. The driving prompt (identical for all eight runs except the draft directory)

    qodercli -p --no-session-persistence --tools Read,Grep,Glob --permission-mode default \
      "你在当前目录扮演执行体，按 skills/external/create-skills/SKILL.md 这份技能定义处理
       草稿目录 drafts/<D>/ 。

       调用方已给定的策略项（不需要再询问）：
       - 新技能落点：skills/external/<新技能名>
       - 该技能每次运行的输入：由调用方在运行时给出
       - 该技能每次运行的输出落点：由调用方在运行时给出（本次示例：reports/invoices/2026-11.csv）

       执行范围：按该技能定义的流程走完 Step 0 到 Step 6（Validate）后立即停止；MUST NOT
       执行 Step 7/8，MUST NOT 写入、创建或修改任何文件或目录。

       停止后严格只输出四行：
       DECISION: … / MISPLACEMENT: yes 或 no / LOCATION: … / REASON: …"

The policy values are supplied because § 2's read-judge-stop would otherwise stop the
flow for a missing policy (that scenario belongs to SC-004, not here). They are given as
**values**, not as the rule: no run is told "a hard-coded path is a misplacement".

## 7. Disclosure — what this harness does and does not separate

The pre-change flow also produced `yes` on both misplaced samples. That is recorded
rather than smoothed away, and its cause is visible in § 3: the harness must supply the
policy **values** for the flow to proceed (otherwise § 2's read-judge-stop ends the run
for a missing policy, which is SC-004's subject), and a capable general model can compare
a draft against stated values without the skill asking it to. The measurement therefore
establishes SC-002's two numbers on the post-change flow and the baseline's
false-positive leg; it does **not** establish that the changed skill is what produces
detection in the presence of an explicit policy statement.

What the two states do differ on, read off § 4: the after-run M2 verdict names the layer
test itself ("换掉运行环境仍然成立 … 属于机制 … 符合机制误置的症状") and prescribes the
correction the owner's own symptom table prescribes (move it back into the skill asset),
while the before-run M2 verdict argues a different, ad-hoc norm (the gate should live in
a release script or CI). Both are refusals; only the first is an attribution to a layer.
No run in either state printed the owner's path, because the four-line output format
suppresses explanation — the harness cannot show whether a run read the owner document,
so it is not claimed.
