# Contract: Decomposition Gate `wp-gate.py` (WG-01…WG-18)

**Feature**: 070 — Task Decomposition & Team Coordination for Subagent-Driven SDD
**Script**: `skills/external/sdd-loop-driver/scripts/wp-gate.py` (new; Python ≥ 3.8, standard library only).
**Non-collision**: this script is not `decomposition-check.py`; the latter owns the Feature-level FR/task slicing gate and is unchanged.

- **WG-01 (Path and responsibility)**: The gate is a deterministic, stdlib-only script at the path above. It reads a plan or the spine, validates it, and emits a JSON verdict with findings. It never dispatches, never writes the spine, and never modifies the plan.
- **WG-02 (CLI grammar)**: `wp-gate.py --spine <path> --stage <stage> --check plan|preflight|retry [--plan-json <path>] [--manifest <path>] [--repo <path>] [--slot-cap-ceiling <int>] [--stage-attempt <n>] [--wp-id <id> --wp-attempt <n>] [--json-out <path>]`. `--stage-attempt` defaults to the highest attempt present in the spine (design refinement DR2). `--wp-id` and `--wp-attempt` are required by `--check retry`.
- **WG-03 (Input precedence)**: `--plan-json` supplies one plan body for fixture or test use and takes precedence over the spine. `--spine` is required otherwise. `--manifest` is required by `--check preflight` when any package has a non-empty `owned_paths`. `--slot-cap-ceiling` defaults to 4.
- **WG-04 (JSON output)**: The script prints `{"schema_version":1,"check":"plan|preflight|retry","stage":"...","verdict":"admit|single-package|reject","findings":[{"code","wp_id","detail"}],"plan_hash":"sha256:...","checked_at":"<ISO-8601>","evidence_ptr":"<path|null>"}`. `evidence_ptr` is the `--json-out` path when supplied, otherwise `null`.
- **WG-05 (Exit codes)**: `0` = `admit` or `single-package`; `1` = `reject`; `2` = input, parse, or I/O error. Exit 2 is treated by the driver as `decomposition-unavailable`, never as a plan rejection.
- **WG-06 (Schema checks)**: A required field that is absent, empty, or of the wrong type produces `schema-missing`. Schema failures are reported before graph checks and skip checks that would require an incomplete record.
- **WG-07 (Graph checks)**: Duplicate ids produce `dup-wp-id`; an unknown dependency produces `dangling-dep`; a dependency cycle produces `cycle`.
- **WG-08 (Output coverage)**: A required output owned by zero packages, a non-intermediate output not listed in `required_outputs`, or an intermediate output not consumed by a dependent produces `orphan-output`. Two packages claiming the same required output produce `duplicate-output`.
- **WG-09 (Boundedness)**: `bounded_by.count` that is not a positive integer produces `unbounded`; `unit=tasks` with count > 8 produces `unbounded`; `unit=clauses` with count > 40 produces `unbounded`.
- **WG-10 (Kind consistency)**: A `kind` that disagrees with `owned_paths`, or `parallel_safe=true` on a write package, produces `kind-mismatch`.
- **WG-11 (Pattern compatibility)**: `parallel` with a write package, with fewer than two packages, or with a package that is not `parallel_safe` produces `pattern-mismatch`. A graph with two or more independent read-only packages and no write package MUST select `parallel`; selecting `serial` there produces `pattern-mismatch`. `iteration` without a complete `repair_loop`, or any use of `continuous`, produces `pattern-mismatch`. `serial` is valid when a write package or a dependency edge exists, and may still run independent ready read-only packages concurrently under SD-04.
- **WG-12 (Plan hash)**: A recorded `plan_hash` that differs from the recomputed canonical effective-plan hash produces `plan-hash-mismatch`.
- **WG-13 (Benefit determination)**: For an `auto` stage, decomposition is beneficial only when the plan has at least two packages and at least one of: (a) two or more independent read-only packages with `slot_cap ≥ 2`; (b) the dependency-DAG critical path is strictly shorter than the sum of all package durations under the plan's declared budgets; or (c) `pattern=iteration` with a complete repair loop. Otherwise the gate returns `verdict=single-package` with an advisory `not-beneficial` finding and exit 0.
- **WG-14 (Preflight: manifest coverage)**: An `owned_path` not covered by a manifest `owned_paths` entry produces `manifest-uncovered`. An `owned_path` or `read_only_path` that hits a manifest `forbidden_paths` entry produces `manifest-forbidden`. Path normalization follows the 064 Ownership Manifest rule: repo-relative expansion, `realpath`, trailing-separator removal; coverage is equality or directory-prefix containment.
- **WG-15 (Preflight: concurrency territories)**: For any unordered pair of packages, overlapping write/read territories with at least one write package produce `path-overlap`; an unordered write package and a package reading its `owned_paths` produce `read-write-unordered`; two unordered write packages with overlapping `owned_paths` produce `write-write-unordered`. Read-only/read-only overlap is allowed as a shared read-only resource.
- **WG-16 (Preflight: slot cap and isolation)**: `slot_cap > --slot-cap-ceiling` or `< 1` produces `slot-cap-exceeded`. A package with an incomplete `resources` object, or a concurrently dispatchable package with no isolated port, temporary directory, cache directory, or non-empty `shared_readonly`, produces `isolation-missing`.
- **WG-17 (Retry checks)**: `--check retry` counts `dispatch` events for `(stage, stage_attempt, wp_id)`. A second attempt without a material delta, or an identical same-budget rerun, produces `retry-unchanged`; a third attempt or a package already at two attempts produces `retry-exhausted`; a malformed delta, a non-smaller scope change, a budget change without dispatch-level evidence, or a fake topology change produces `retry-delta-invalid`. Attempt 1 is admitted without a delta.
- **WG-18 (Determinism, repair, and fallback)**: The gate is deterministic for the same inputs and emits findings in a stable order (code, then `wp_id`). The driver may repair a `reject` once (split, serialize, or reduce to one package), records the repair as an amendment, and re-runs the gate. A second `reject` falls back to `single-package` with `decision=fallback` and `reason=gate-reject`. Exit 2 falls back with `reason=decomposition-unavailable`. The gate verdict is appended to the ledger's `plan` event before the first dispatch; the plan fence itself is never edited by the gate.
