# Contract: Scheduler and Dispatch (SD-01…SD-16)

**Feature**: 070 — Task Decomposition & Team Coordination for Subagent-Driven SDD
**Owner of the procedure**: `skills/external/sdd-loop-driver/references/decomposition-model.md`. The scheduler is driver prompt logic; no runtime scheduler, queue service, or daemon is introduced (Constitution IX).

- **SD-01 (Sole coordinator)**: The driver is the sole scheduler and coordinator. It selects the ready set, respects the slot cap, dispatches packages, collects results, and records the ledger. Package executors never dispatch other packages, never spawn a driver, and never edit the plan.
- **SD-02 (Readiness)**: A package is ready only when every `depends_on` package has a ledger `verdict=pass` with an evidence pointer in the current stage attempt. A failed, missing, or malformed verdict leaves dependents `blocked`; they are not silently dropped.
- **SD-03 (Write-alone rule)**: Every write package is dispatched alone. Before launching one, the scheduler waits for every running package to settle. Its effective concurrency is 1. No two write packages ever overlap in this feature.
- **SD-04 (Read-only concurrency and slot cap)**: Up to `slot_cap` read-only packages may run concurrently. The default is 2; `decomposition_slot_cap` may override it; the ceiling is `min(4, the line's remaining concurrency allowance)`. A `serial`-pattern stage may still run independent ready read-only packages concurrently; `parallel` names the all-read-only independent case.
- **SD-05 (Deterministic dispatch order)**: Ready packages are chosen by topological layer and then `wp_id` lexicographic (the declared tie-break). The ledger records the actual `dispatch_order` counter separately. Integration uses the same order and never the dispatch timing order.
- **SD-06 (No starvation)**: When a write package becomes ready, the scheduler stops launching new read-only packages, waits for running ones to settle, dispatches the write, and only then resumes the read-only queue. A ready write is never indefinitely deferred behind newly launched reads.
- **SD-07 (Local topology)**: The driver dispatches one native host subagent per package using the existing `run-agent` native dispatch path. It MUST NOT launch `qodercli` or another external CLI locally. If the host cannot issue parallel native calls, the driver records `parallel_requested=yes`, `effective=serial`, `reason=host-no-parallel-native` and dispatches serially; the effective concurrency is recorded.
- **SD-08 (Remote topology)**: The driver launches one detached `stage-runner.sh` process per package with a unique label `--stage <stage>-<wp_id>` and sentinel `WP-<WP_ID_UPPER>-DONE`. Each package has its own pid/status/log/heartbeat set. No shared runner or shared sentinel is used.
- **SD-09 (Result collection)**: A package is settled only when the runner's terminal status (`exit`, `sentinel`) and the last non-empty log line agree on the WP sentinel. The driver then reads the attempt-scoped result file. `INCOMPLETE`, a missing result file, a missing sentinel, or an `ANOMALY` line means the package did not complete and is not verified.
- **SD-10 (Verifier dispatch)**: After a package settles with a complete result, the driver dispatches the independent verifier (VI-01) and waits for the verdict before considering the package verified.
- **SD-11 (Failure isolation)**: A failed, stalled, or budget-exhausted package never cancels unrelated running packages. Its dependents remain blocked; unrelated ready packages continue and are recorded. A failure is surfaced, never silently repaired.
- **SD-12 (Unlock only on a verified verdict)**: A dependent is unlocked only by a ledger `verdict=pass` with an evidence pointer. A package that fails twice triggers `wp_failed`, fails the stage gate, and enters the unchanged U5 path.
- **SD-13 (No nested driver)**: Before dispatch, the driver checks that the outgoing package prompt does not name or load `sdd-loop-driver`, does not instruct the subagent to load any skill, and contains no loop logic. A prompt that fails the check is not dispatched; the block is recorded. The obligation is owned by `run-agent` dispatch governance and cited, not redefined.
- **SD-14 (Resource isolation)**: Each concurrently dispatched package declares its ports, temporary directory, cache directory, or a read-only shared resource. Packages never start a global service and never write a shared mutable cache. The preflight check is WG-16.
- **SD-15 (Reuse, no new mechanism)**: Package dispatch uses the existing `run-agent` / `stage-runner.sh` paths only. Feature 070 adds no dispatcher, queue, broker, daemon, external service, or model API.
- **SD-16 (Stage-attempt reset and re-entry)**: A U5 stage retry starts a new `stage_attempt` with a fresh plan fence, a fresh plan hash, and a fresh per-package attempt counter; earlier records remain in the spine. On re-entry the driver reads the spine, re-runs `watch-target.sh --once` for any detached runners, and never redispatches a completed package.
