# Contract: Opt-Out, Fallback, and Non-Regression (FN-01…FN-16)

**Feature**: 070 — Task Decomposition & Team Coordination for Subagent-Driven SDD
**Owner**: this file for the opt-out/fallback semantics; preserved behaviors are owned by their original features and cited, never redefined.

- **FN-01 (Declaration fields)**: The U0 entry declaration carries `decomposition: auto|off`, `decomposition_stages: <stage>=auto|on|off` (defaults recorded per stage), and `decomposition_slot_cap: <int>` (default 2). The stage-attempt declaration carries `decomposition_decision` and an optional `decomposition_override: auto|on|off`. These are spine fields, not new command arguments.
- **FN-02 (Precedence)**: Feature-level `decomposition: off` is a hard opt-out and no stage override can re-enable it in the same run. Otherwise the stage-attempt override wins over the per-stage map, which wins over the built-in defaults.
- **FN-03 (Built-in defaults)**: `plan`, `implement`, and `review` are `auto`; `analyze` and `clarify` are `off` and require an explicit `on`; `requirements`, `tasks`, and `checklist` are `off` for the first slice.
- **FN-04 (Auto and benefit)**: `auto` resolves to `decomposed` only when the gate returns `admit` with at least two packages and the WG-13 benefit test holds. Otherwise it resolves to `single-package` with `reason=not-beneficial`. A stage with one artifact and no separable work is single-package.
- **FN-05 (Single-package path)**: `off`, `disabled`, `single-package`, and `fallback` run the standard single-subagent stage path with the unchanged stage prompt, runner/native dispatch, sentinel, and U4. No new argument, field, or service is needed. For `implement`, this 070-layer boundary does not remove the pre-existing 067 part discipline; FR-025 keeps that discipline in force for large implement stages.
- **FN-06 (Fallback causes)**: A gate reject after the one allowed repair, an unavailable or corrupt decomposition layer (exit 2), or an unrepresentable stage contract resolves to `decision=fallback` with `reason` exactly one of `gate-reject`, `decomposition-unavailable`, or `not-beneficial`. A fallback always names its cause.
- **FN-07 (No silent partial run)**: A fallback never continues with a partial package set. The driver records the failure reason and the fallback in the spine and runs the single-package path, or stops if the single-package path is unavailable.
- **FN-08 (Every stage records a decision)**: Every stage writes one `decomposition_decision` in `decomposed`, `single-package`, `disabled`, or `fallback`, with the gate verdict and reason where applicable. A silent run is a gate failure.
- **FN-09 (Preserve 058)**: Stage sentinel literals, the stage chain, the state spine, U4 independent verification, watcher verdicts/exit codes, and stall handling are unchanged. Feature 070 adds pre-U4 steps only.
- **FN-10 (Preserve 063)**: The fast lane, the two-slot test budget, the plan minor-fix constraint, stream-json progress, and detach behavior are unchanged. A verifier's targeted tests use `targeted-set-v1`; no WP path runs a second full suite.
- **FN-11 (Preserve 064)**: The line registry, envelopes, worktree-per-write-line, Ownership Manifest, integration queue, CLI profiles, and lifecycle decoupling are reused read-only. Feature 070 creates no second registry, ownership model, worktree model, or integration queue.
- **FN-12 (Preserve 067)**: The part brief, bounded part size, dispatch log, test economics, and micro-gap coalescing are extended, never replaced. The WP brief for implement is the part brief plus WP fields; the ledger dispatch event carries the 067 fields.
- **FN-13 (Preserve 068)**: The exec-quant feedback channel is unchanged. Feature 070 adds no transmission surface and no new runtime record type.
- **FN-14 (Test matrix)**: Contract tests pin the WP schema, gate outcomes, pattern selection, preset-to-seat mapping, ownership/slot preflight, retry policy, opt-out precedence, and single-package fallback. Unit tests cover the two scripts. Fixture dry runs prove concurrent read-only dispatch, write serialization, ownership-violation rejection, deterministic integration, failure isolation, fallback, and no nested driver. A non-regression file proves the 058/063/064/067/068 behaviors above. Mutation drills prove the tests go red when a gate or simulator is broken.
- **FN-15 (Red-first evidence)**: New behavior is red before implementation. Each verification record carries the command, exit code, pass/fail counts, changed paths, and an evidence pointer. A green check that would not turn red when its subject breaks is not cited as proof.
- **FN-16 (Delivery surface and non-duplication)**: Delivery is confined to the driver skill source (`SKILL.md`, the new reference, the template, the two scripts), the driver documentation page, the canonical test suites, the mirror projection, and this feature's specification and evidence. No runtime service, daemon, external dependency, model API, second registry, second ownership model, second integration queue, second brief format, second ledger, or persisted team directory is added.
