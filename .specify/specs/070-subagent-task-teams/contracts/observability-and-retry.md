# Contract: Observability, Metrics, and Retry (OR-01…OR-16)

**Feature**: 070 — Task Decomposition & Team Coordination for Subagent-Driven SDD
**Script**: `skills/external/sdd-loop-driver/scripts/wp-report.py` (new; Python ≥ 3.8, standard library only).
**Metric owner**: this file; schema projection: `data-model.md` E11–E13.

- **OR-01 (Ledger fields)**: The ledger events and their required fields are fixed by `data-model.md` E4. The `plan`, `dispatch`, `settle`, `verdict`, `retry`, `integrate`, `stage-close`, and `wp_failed` events are the only event types used by the WP layer.
- **OR-02 (Attempt identity)**: Every dispatch is addressable as `attempt_id = <wp_id>-a<stage_attempt>-w<wp_attempt>`. Result and verdict evidence carry the same identity.
- **OR-03 (Stage-close fields)**: At stage close the spine carries `stage_attempt`, `stage_u4_at`, `wall_clock_seconds`, `critical_path_seconds`, `parallelism_efficiency`, `retries_package`, `retries_stage`, `stage_attempts`, `canonical_stages`, `stage_executions_per_canonical`, `manual_interventions`, `token_cost`, and `report_ptr`.
- **OR-04 (Stage wall-clock)**: Stage wall-clock = `stage_u4_at - first started_at` for the stage attempt. Missing either value → `not_evaluated`. Wall-clock is never inferred from commit timestamps or transcripts.
- **OR-05 (Critical path)**: The critical path is the duration-weighted longest path through the package dependency DAG, using each package's verified executor interval (`ended_at - started_at`). For a package with several attempts, the verified attempt supplies the duration; failed attempts remain in wall-clock and retry counts. The computation is `cp[node] = duration[node] + max(cp[dep])` over topological order; the result is the maximum `cp`. A missing duration on any candidate path → `not_evaluated`.
- **OR-06 (Parallelism efficiency)**: `parallelism_efficiency = sum(package durations) / (wall_clock_seconds × max_concurrent_package_count)`, with the product in the denominator. `max_concurrent_package_count` is the maximum overlap count from a sweep over all executor intervals. Missing durations, a non-positive wall-clock, or an undecidable sweep → `not_evaluated`. Verifier executions are excluded.
- **OR-07 (Stage executions per canonical stage)**: `stage_executions_per_canonical = stage_attempts / canonical_stages`, where `stage_attempts` is the count of plan events for the stage in the run and `canonical_stages = 8` (the canonical chain owned by `references/dispatch-recipes.md` Recipe 4). A run-level rate aggregates stage-close records; it is never guessed.
- **OR-08 (Retry counts)**: Package retries and stage retries are recorded separately. `retries_package` counts `retry` events in the stage attempt; `retries_stage = stage_attempt - 1`. A package retry does not consume the stage retry budget before escalation.
- **OR-09 (Manual interventions)**: Manual interventions = user continue/retry/status messages per run, normalized per session for the benchmark. The report accepts an optional `--manual-interventions` value; without it the metric is `not_evaluated`.
- **OR-10 (not_evaluated)**: Every metric whose source record is missing is the literal string `not_evaluated` in the spine and in both report files. It is never `0`, an estimate, a range midpoint, or another stage's value. A success criterion whose metric is `not_evaluated` is not claimed as met.
- **OR-11 (Report script and CLI)**: `wp-report.py --spine <path> --stage <stage> [--stage-attempt <n>] --out-dir <state-dir>/reports [--stage-u4-at <epoch>] [--manual-interventions <int>]` writes `<line>-<stage>-a<N>-coordination.md` and `.json`, prints the derived metrics JSON to stdout, and never writes the spine. The U4 time and intervention count are optional inputs because they are not derivable from the ledger before stage close (DR6).
- **OR-12 (Report content)**: Both report files carry the decomposition decision, pattern, slot cap, dispatch order, integration order, wall-clock, critical path, parallelism efficiency, max concurrency, retry counts, stage-execution rate, manual interventions, token cost when available, per-package verdicts with evidence pointers, and a parallel-overlap flag. They never contain raw transcripts, full logs, or fabricated prose metrics.
- **OR-13 (Benchmark method)**: A comparable feature is a full-chain run (checklist/analyze/review, no fast lane), 8–30 FR definitions and 10–40 task rows, on the same host class and topology as the baseline (or a re-measured baseline). At least three comparable samples per measured stage are required; fewer than three → `not_evaluated`, never a median claim. The conservative anchor is the upper bound of the 2026-10-24 dated range: plan 70 minutes, review 37 minutes; a 20% reduction means plan ≤ 56 minutes and review ≤ 29.6 minutes. A re-measured baseline replaces the anchor; sources are never mixed.
- **OR-14 (Retry counter source)**: The per-package retry counter is derived by counting ledger `dispatch` events for `(stage, stage_attempt, wp_id)`. There is no separate counter file. A U5 stage retry starts a new `stage_attempt` with a fresh WP counter while earlier records remain.
- **OR-15 (Retry delta schema and checks)**: The delta is `{changed[], reason, scope?, budget?, topology?}` with `changed` a non-empty subset of `scope|budget|topology`. Scope: the total `bounded_by.count` strictly decreases, or the package splits into children with distinct outputs. Budget: `max_turns` strictly increases and `evidence_ref` resolves to dispatch-level evidence (turn count, budget-exhaustion record, or output-token evidence). Topology: the dispatch form changes among `parallel-native`, `serial-native`, `detached-runner`, and `split-serial-children`. An identical same-budget rerun is rejected even if reworded.
- **OR-16 (Escalation)**: Attempt 3 is rejected as `retry-exhausted`. A package failing twice records `wp_failed` with its attempt history and verdict evidence, fails the stage gate, and enters the unchanged U5 stage-retry path (default two stage retries). The U5 retry re-dispatches the stage with a new plan and stage attempt; it never silently reuses the failed package set.
