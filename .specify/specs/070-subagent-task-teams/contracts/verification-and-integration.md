# Contract: Verification and Integration (VI-01…VI-14)

**Feature**: 070 — Task Decomposition & Team Coordination for Subagent-Driven SDD
**Owner of the procedure**: `skills/external/sdd-loop-driver/references/decomposition-model.md`; verdict schema: `data-model.md` E6–E7.

- **VI-01 (One independent verifier per package)**: Every package MUST be verified by exactly one fresh-context verifier execution that is not the package's executor. Native topology uses a native host subagent; detached topology uses one `stage-runner.sh` invocation labeled `<stage>-<wp_id>-verify` with sentinel `WP-<WP_ID_UPPER>-VERIFIED`. If the host cannot spawn a subagent, the driver performs the verification itself (`verification_execution=driver-u4`) and records the fallback; the driver is structurally independent of the executor.
- **VI-02 (Verifier scope)**: The verifier is read-only with respect to repository content. It may run the package's declared acceptance checks, including tests selected by the existing `targeted-set-v1` procedure, but MUST NOT run a full suite (the two-slot test budget is unchanged). Its only write is the verdict file and optional evidence under the state directory.
- **VI-03 (Verdict record)**: The verifier writes `<state-dir>/wp/<line>-<stage>-<wp_id>-a<N>w<M>.verdict.json` with `schema_version`, `wp_id`, `stage`, `stage_attempt`, `wp_attempt`, `verdict` (`pass|fail`), `checks[]` (id, kind, command, result, evidence_ref), `evidence_refs[]`, `execution_id`, and `verified_at`. The `checks[].id` values cover every acceptance criterion.
- **VI-04 (Missing verdict is fail)**: A missing, unreadable, malformed, or ambiguous verdict counts as `fail`. Success is never inferred from a package self-report, a missing file, or a package sentinel.
- **VI-05 (Verdict event)**: The driver appends a `verdict` ledger event `{wp_id, verdict, verifier_execution, evidence_ptr, at}` after reading the verdict. A package without that event is not verified.
- **VI-06 (Aggregation)**: After every dispatchable package settles, the driver aggregates the verified verdict set, checks output existence, output coverage, and contradictions, and never infers success from a self-report. Coverage is checked against `required_outputs` minus `integrator_outputs`: package outputs must cover the former exactly, while every `integrator_outputs` entry is expected from the integrator execution (VI-11), not from a package. Missing or contradictory outputs are surfaced with both evidence pointers.
- **VI-07 (Deterministic integration order)**: Verified outputs are integrated in topological layers, each layer sorted by `wp_id` lexicographic. The order is declared in the plan and recorded in the `integrate` event; it is not the dispatch order.
- **VI-08 (Conflict stops integration)**: An integration conflict or a missing output stops integration, fails the stage gate, and leaves no partial commit presented as a complete stage deliverable.
- **VI-09 (One closing commit)**: For stages without a part-commit discipline (`plan`, `review`, `analyze`, `clarify`), package executors do not commit; the integrator makes the single stage-closing commit after integration. The stage commit happens once, after integration.
- **VI-10 (Implement part commits preserved)**: For `implement`, the 067 part-commit discipline is preserved. Part commits stay as they are; the integrator's closing commit covers the remaining integrated deliverable and MUST NOT rewrite, squash, or bypass the part commits.
- **VI-11 (Integrator seat and sentinel)**: For `decision=decomposed`, one integrator execution per stage attempt fills the `stage-integrator` seat. It receives the verified outputs, the plan, and the stage authority artifacts; it aggregates in VI-07 order, detects missing or contradictory outputs, produces the plan's `integrator_outputs` (for `clarify`, the clarification write-back), makes the closing commit, and emits `<STAGE>-DONE` as its last non-empty line. `integrator_outputs` are owned by this single integrator seat, are excluded from package output coverage (WG-08), and remain subject to the unchanged stage U4 (VI-13). It never dispatches a package, never re-plans, and never loads the driver.
- **VI-12 (Package sentinels are never promoted)**: A package sentinel (`WP-…-DONE`) never satisfies the stage sentinel. Only the integrator's `<STAGE>-DONE` (or, for a non-decomposed stage, the standard stage executor's `<STAGE>-DONE`) satisfies it. The single-package path is the stage execution itself, so its sentinel is the stage sentinel, not a promoted package sentinel.
- **VI-13 (Stage U4 unchanged)**: After integration, the driver runs the unchanged stage-level U4: the stage sentinel is necessary, artifact verification is required, and discipline checks are required. Package verdicts are inputs and never substitutes. A failed package or a failed U4 fails the stage gate.
- **VI-14 (Closure and merge stay driver-owned)**: This feature does not push, force-merge, or auto-merge, and preserves the existing confirmation gates. Closure and merge remain driver-owned under 058 and 064.
