# Contract — Snapshot CLI and Inputs

**Owner**: `references/state-awareness.md` (rules) and `scripts/loop-state.py` (code). This contract is normative for slice A; clauses are numbered `CLI-NN`.

- **CLI-01**: The engine is `skills/external/sdd-loop-driver/scripts/loop-state.py`, a Python 3.8+ standard-library script with no third-party import.
- **CLI-02**: `--action snapshot` is the only implemented action. `recover` and `check-spine` are recognized as reserved actions and MUST return exit 2 with the shared envelope `{schema_version:1, action:<name>, applied:false, result:"refused", steps:[], reason:"action-not-available-in-slice"}`; they MUST NOT read or write any state, lock, carrier or worktree.
- **CLI-03**: A snapshot is read-only. It MUST NOT write the state spine, carriers, watchbeat, Registry, spec artifacts, git index/history, or the worktree. The sole write path is an explicit `--out <path>`.
- **CLI-04**: Standard output is exactly one JSON document on success; diagnostics go to standard error. No progress lines, banners or debug text are written to standard output.
- **CLI-05**: Exit codes are the frozen ladder: `0` = snapshot evaluated successfully (every `loop_state`, including `UNKNOWN`, is data and still exits 0); `1` = not used by the snapshot action (reserved for later `recover`/`check-spine` refusals); `2` = parameter error or a required input that cannot be read. The ladder MUST be visible in `--help` and asserted by `--self-test`.
- **CLI-06**: Path resolution is explicit override first, then the Registry entry, then `missing`/`unknown`: `--spine` → `--state-dir` → `--spec-dir` → `--repo` → `--probe`. The engine never guesses a path from the current working directory or a directory scan.
- **CLI-07**: `--line-id` is required unless `--probe` carries a line id. A missing line id is exit 2.
- **CLI-08**: The Registry entry path is `<registry-dir>/<line_id>.json`. The registry directory resolves `SPECIFY_LINE_REGISTRY_DIR` → `$XDG_STATE_HOME/spec-kit/lines` → `$HOME/.local/state/spec-kit/lines`, matching `line-registry.py`; a contract test compares both resolvers on env-set, XDG-set and default cases.
- **CLI-09**: Registry status is `found` (readable JSON object), `missing` (no file), `unreadable` (I/O error) or `invalid` (malformed JSON or non-object). The four values MUST remain distinct.
- **CLI-10**: `--probe <file>` accepts a snapshot-shaped JSON document with `schema_version=1`. It is the caller-collected evidence source for a remote host. The engine MUST validate `schema_version`; a different value is exit 2.
- **CLI-11**: When a probe is supplied, every absent probe field is recorded as `missing`/`unknown` with `evidence_source=probe`. The engine MUST NOT read a local same-named carrier to fill it.
- **CLI-12**: `--state-dir` resolves explicit → parent directory of an explicit `--spine` → parent directory of the Registry `spine_path`. If none resolves, the watchbeat is `missing` and the applicable reason is `state-dir-unknown`; the engine MUST NOT scan the filesystem.
- **CLI-13**: `--spec-dir` is never inferred. If absent, stage artifacts are not evaluated, `evidence.artifacts.status=missing` with `detail="spec-dir-unknown"`, and `completion` MUST NOT be `complete`. `--repo` is explicit or the Registry `worktree_path`/`repo_root`; there is no CWD fallback.
- **CLI-14**: `--salvage-evidence <ref>` is repeatable and read-only. Each non-empty reference is echoed into `salvage.evidence[]`; the argument never writes the state spine. A spine `spine_salvage: accepted` record with `spine_salvage_evidence` and `spine_salvage_at` is the alternative input.
- **CLI-15**: `--sentinel <literal>` and `--no-sentinel` are explicit overrides. `--no-sentinel` sets `effective.sentinel.value=null` with `source="cli"`; it does not mean "sentinel unknown".
- **CLI-16**: `--out <path>` is the only write path. The engine MUST refuse (exit 2) an output path that resolves inside the resolved state directory or inside the resolved repo worktree; it writes atomically (temporary file in the same directory + replace) and still prints the same JSON to standard output.
- **CLI-17**: The watcher is invoked as a bounded subprocess: `watch-target.sh --once` from the skill directory, with the resolved pid/status/log/heartbeat paths, sentinel, line/run envelope, registry directory when available, deadline and effective thresholds. The invocation is read-only and uses no shell interpolation.
- **CLI-18**: A watcher that is absent, exits with a non-verdict status (including 2 or a transport failure), or emits no `WATCH` line yields `watch_status=unavailable` and `watch_verdict=null`. It never yields a stage-failure verdict, `DEAD`, or a fabricated watcher verdict. The snapshot still exits 0.
- **CLI-19**: `--self-test` runs hermetic fixtures with no repository state, prints one `ok <case>` line per case and a final `SELF-TEST: <n> passed, <m> failed`, and exits 0 only when `m=0`. It MUST cover the self-test obligations listed in CMP-10.
- **CLI-20**: No invocation starts a daemon, background process, network listener or resident service. Watcher and git subprocesses have bounded timeouts; a timeout is treated as unavailable/unknown evidence, never as a verdict.
