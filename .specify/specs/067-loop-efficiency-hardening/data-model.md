# Data Model & Evidence Schemas — 067 test-suite slimming (Phase 1)

**Owner**: this file owns the field-level schemas for every record the slimming scope
creates or audits. Normative procedures live in `contracts/`; requirement semantics in
`requirements.md`. Entities marked *(requirements)* repeat only the requirement-level
entity name; their field ownership is HERE.

## E1 · FullRunMeasurement *(requirements Key Entities)*

One dated record per complete measured run; appended under `test-evidence/`
(one file per run, `full-run-<date>-<purpose>.md`, per the one-entry-one-file rule).
Fields (protocol §2 is the ruling source; this table is the field owner):

| Field | Type / allowed values | Rule |
|---|---|---|
| command | string, verbatim | MUST equal the fixed command of contract MP-02; presence of `-k`/`-m`/path args invalidates the record (MP-05) |
| host | uname -m, OS version, interpreter + pytest version | 达标 host = 2026-10-22 baseline dev host only (MP-07) |
| date | ISO date | run date |
| git_commit | short hash | tree state measured |
| cache_clear | commands + timestamp | MUST show the cold-clear step ran contiguously with the run (MP-03) |
| start_epoch / end_epoch | integer | wrapper-recorded (MP-04) |
| wall_seconds | integer = end − start | THE budget number; pytest self-report recorded separately as cross-check only |
| exit_code | integer | runner exit |
| layer_counts | per layer × {passed, failed, error, skipped} | contract / unit / integration; any `deselected` > 0 invalidates the record (MP-05) |
| pytest_summary | string | pytest's own summary line, cross-check |
| evidence_log | path | machine-local log pointer (`.log` gitignored; the record itself is committed) |
| baseline_pointer | path or `none` | for the达标 record: the pre-change baseline dated record it is compared against |

Validation: V-E1-1 every field present or the record is invalid evidence; V-E1-2 a
达标 claim MUST cite a record whose command equals MP-02's fixed command verbatim;
V-E1-3 wall_seconds is the epoch delta, never the pytest self-report.

## E2 · ConsolidationLedger row *(requirements Key Entities)*

Single append-only file `.specify/specs/067-loop-efficiency-hardening/test-evidence/test-consolidation-ledger.md`;
one row per disposed test (FR-015). Row fields:

| Field | Values | Rule |
|---|---|---|
| original_id | full node id (case-level) OR test file + node-id prefix (file-level) | FR-015 |
| disposition | deleted / case-merge / file-merge / retained | `retained` rows are optional bookkeeping; only missing ids are audited |
| retained_equivalent_id | node id of surviving coverage | case-merge → the parametrized suite id; file-merge → suite id + stated prefix mapping |
| equivalence_rationale | free text, MUST state the assertion set preserved | byte-identity rows cite the shared suite (contract LED-04) |
| date / commit | ISO date / short hash | attribution |

Validation: V-E2-1 append-only (no rewrite of earlier rows); V-E2-2 every id in
`comm -23 baseline-ids post-ids` MUST join a row (case rows by full id; file rows by
mechanical prefix expansion), else silent deletion → closure audit fails (LED-05);
V-E2-3 a `deleted` disposition with no retained_equivalent_id is invalid (never legal
for a test that still exists in baseline).

## E3 · BaselineFailureSet *(requirements clarification 2026-10-22)*

- **Authority**: the 83-name FAILED list of the 2026-10-22 full run —
  `test-evidence/baseline-failures-2026-10-22.txt` (committed dated record).
- **Provisional status retired**: the clarify-era `.pytest_cache` 109-name provisional
  record is superseded by the completed run; requirements wording already names the
  full-run list as authoritative.
- **Usage**: SC-008 green = no NEW name-level failures vs this set (name-level diff via
  the runner's `--names-out` output plus `comm -13`, per contract FB-04); membership of
  a pinned test in the BASELINE set is pre-existing debt, handled per contract FB-06.

## E4 · BaselineTestIdList *(SC-007 Source)*

- File: `test-evidence/baseline-test-ids.txt`; one node id per line, summary lines
  stripped; header records the generation command + date + resolved interpreter.
- Generation: `pytest --collect-only -q` via the runner-resolved interpreter; timing =
  implement start, BEFORE the first consolidation-affecting task, AFTER the baseline
  full run (requirements Measurement Sources).
- Post list: same method regenerated at closure (`post-test-ids.txt` is transient
  evidence, may live under test-evidence/ with its generation record).
- Validation: V-E4-1 both lists generated by the SAME collect method; V-E4-2 the
  baseline list count is cross-checked against the baseline run's collected count
  (4553) — a material mismatch blocks the audit until explained.

## E5 · FailureTriageRecord (per baseline failure name)

Home: `test-evidence/failure-triage-2026-10-22.md` (one row per name, created during
implement triage). Fields: original node id; class
(`mirror-sync` / `stale-pin` / `regression` / `pre-existing-debt`); disposition
(`synced` / `pin-updated+rationale` / `mechanism-fixed` / `debt-registered`); evidence
pointer (diff, owner fact, or debt record path); date / commit. Validation:
V-E5-1 every one of the 83 baseline names appears exactly once; V-E5-2 a
`debt-registered` row MUST point at a dated debt record explicitly marked
"not introduced by this scope" (SC-008 wording); V-E5-3 `mirror-sync` rows MUST name
the sync command and pair scope executed.

## E6 · HookNeutralization (design mechanism record, not a store)

The autouse fixture (tests-side conftest) that redirects `GIT_CONFIG_GLOBAL` /
`GIT_CONFIG_SYSTEM` to empty temp files for the test process. Not a data store; owned
by plan.md §W2 / contract RC-07. Any test broken by the override is repaired by scoping
the override, never by re-enabling hooks for the whole suite silently.
