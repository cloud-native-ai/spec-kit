# Contract — `/speckit.anchor` (seven modes)

**Owner of the concept**: `shared/definitions/anchor-definitions.md` (created by this feature).
**Owner of the mode mechanics**: `skills/internal/manage-anchor/SKILL.md` (created by this feature).
This contract fixes the **command surface** only; it restates neither the concept nor the skill's
mode table.

## C-2 — Mode set (exactly seven)

`argument-hint` lists, and the body exposes, exactly these modes and no eighth:
`create` · `view` · `modify` · `targets` · `migrate` · `migrate-archive` · `coordinate`.

A contract test parses `argument-hint` and the mode table; a template missing a mode, gaining an
eighth, or dropping the file turns red (FR-062).

## C-3 — Positioning text

The template MUST state that `/speckit.anchor` is the **sole authoring entry** for the anchor store
(`.specify/anchoring/**` definition files) and that the engine `goal-utils.py` is its sole definition
writer. Derived `summary/**` is out of scope of the authoring entry (see `research.md` R-06).

## C-4 — Scope values by pointer

The template MUST cite `.specify/shared/definitions/anchor-definitions.md` § Archive Layers for the
`--scope` value set and MUST NOT enumerate its members. A template that hard-codes the value set
turns red (FR-062). Pass-through: `--scope` and `--spec-dir <path>` go to the engine unchanged.

## C-5 — Delegation

The body MUST delegate mode semantics to the `manage-anchor` skill and MUST NOT restate its mode
table, its four-element `create` interview, or its read/write grouping (FR-012). The template keeps
entry, `$ARGUMENTS` processing, glossary pre-pass and the wrap-up lifecycle.

## C-6 — Mode behaviours (surface-level, one line each)

| Mode | Surface obligation |
|------|--------------------|
| `create` | writes `.specify/anchoring/<anchor-slug>/anchor.md` through the engine; outcome-shaped objective, ≥1 verifiable success criterion |
| `view` | read-only; with no slug, lists the anchor store |
| `modify` | edits objective / criteria through the engine, prior value recorded in `## History` |
| `targets` | delegates to the engine `targets` action: `--list` / `--check` / `--add` / `--set` on one Anchor |
| `migrate` | derives an Anchor from a team's inline goal through the engine `migrate` action |
| `migrate-archive` | the explicit spec-local legacy migration (094 semantics); archive-not-delete |
| `coordinate` | proposes a territory re-partition for the teams bound to one Anchor; no write before approval |

## C-7 — Refusals

- No mode rewrites a Goal definition (`.specify/goals/**`): anchor-side writes target the anchor
  store only. A caller asking for an action-level definition is redirected to `/speckit.goal`.
- `create` over an existing slug is refused by the engine (exit 2); the template never offers an
  overwrite flag.
- The only destructive write is a criteria emptying operation, and it requires explicit user
  approval in the run (same rule as the retired command).

## C-8 — Wrap-up probe

The template carries a compiled `## Wrap-up` block for unit-id `/speckit.anchor` covering run
determination, exec quant, feedback, threshold notice, token reflection, docs sync and close-out.
The probe object and its binding are registered in `shared/definitions/probe-definitions.md`; the
block is generated by `probe-utils.py --action compile-embeds` and never hand-edited (FR-014,
FR-055). The emitted fingerprint is taken from the generator's output, never pinned by hand.

## C-9 — Flow-class registration

`shared/definitions/flow-class-definitions.md` gains a `/speckit.anchor` row and a
`skill:manage-anchor` row; `flow-class-check.py --action check` is the guard, and the ledger's own
counts are re-measured in the same change (FR-054, FR-070).

## C-10 — Reference page and tutorials

`docs/reference/commands/anchor.md` exists and describes the seven modes; the tutorial command
tables and any command index list the command with its new meaning (FR-057). A missing page turns
the docs-coverage guard red.

## C-11 — Handoffs

Before: none — an Anchor may be created at any time. After: bind a team with `anchor_slug`
(`/speckit.team`); once two or more teams share an Anchor, `coordinate` keeps territories disjoint.
The handoff text names `/speckit.anchor` for every anchor-side follow-up (FR-016).

## C-12 — Non-goals

The command does not implement the cleanup action group (that is an engine action invoked by the
implement flow, not an eighth mode — requirement D-4), does not write team definitions except
through `migrate`'s declared inline-goal reference, and does not alias the retired `/speckit.goal`
modes.
