# Feature Detail: Subagent 并发归属、CLI 能力档案与生命周期解耦（Subagent Concurrency, CLI Profiles, and Lifecycle Decoupling）

**Feature ID**: 064
**Name**: Subagent 并发归属、CLI 能力档案与生命周期解耦
**Description**: 让 subagent 驱动的 SDD 在同一环境多线并行、同一仓库多写线与主/子会话生命周期解耦的条件下，保持线路归属不串台、工作区互不破坏、CLI 行为知识持续沉淀、子代理不随主会话死亡。
**Status**: Planned
**Created**: 2026-10-20
**Last Updated**: 2026-10-20

## Overview

已观测事故的根因不是单线执行能力不足，而是缺少环境级线路归属：一次广泛 `ps` 扫描把另一进程的 `IMPLEMENT-DONE` 当成了当前 SDD 线的进度；同时，同仓多写线共享工作树、Git index、运行时存储、镜像与构建缓存，即使归属正确也会互相破坏。本 Feature 在 Feature 058 的 U0–U6、每线状态脊、通用阶段哨兵与 watcher 判定之上增加四层增量：A 环境级 Line Registry 与 `line_id`/`run_id` 归属信封；B worktree-per-line、Ownership Manifest、运行时/镜像单点集成与确定性队列；C 每个 CLI 一份观测能力档案（064 为权威归属，收编 063 的 provisional 范围）；D 脱离式阶段执行与主会话重接线。它不替换 058/061/063 的任何 owner，也不引入常驻服务、外部依赖或模型 API。

## Key Changes

1. 环境级 Line Registry：每线 `<line_id>.json` + 同线锁 + 原子替换；`line_id`/`run_id` 归属信封以 JSON 旁路承载，不改哨兵最后一行。
2. 消息入口与 foreign 处理：活动线为 `active`/`waiting`；无标识消息只在 >1 条时恰好一次澄清；`foreign`/`stale-run`/`unattributed` 均不得改变当前状态；禁止进程扫描推断。
3. 同仓工作区隔离：worktree-per-line + Ownership Manifest + 归一化重叠检测；重叠按 FIFO/`line_id` tie-break 串行化，后到线 `waiting`；运行时记录由集成者一次归档，镜像/命令副本只在集成过程再生成。
4. 确定性集成队列：`ready_for_merge` 时间 FIFO、`line_id` tie-break，显式拓扑依赖优先；逐线 rebase→完整门→合并→更新 Registry/镜像→归档→移除 worktree，失败保留。
5. CLI 能力档案：`references/cli/<cli>.md` 八维度 known/unknown；qodercli 初始事实；U2 查阅、U4/U5 比对，只在新事实时经 `feedback-utils.py` 记录一条 `cli-profile:<cli>`；最小 Probe Object 入既有注册表；064 为权威归属，063 provisional 范围逐条裁决。
6. 生命周期解耦：detach 进程组 + 四件套 + Registry + reservation + driver lease；主会话 kill 后新会话凭 Registry/状态脊重接，running/done/dead 三分支零重复派发；orphan/stale/远端不可达显式分层处置。

## Implementation Notes

- 不引入常驻服务、daemon、外部依赖或模型 API；复用既有 shell/Python/stdlib、feedback/probe 引擎、sync-mirrors/regen-command-copies。
- 058 拥有 U0–U6、状态脊、哨兵与 watcher 判定/退出码；064 只加归属信封与生命周期层，不得改变其状态机、退出码或确认门。
- 061 的 `CAPABILITY_MATRIX` 是派发资格唯一 owner；CLI 档案只记录观测行为，冲突时以矩阵为准并产生反馈，不暗改矩阵。
- 063 的 CLI-profile 临时条款（`FR-044`…`FR-049`、`CP-01`…`CP-10`）由 analyze/plan 逐条保留/迁入/去重并记录；禁止双 owner 或静默复制；063 合并时自登记。
- Registry 默认路径可经 `SPECIFY_LINE_REGISTRY_DIR` 覆盖；远端 line 的 Registry 始终在驱动侧，ssh 不可达记为 `stalled`（`remote-unreachable`），不判 dead。
- worktree 清理只在合并成功或用户显式动作后执行，永远不用 `--force` 删除未提交/未合并工作；stale lock/reservation 先验证再破除。
