# Feature Detail: Agent+LLM 执行量化记录(Execution Quant Recording)

**Feature ID**: 059  
**Name**: Agent+LLM 执行量化记录(Execution Quant Recording)  
**Description**: 每个「agent 程序 + LLM」受测单元执行时,经既有 wrap-up probe 挂点自动落一条量化记录(agent 程序信息 / LLM 详细信息 / 质量指标与可选打分),由确定性引擎采集入项目 memory 层专属 durable 存储;本期 Recording Only  
**Status**: Draft  
**Created**: 2026-10-16  
**Last Updated**: 2026-10-16

## Overview

为 spec-kit 增加「agent 程序 + LLM」执行的量化数据记录能力:任一受测单元(与运行判定同语义的 command / skill / custom-unit)完成一次执行,即在 wrap-up 挂点经确定性程序落一条量化记录,含 agent 程序信息、LLM 详细信息、质量指标(时长 / token 消耗 / 错误次数)与可选打分。核心纪律:**测量而非印象**——不可采字段以显式未采标记落库,零空缺、零臆造;与运行判定并行携带、标注来源、不重复测量;存储独立于 feedback store,结构性排除于反馈打包与一切上送路径。本期只做记录(Recording Only):积累可机读的执行遥测数据集;量化分析、报表、聚合口径、打分模型均为后续特性。

## Key Changes

1. 新增 scripts 层确定性采集引擎 `exec-quant.py`(定名,clarify Q2 锁定):采集(挂 wrap-up 点,HandlerBinding engine-kind 非阻塞 handler)、列出(单元/类型/时间过滤 + 机器可读)、打分补录三个动作面。
2. 新增执行量化记录与专属 durable 存储:身份三元组 `(unit_id, unit_type, run_id)`,append-only、机器可读,位于项目 memory 层、feedback store 之外,不入打包路径。
3. 三字段组采集契约:agent 程序(宿主可解析时全采,按宿主如实降级)、LLM 详细(候选值/生效值区分,不可得落显式未采标记 `not_evaluated`)、质量(时长/token 自同 run 运行判定记录携带并标注来源,错误次数自声明来源枚举,打分双通道按来源区分)。
4. 新增 probe 注册行(伞形 probe 注册表 scripts 切片 Class + Objects),派生视图重建而非手抄。
5. 非回归与安全边界:既有 feedback / probe / 运行判定行为不变;量化存储结构性排除于打包与上送;凭据型环境值白名单排除 + 记录体尺寸封顶。

## Implementation Notes

- 简报四开放点已于 requirements 阶段以 A1–A4 裁决闭合:单元粒度 = 运行判定同语义三元组,不细化到子步骤;存放 = 独立 durable 存储不入 feedback store;触发 = 既有 wrap-up probe 挂点(零新增每命令模板面、零新增确认门);打分 = 用户手动 + 运行判定推导并存、按来源区分。
- A6 组合裁决:与运行判定并行携带、标注来源,不重复测量;运行判定记录的 schema 与改进流程契约不变,其记录仍是时长/token 的唯一权威。
- 采集可行性锚点(2026-10-16 同机实测,dated record 仅作可行性输入):agent 程序信息可全采;LLM 详细分级可采——env 端点变量均为候选而非生效,生效端点仅记可判定证据,未设置的 reasoning effort 不可测得,落显式未采标记。
- 采集非阻塞:采集失败不使单元运行失败或劣化,失败在运行输出可见(同 feedback 非阻塞语义)。
