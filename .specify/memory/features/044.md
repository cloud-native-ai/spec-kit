# Feature Detail: Agent Metadata Portability

**Feature ID**: 044  
**Name**: Agent Metadata Portability  
**Description**: Separate tool-agnostic metadata from the agent's own body in preset agent definitions, express the metadata in neutral vocabulary (removing the Qoder dialect embedded today), and render it at `specify init --ai <tool>` time into each supported tool's real agent format (real files, replacing the per-file symlink model); also canonically defines the difference between `agents/`, `skills/create-agent/templates/` and `skills/create-team/templates/agents/`.  
**Status**: Implemented  
**Created**: 2026-08-13  
**Last Updated**: 2026-08-13 (planned via /speckit.plan: plan.md + data-model.md + 4 contracts + quickstart.md + feature-ref.md; Constitution v1.9.1 check 12 Pass / 1 Partial (IX, justified). Earlier the same day: registered via /speckit.clarify; second clarify round revised scope to the directory-level Worker/Meta taxonomy — `agents/` becomes exclusively framework-maintenance Meta Agents, the 7 role definitions relocate to `skills/create-agent/templates/` as Worker capability templates)

## Overview

Today the 7 preset role agents (`agents/*.agent.md`) carry one flat frontmatter in which framework assembly keys, Qoder-specific runtime fields (`model`/`tools`/`maxTurns`/`color`, documented as "Qoder-compatible fields" in `docs/reference/agents/templates-and-agents.md`), and no separation from the body coexist. Distribution is a per-file relative symlink (`ensure_per_file_agent_links()` in `src/specify_cli/__init__.py`) that hands the same Qoder-flavored file to every tool — `.claude` is never created (claude maps to `.github`), and codex receives no agents at all.

This Feature turns that around in one move:

1. **Separate**: agent metadata becomes a programmatically delimited block, distinct from the body that describes who the agent is and how it works.
2. **Neutralize**: the metadata uses tool-agnostic vocabulary; the Qoder dialect (including the camelCase `maxTurns` key) leaves the canonical layer.
3. **Render at init**: `specify init <project> --ai <tool>` translates the neutral metadata into the target tool's real supported format and writes real files (no symlinks) into the tool's agent directory. Mapping rows are sourced from each tool's official docs, with unverified rows explicitly flagged until confirmed.
4. **Define the three directories**: `agents/` (concrete runnable presets → Agent Template layer), `skills/create-agent/templates/` (single-agent authoring scaffolds with placeholders), `skills/create-team/templates/agents/` (team-domain authoring + orchestration contracts) — with the "templates" triple-meaning resolved.

Externally verified format facts feeding the mapping (as of 2026-08-13): Qoder `.qoder/agents/*.md` (docs.qoder.com/cli/subagent), opencode `.opencode/agents/` plural with `description` required and filename-as-name (opencode.ai/docs/agents), Copilot `.github/agents/*.agent.md` with VS Code also reading `.claude/agents/` (code.visualstudio.com custom-agents), Codex agents exist but as TOML under `$CODEX_HOME/agents/` (openai/codex source), Claude Code `.claude/agents/` (canonical URL code.claude.com/docs/en/sub-agents; field list second-party only in this run), Hermes undocumented.

Relationship to Feature 033 (Agent Project Context Parameterization): complementary layers, both touching the init/refresh path — 033 parameterizes the body's `## Project Context` section; 044 owns the metadata layer and the per-tool render/distribution pipeline that 033's refresh would ride on.

## Implementation Notes

- The symlink removal is a breaking structural change: every behavior `ensure_per_file_agent_links()` carries (instance wins on name collision, real-file-as-override, stale-link pruning, legacy whole-dir migration) must be re-homed in the render path or explicitly retired.
- No per-tool agent format is documented inside this repo today; the mapping's provenance column is the enforcement mechanism (FR-010, SC-003).
- Codex output is TOML, not Markdown — the renderer is format-aware, not a Markdown-only writer.
- After rendering, "user override vs rendered output" can no longer be distinguished by file type; the override-detection mechanism is an open clarify question (FR-021).
- Rename/retire discipline from instructions applies: retiring the symlink model must register obsolete assets and update `tests/contract/test_agents_symlink.py` and friends.
