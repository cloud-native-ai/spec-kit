# Feature Detail: Confirmation Gate Governance

**Feature ID**: 046  
**Name**: Confirmation Gate Governance  
**Description**: 框架级确认门控治理:确立两级分类判据(破坏性/不可撤销动作保留前置确认、可逆动作自动执行 + 事后执行报告),对全框架既有约 55–60 处阻塞确认门控逐一归类治理,并约束未来新增命令/技能不回流非破坏性门控;team 创建/运行/收尾全流程零确认为首要落地场景。  
**Status**: Implemented  
**Created**: 2026-08-18  
**Last Updated**: 2026-08-18

## Overview

Registered as Draft during `/speckit.clarify` for requirement 044 (2026-08-18), which resolved the binding decision: **new Feature** rather than binding 027 Team Management — team 流程是痛点核心但本需求的治理面(全框架门控分类判据、收尾确认非阻塞化、执行报告契约)横跨 team/goal/tools/skills/agents 多个命令域与共享工作流约定,属框架级横向交互策略,无既有 Feature 覆盖此职责。

痛点:全框架命令/技能中约 55–60 处"阻塞等待用户确认"门控,多数保护的动作本身可逆;team 一次完整使用被打断三次(创建确认、运行确认、收尾确认)。原则:**先按设定执行、执行完允许修改;只有不可撤销、破坏性动作才保留前置确认**。

## Key Changes

1. 确立两级确认分类判据(破坏性/不可撤销 vs 可逆),含保守破坏性动作清单与"存疑从严"规则,沉淀为共享约定约束后续新增/修订流程。
2. team 流程三处门控移除:创建直接落盘、运行直接启动(持续循环类保留既有分级门控)、收尾自动完成(反馈提交提示改为非阻塞一次性提示)。
3. 全框架既有门控逐一归类治理:可逆类移除或转自动执行,破坏性类保留;目标残留门控较基线下降 ≥75%。
4. 执行报告契约:自动执行动作完成后呈现"执行内容、产出工件、修改途径"三要素;琐碎动作并入所属流程收尾报告。
5. 保护清单不动:访谈式交互、宪章不可撤销确认、implement 安全 CONFIRM 判定、git 工作流远程操作门控。

## Implementation Notes

- 治理对象是框架源侧工件(templates/commands/、skills/、shared/),经发布/安装自然传播到客户项目;不做客户侧直接修改。
- 破坏性动作清单至少涵盖:删除文件或数据、移动/归档既有工件、远程推送、覆盖用户既有内容。
- 分类判据的概念基础是框架既有分级确认模型(reconcile-pattern 的"安全自动、破坏性停等"),本 Feature 将其推广为全框架统一约定。
- 事后修改复用既有修订类命令(如 improve-team),不新建通用撤销/回滚基础设施。
