# 091 — Automatic git Close-out（自动收口）

## Overview

工作流模型当前能回答「分支怎么走」，但不能回答「一次运行结束时到底剩下什么」。`master` 模式因此把
「提交」当作终点，收口靠人手——分支留在本地、记录提交在侧分支、远端不更新。本特性把**收口**变成工作流模型
声明的一部分：模型新增 `closeout` 与 `closeout_remotes` 两条带值域约束的声明，收口本身是一条**有序列的局部
生命周期段**，而不是一条新命令或一个新引擎。

## Key Changes

- `shared/workflow/artifact-commit-step.md`：新增收口步骤——分支 → 记录提交 → 合入干道 → 清理 → 推送，
  首次失败即停，不改写既有记录，并重述推送边界（目标只取自声明）。
- `skills/external/git-utils/`：`SKILL.md` 的 scope A 增加具名 `closeout` 操作与三输入定位；命令面落到**新的
  同辈参考文件**（`research.md` R4 的实测理由），三模型参考只加一行指针；块模板资产新增两条声明行（占位形态）。
- `shared/definitions/probe-definitions.md`：新增一个 wrap-up handler 行表达收口步骤，嵌入面由引擎
  `compile-embeds` 生成，不手写。
- `.specify/workflow/git.md`（本仓运行态实例）：托管块内新增两条声明行，值域与角色按声明校验。
- 守卫：新增一个契约测试模块（两条声明与值域、四种模型序列、指针义务、无第二张分支表的负向断言、
  SC-004/SC-008 封闭清单声明）与一个 fixture 目录（每个模型一套 fixture 仓库 + 本地裸远端）。

## Future Evolution Suggestions

- 收口凭据可被 `/speckit.review` 用作「这轮到底推了什么」的证据源，届时只需读指针，不需重跑。
- `closeout_remotes` 目前是值域列表；若出现「只推某一分支」的需求，应扩展声明取值而不是在命令里加条件分支。
