# Feature Detail: Non-Disposable（不可一次性处置）

**Feature ID**: 092
**Name**: Non-Disposable（不可一次性处置）
**Description**: 把「过期 / 无用 / 延期」从一种沉默的默认状态变成一种必须被处置的状态，并把 `/speckit.history` 从「把会话蒸馏成主题文档」升级为「回顾 → 设计（方案）→ 用户确认 → 执行」四段。交付物是一个 stdlib 只读确定性检出引擎、一份唯一 owner 文档（八类检出闭集 / 四值处置集 / 豁免四字段 / 处置桥 / 取代与重编号协议 / 报告 schema）、一份声明式回顾面事实，以及按档 I（首轮修复）/ 档 II（检出 + 移交标记）分档的 A–H 语料处置。
**Status**: Planned
**Created**: 2026-11-09
**Last Updated**: 2026-11-09（tasks 阶段：见 § Latest Review）

## Overview

一条记录一旦写出，就倾向永远留在原地：它引用的文件被改名、它声明的计数被下一条特性改动、它的状态字段停在
`Planned` 而闭合裁决早已 `accept`。这些都不是错误行，而是**没有被处置的状态**——没有人被要求为它们做决定，
于是"什么都不做"成了唯一的默认处置，且不留痕迹。

本特性把这种沉默变成可检出的状态。三个失效面各自要有机制承接：

1. **检不出**——"过期/无用/延期"没有可观察定义，也没有程序可读的判据面，所以只能靠人工偶然发现；
2. **无处置词汇**——检出之后没有一套封闭的处置集，"先留着"不是一个值，却事实上是唯一结局；
3. **执行无形态**——`/speckit.history` 把会话蒸馏成文档，但它没有"先回顾、再设计、经用户确认、最后执行"的四段形态，因此任何"顺手修一下"的改动都不需要确认为方案条目。

本特性的交付物是**机制本身**，并把本仓既有记录作为第一批被检查对象：只写规则文字而不对现存语料分档处置，规则从
第一天起就是假的。
