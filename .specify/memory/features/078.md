# Feature Detail: 双语表述（Bilingual Expression）

**Feature ID**: 078
**Name**: 双语表述（Bilingual Expression）
**Description**: 把「核心概念 / 关键流程在定义处使用中英双语」从既有自发写作习惯固化为可执行的项目级约定：唯一 owner 文档承载方向规则（中文文档 `中文(English)`、英文文档 `English(中文)`）、唯一形态（半角括号、紧贴）、覆盖定义面封闭集、豁免面封闭集、跨文档一致性（以词汇表 Canonical 为准）与迁移边界（不追溯重写）；instructions 模板与运行时只放 ambient 摘要 + 指针；确定性检查器只做机械形态判定（定义行双语形态 / 括号语言与主语言相反 / 覆盖面齐全），不判语义；全部规则落在框架源（`shared/guidelines/` + `templates/`），经镜像与 `specify init` 分发到下游项目。不新增命令、运行时或服务。
**Status**: Implemented
**Created**: 2026-10-30
**Last Updated**: 2026-10-30

## Overview

框架已有大量双语并置实践（requirements 现状锚点实测：2333 个 `.md` 中半角 `中文(English)` 行长匹配 1609、全角 `English（中文）` 1383，32 个文件内部混用两种方向/宽度；词汇表 161 条中 132 条 Canonical 已双语化），但 grep `bilingual|双语` 于 `shared/`、`templates/`、`src/`、`scripts/` 零命中——概念存在而规则缺席：何时必须双语、用哪种括号、哪些面豁免、跨文档如何一致，全凭作者自觉。本特性把该实践固化为约定 + ambient 指针 + 机械守卫 + 分发路径四件套，使「锚定语义」（用户原话：不同 context 与大语言模型对同一名词/动词的理解会漂移，双语并置让两种语言互为约束）有唯一可引用的裁决来源。

约束对象是**定义处**（owner 文档定义行、词汇表条目、概念/流程首次定义、章节标题中的概念名），不是每一次提及——全文双语化会制造噪声并稀释定义处的锚定作用（规格显式排除项）。

关键裁决（详见规格 § Assumptions）：

- **Flow Class = `expression`**（reader-oracle）：主交付物是写作约定 owner 文档，缺陷最先在读者面暴露；形态检查器属结构检查，按 069 判据「结构检查通过不构成充分条件」不改判 execution（A2，含反题与重开条件）。
- **Flow Type = `technique-document`**（A3）。
- **唯一形态 = 半角括号、紧贴**（`中文(English)` / `English(中文)`）：用户原文逐字形态优先于仓内 1383 处全角存量（A4）；存量不追溯（FR-006）。
- **绑定新建 Feature 078**：reuse-first 复核 014 / 018 / Glossary / instructions 机制 / 069 后均无归属（规格 § Related Feature 复核表）。
