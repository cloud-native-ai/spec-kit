# Feature Detail: Goal Registry

**Feature ID**: 041  
**Name**: Goal Registry  
**Description**: Promote `goal` from a per-team field into a project-level first-class concept: an authored definition archive under `.specify/goal/`, referenced by teams via `goal_slug` instead of copied, consolidating requirement 036's goal-indexed summary delivery directory under the same single goal index.

## Overview

Today **goal is not an object, it is a field**. It exists only as a team attribute, and the same goal is written in several places at once: every team's `team.md` carries the same objective twice (frontmatter `goal:` and the `## Goal` body — measured: all 4 existing teams do this, so 4 goals are stored as 8 copies), while 12+ files in the team domain (presets, agent templates, `create-team/references/goal.md`, `references/optimization-goals.md`, `improve-team/references/goal-editing.md`) each discuss how to write and change a goal.

Requirement 036 introduced `goal_slug` as the join key for "the same goal" and aggregates team summaries by it — but **the goal being joined has no definition file**. When several teams share a goal, whose wording is authoritative can only be decided by a human; goal drift has no authoritative version to compare against; and no consumer outside the team domain can point at a stable project-level object.

This Feature archives the goal **definition** (narrative + verifiable success criteria + lifecycle state) as an authored source of truth, and makes the derived summary its output counterpart inside the same directory.

## Key Changes (planned)

1. **Definition archive** at `.specify/goal/<goal-slug>/goal.md`: composed of exactly three parts — objective narrative, zero-or-more verifiable success criteria, and lifecycle state (`active` / `achieved` / `abandoned`). Identity is carried by the directory name; timestamps are change-history metadata, not a fourth part. Authored, never rewritten by a derived flow. The goal's object is unrestricted — it may target the framework itself, codebase-wide convention convergence, or runtime outcomes, not just what this project's code implements.
2. **Team reference instead of copy**: a team declares `goal_slug` and resolves narrative + criteria from the definition; N teams sharing a slug resolve to one file. Broken references are reported, never silently degraded to an empty goal. Legacy teams with only an inline goal keep working with zero edits.
3. **Consumer integration**: 036's summary mechanism sources project narrative and milestones from the definition, replacing "take it from whichever team's `## Goal` body"; falls back to existing behavior when no definition exists.
4. **Single goal index**: 036's delivery directory moves from `.specify/project/goal/<goal-slug>/` into `.specify/goal/<goal-slug>/summary/` (37 measured referencing files), so the project has exactly one goal-indexed directory and `.specify/project/` holds no goal artifacts.
5. **`/speckit.goal`** as the sole entry for create / modify / view / migrate, delivered through the standard mirror model.
6. **Multi-team coordination** (N teams : 1 goal): a **derived** roster of participating teams in `summary/` (team slug, declared scope, explicit-vs-inferred identity, whether it is currently advancing); a new **team-level `territory`** declaration reusing the existing Write Scope / Read Scope / Forbidden vocabulary, covering all four collaboration patterns and carrying both path-shaped entries (normalized before intersecting) and typed non-path entries; overlap detection riding 036's existing goal summary refresh; the member-level *zero write overlap* invariant lifted to team level with read overlap still allowed; and a coordination round that only **detects and proposes** a re-division — a human ratifies, and the ratified division is written back into each `team.md`, never into the goal directory.

## Implementation Notes

- Reuse `goal_slug` and its grammar exactly as 036 established it (first char alphanumeric, rest `[A-Za-z0-9_.-]`, safe path segment, constrained by the invoked skill's DDL) — a second identity mechanism would immediately create a handover problem between the two.
- The `goal.md` + `summary/` split turns 036's write-set discipline from a deny-list ("everything except the definition") into a single-subtree allow-list, which is what makes "zero writes to the definition" mechanically checkable.
- `--goal` is already taken by two scripts with different meanings (`build-summary-input.py --goal` = goal identity to aggregate; `match-team-preset.py --goal` = objective text) — any new option must avoid that name.
- Coordination **lifts** the existing discipline rather than inventing a parallel one: `skills/create-team/SKILL.md` → Territory Division already defines Write Scope / Read Scope / Forbidden with a zero-write-overlap invariant, a Forbidden Write List for shared files, and optional `isolation: worktree` for physical separation. A new *team-level* field is nonetheless unavoidable — territory exists only at member level in the **parallel** pattern, so a union of member territories would cover one of four patterns. Non-path entries must be first-class because FR-029 makes the goal's object unrestricted, so a team's coverage is not always file-shaped.
- Path-shaped scopes MUST be normalized before intersecting. This repo has already been bitten by the opposite: a `{a,b,c}` brace path slipped through an existence check untouched. Glob vs explicit enumeration, relative vs canonical, and brace vs expanded forms all have to converge before any overlap verdict is issued — and "no overlap" must stay distinguishable from "undecidable".
- The migration is the largest risk surface: 5 per-tool command copies, skills and their mirrors, the generator script, a Tool record, and 036's own spec and 10 test files. Keep 036's assertions intact (paths updated only) and drive the fan-out with `sync-mirrors.py`, never manual dual-writes.
- Host-CLI `/goal` integration is deliberately excluded: official docs verification (`https://docs.qoder.com/cli/goal.md`) shows `/goal set <description> [--turns <n>]` accepts inline text only, with no file or identity option, so the originally requested "specify the goal via its description file" cannot be honored on the CLI side.

## Future Evolution Suggestions

- Consumer adapter that renders an archived definition into a host CLI's goal mechanism (the deferred integration) — one requirement per CLI whose contract is verifiable against official docs.
- Goal-level reader view answering "which goals are active, and how far along" across all teams.
- Relate goals to the Feature Index and requirement slices without merging the three layers.
