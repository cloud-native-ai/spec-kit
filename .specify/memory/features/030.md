# Feature Detail: History Command

**Feature ID**: 030  
**Name**: History Command  
**Description**: `/speckit.history` distills the current AI tool's past conversations for the current project into a theme-aggregated knowledge base under `.specify/history/` (decisions, reusable lessons, TODOs, interaction flows, user↔model conflicts — not verbatim). Incremental via a manifest; Claude Code supported today with a pluggable `STORE_RESOLVERS` adapter for other tools.  
**Status**: Implemented  
**Created**: 2026-07-14  
**Last Updated**: 2026-07-14

## Overview

Long-running projects accumulate large amounts of context inside AI-tool conversation history that is never captured anywhere durable. `/speckit.history` turns that history into a maintained knowledge base: it identifies the current tool and project, extracts the de-noised transcript of each past session, and distills each into five dimensions of long-term value — **关键决策与理由 (decisions & rationale, incl. abandoned alternatives)**, **可复用经验/踩坑 (reusable lessons/pitfalls)**, **未完成/待办 (unfinished/TODO)**, **关键交互流程 (key interaction flow)**, and **用户↔模型的冲突/分歧点 (user↔model conflicts)** — then aggregates them by theme into `.specify/history/`.

It is deliberately **tool-aware** (session history lives in different places per tool) and **incremental** (a manifest records which sessions were already distilled, so re-runs only process new ones and merge into existing docs, rather than re-summarising everything).

## Key Changes

1. **`scripts/python/history-utils.py`** — deterministic engine with `--action locate | extract | manifest-read | manifest-update`. Tool→store resolution is pluggable via `STORE_RESOLVERS` (Claude Code implemented: `~/.claude/projects/<encoded-path>/*.jsonl`, encoding `[/._]→-`). `extract` strips tool_use/tool_result/system-reminder/local-command noise, writes one de-noised transcript per session to `.specify/history/.work/<sid>.txt`, and returns an inventory with per-session `processed` flags. Unsupported tools return `supported:false` with an honest hint instead of guessing.
2. **`scripts/bash/collect-history.sh`** — thin wrapper (models `refresh-tools.sh`): sources `common.sh`, resolves repo root, prefers the `.specify/scripts/python` runtime copy, pins `--project`, forwards args.
3. **`templates/commands/history.md`** — the command template (models `research.md`): frontmatter `scripts.sh` → `collect-history.sh --json`; six-step Outline (identify tool → extract → distill per session via parallel subagents → theme aggregation → manifest update → report); canonical `## Feedback` and `## Handoffs` sections.
4. **Runtime mirrors** — `.specify/scripts/{python,bash}/` copies + generated command files for the four tool dirs present in this repo (`.claude/commands`, `.github/prompts`, `.qoder/commands`, `.opencode/command`), produced via the same transform the CLI generator uses (`rewrite_paths`, `{SCRIPT}` substitution, frontmatter dropped).
5. **Docs & registry** — `docs/commands/history.md`; `.gitignore` excludes `.specify/history/.work/` (the `.md` docs and `.manifest.json` are tracked); this feature entry.

## Implementation Notes

- The command was built directly (not via the full `/speckit.requirements→plan→tasks` cycle), so it has no `.specify/specs/` spec dir; Spec Path is `-`.
- Consistent with the project's "runtime mirror is manual and easily missed" pitfall: the existing runtime command files predate the `## Feedback` convention and are stale; the newly generated `speckit.history` files include it (matching the current generator). A future `/speckit.instructions` / refresh regenerates all commands consistently.
- Summarisation/theme-derivation is intentionally the AI's job (driven by the command prompt); only locate/extract/track is deterministic Python.
- Verified end-to-end against this repo's own 25 Claude sessions: `locate` → 25 sessions, `supported:true`; `extract` → ~993k chars of de-noised text; incremental manifest correctly skips processed sessions; unsupported/unknown tools degrade cleanly.
