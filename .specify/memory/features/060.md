## Overview

sdd-loop-driver 与 sdd-project-setup 都涉及"驱动子代理"调用 speckit 命令，且各自内联了同型派发机制（五族前置检查、ssh+su 命令形态、提示词文件与 runner 机制），与既有公用真源（subagent-definitions、external-dispatch-recipes）形成多副本。本特性以既有 Agent 三层分类法为骨架：

- **Template 层**：「SDD 执行者」能力模板——以项目目录为工作目录、加载项目上下文、执行 SDD 流程的能力面；分发层按内容判据裁定（不含用户/环境/项目专用信息 → 随 `specify init` 分发）。
- **Instance 层**：从同一模板实例化多职责实例（setup 操作者 / requirements 执行者等），一实例一职责，引用不复述。
- **Execution 层**：拓扑声明（本地直驱 / 远端 ssh+运行用户+CLI+项目目录）全部入口参数化，经 run-agent 发起真实执行，反嵌套治理上收为公用派发义务。

三技能承接面：create-agent（创建+生命周期）、run-agent（派发+前置检查+处置链）、improve-agent（执行证据回流）；两技能（sdd-loop-driver / sdd-project-setup）保留各自编排本体（六阶段循环 / 调协五步），机制段按 057 行为平价搬家清零。
