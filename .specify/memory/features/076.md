## Overview

spec-kit 的改进侧已有「批评和自我批评」纪律：SI-3C 要求每个改进提案在派发前携带一条可执行的证伪尝试（`shared/guidelines/critique-and-self-critique.md`）。但**决策侧没有对应装置**——`templates/plan-template.md` 不含反题、取舍或预期代价章节；ADR 的 `Alternatives` 事后撰写且不参与任何门禁；`/speckit.analyze` 只检测不一致，不回答「哪个冲突是主要的」。结果是：选了一个方向，却没有留下任何可判定记录说明「没选另一条会付出什么」。

本特性补两件事：

1. **决策反题与反指标契约（DTR）**：每个承重决策（不可逆 / 跨团队 / 高爆炸半径 / 与宪法原则相关）记录一条六字段张力记录；结构由确定性校验判定，语义由两位复核者按同一判据复现。
2. **证伪执行化**：把 SI-3C 的证伪尝试产物从「一句话 + verdict」升级为四元组（attempt / exit_code / observation / would_go_red_if），使「跑过」与「声称跑过」在工件上可区分。

本特性同时补齐 `docs/concepts/prompt-to-graph.md` §6 自陈的缺口一「指标没有强制成对（无 counter-metric）」在计划层的落点。

**术语裁决（2026-10-29 用户确认）**：内部允许「矛盾论」作为**理解用别名**（主要矛盾↔唯一承重张力、矛盾的主要方面↔`binding_constraints`、对抗性/非对抗性↔双方约束能否同时满足、矛盾转化条件↔`revision_trigger`），但**对外一律使用工程词**，遵循 `shared/guidelines/user-facing-comprehension.md`。

## Key Changes

1. **规范 owner** `shared/guidelines/decision-tension.md`：六字段 DTR 的输出形态、可采纳判据、拒绝形态、触发门槛与相邻 owner 边界，只在此定义；其他落点以路径引用，不复述。
2. **模板落点** `templates/plan-template.md` 增 `## Decision Tensions`：当计划含 ≥1 承重决策时必填，每条张力对应一个 `T-NNN`。
3. **分析检测** `/speckit.analyze` 增结构通道：承重决策缺 DTR、六字段不全、`expected_sacrifice` 无法映射到已声明的测量来源 → HIGH。
4. **证伪四元组** `shared/guidelines/critique-and-self-critique.md` 与 `shared/workflow/self-improvement-workflow.md` SI-3C：attempt / exit_code / observation / would_go_red_if；缺失或无法反空真即拒收。
5. **ADR 引用** `docs/decisions/template.md` 的 `Alternatives` 段引用 `tension_id`，不复制内容。
6. **复杂度门控**：DTR 只对承重决策强制，按 `shared/guidelines/task-complexity-rubric.md` 分级，trivial 任务不触发。
7. **确定性校验**：结构校验走既有 `scripts/python/`，不新增运行时（宪法 IX）。

## Implementation Notes

- 不新增存储：DTR 搭在 plan 工件上；证伪四元组搭在提案已有载体上（SI-4 派发载荷、SI-7 intervention 记录）。
- 不新增 `/speckit.*` 命令：DTR 由 `/speckit.plan` 填、`/speckit.analyze` 查、`/speckit.review` 复核。
- 与 requirements/clarify 的分工：需求阶段的分歧走 `clarify` 与 interview 账本（已有 `conflicts` 与翻供传播）；DTR 只承接「方向已定之后的技术取舍」。
- 与 `derivation-definitions.md` C5 的关系：C5 管「两个来源冲突时不得取平均」，DTR 管「一个决策的反面是什么、代价是什么」；两者共享「判别性问题」形态但对象不同，各自 owner 不复述。
- `expected_sacrifice` 必须可测量且能映射到 requirements 的 Measurement Sources；无法测量时该决策不满足承重门槛，降级为普通取舍。
- 术语对外用工程词；「矛盾论」别名只允许出现在内部设计说明与本 Feature 详情中。

### 规划落点（2026-10-29 plan 阶段）

- **analyze 通道取字母 `I`**：`SKILL.md` 的 checklist 通道已占用 `H`，新通道不可复用该字母。`detection-and-severity.md` 侧改动的行只有计数标题（`## The seven passes` → `## The eight passes`），它与新增通道小节同属 FR-014 声明的允许差异集；`SKILL.md` 的通道枚举句另行同步（这是指针更新，该文件不在 FR-026 指定的两个闭合面内）。
- **ADR 断链复用校验器的记录索引函数**：不为 ADR 另写第二个记录解析器；`dtr-tension-id` 与 ADR 断链契约测试共用一条实现。
- **`expected_sacrifice` 单值**：值中出现第二个 `SC-NNN` 即判解析失败，否则「代价」失去单值语义、SC-001 的一次记录一条来源无法计数。
- **plan 自身即首个夹具**：`T-001`（判定者＝确定性脚本 vs 接收方 agent）与 `T-002`（封闭文法 vs 自由文本）用未来校验器要解析的同一文法书写，实现期直接复用为夹具。
- **两处偏离已披露**：`create-new-plan.sh` 因 `CWS_LIB_BASH_HOME` 未设置退出 1（脚本本身不含分支动作，被抑制的是模板复制）→ 按模板就地填写；模板尚未含 `## Decision Tensions`，属实现阶段改动。

## Future Evolution Suggestions

- **主要矛盾排序算子**：多条 DTR 并存时选出唯一主要张力（因果 / 根源 / 阶段三检验）；须在 DTR 落地并有回放证据后启动。
- **对抗角色异质性契约**：proposer ≠ synthesizer、critic 异源、先独立后交换；属 teams 定义层，不引入调度器。
