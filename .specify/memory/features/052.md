# Feature Detail: 快速失败纪律(Fast Fail)

**Feature ID**: 052  
**Name**: 快速失败纪律(Fast Fail)  
**Description**: 把框架今天已在十余处要求 agent"停下来"、却从未定义"什么时候该停、什么时候可以顺手修完继续"的一条无名规矩,命名为一条独立纪律:在 `shared/guidelines/fast-fail.md` 建立唯一真源,以「解决它需要**纠正**还是需要**裁定**」这一可判定轴把执行期异常二值分流(顺手修复并披露 / 停在异常点上送用户),配两份封闭清单(其条目取自本仓已实测的失效:盲检四成因、`git diff` 三形态陷阱、`&&` 链空转、脚手架覆盖、两顶帽子错位、两振停滞)、两条可复现机械测试、经宪章模板 + 宪章命令**双落点**输出到下游项目,并针对子代理面新增**派发期注入义务**(注入子句 + 派发前自检 + 回传显式异常行),因为子代理的提示派生自其 Agent 定义与派发载荷而非常驻指令层。  
**Status**: Planned  
**Created**: 2026-09-22  
**Last Updated**: 2026-09-23

## Overview

框架今天的停止/上报规则分散在十余个互不引用的点位(可写性预探针、前提证伪回写、门控判定不得绕、非并行任务失败即停、两振停滞升级、只读命令缺件即中止、标记不配对即停、悬空引用不得静默降级),而真源文档数为 0、`快速失败` 作为一条纪律的名字在仓库中出现次数也是 0。后果不是"没有规矩",而是**规矩只存在于它被写下的那一个点位**:同类异常在某个流程里 MUST 停,在别处被就地修掉,修掉的痕迹不进任何报告,用户看不见,而看不见的错误逻辑被下游工件当作已验证前提继续引用、逐层扩散。

本仓最贵的一类缺陷正是这个形状:`docs/reference/history/00-cross-cutting-lessons.md` §十二 记录的四种盲检成因,共同点不是"检查失败",而是**检查成功了,而那次成功不是关于它被写来判定的那个命题的**——「看着绿的假通过比红着更贵;红会被人修,绿会被下游当证据引用」。本 Feature 要闭合的失效因此有一个名字:**静默兜底**。

两个落地层:**层 A(框架自身)** 真源文档 + 指令文件常驻顶级章节 + 两份封闭清单 + 契约守卫 + 与五条相邻纪律的边界落位 + 既有分散实例收敛为指针 + 门控预算中立 + 子代理派发注入;**层 B(下游项目)** 经宪章模板与宪章命令双落点导出,自动进入下游每次 `/speckit.plan` 门控的动态枚举。

子代理面是用户点名重点关注的部分,其依据经源码核实比直觉更硬:`shared/definitions/subagent-definitions.md:13` 明写子代理提示「not from the orchestrator's conversation」,团队上下文隔离规则另把「不传对话历史给子代理」定为**有意设置的屏障**——所以常驻层到不了子代理不是疏漏而是设计,未被注入的子代理是**结构性地**收不到规则。同时实测:`shared/guidelines/` 12 份纪律文档中 **0 份**提及子代理,派发这个动作上唯一的框架级 MUST 是外部派发可见性契约,而它只管"能不能观测"、不管"守不守规矩"。本 Feature 是第一个补这个洞的。

## Implementation Notes

- **最硬的机械约束是门控预算整数余量为 0**:扫描器实跑 total 23,两个契约测试把它钉成相等;新增文本落在 `shared/`、根级 `templates/*.md`、`skills/` 三个扫描面内,任何一行命中 17 条阻塞模式即同时打爆两个测试。处置取**设计规避**(零命中措辞 + 测试钉死),MUST NOT 扩大 `POLICY_DOCS` 豁免集——房式先例为 Feature 050 与 051。
- **真源文档 MUST 以路径而非中文名指称相邻的门控治理纪律**:其中文名逐字命中阻塞模式 `确认门[禁控]`。
- **命名取 `fast-fail` 词序**:该系列字面量全仓零命中;反序 `fail-fast` 在权威源上有 9 处占用、跨三种互不相干语义(可写性探测 / 平台与配置校验 / 配置写入原子性)。
- **注入 MUST 是调用方内容义务,不是包装器行为**:包装器只覆盖 external 一种模式,而义务须对 native / virtual / external 同等成立;且既有分工就是"机制归包装器、内容归调用方"。
- **MUST NOT 新增"所有 agent 继承的共享前导文件"**:`agent-definitions.md:40` 明写 Agent 定义制品自包含、其存储下无共享资产目录。通道二的义务因此绑定**制作者要求**(命令模板 Run Mode + `create-agent` 创作契约 + 出厂预设),而非一份会被无界实例目录打破的文件清单。
- **通道一的合规性不可被契约测试观测**(编排者当场撰写的提示不落盘),由评审强制;规格与 plan MUST 如实标注该边界,MUST NOT 声称三通道均由守卫覆盖。
- **注入子句副本是"守卫钉死的合法重复",不是"机器可再生副本"**:实测无引擎会再生团队载荷模式或 `.agent.md`,故须由成对定界符包围以便机械提取比对,漂移修复路径为从拥有者手工重灌。
