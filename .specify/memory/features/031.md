# Feature Detail: Glossary Mechanism

**Feature ID**: 031  
**Name**: Glossary Mechanism  
**Description**: Single project-wide glossary (`.specify/memory/glossary.md`) that anchors project vocabulary and corrects voice/dictated input (homophones, easily-confused words); initialized at instruction generation, ambient to all commands, progressively enriched with user-confirmed conflict handling.  
**Status**: Implemented  
**Created**: 2026-07-16  
**Last Updated**: 2026-07-16 (implemented: engine + template + protocol + init hook + ambient wiring; 23 tests pass, 0 regressions)

## Overview

Voice/dictated input frequently corrupts domain terms into phonetically similar but wrong words. This feature introduces a single project-wide glossary (词汇表) — a human-readable, user-editable Markdown artifact beside `constitution.md`/`features.md` — that records canonical project terms, their known confusable/homophone variants, and brief domain meanings. The glossary anchors high-frequency project descriptions to agreed vocabulary and doubles as a lightweight domain-knowledge dictionary. Per Principle IX it is a documentation/prompt-framework capability, not a runtime service: term correction and conflict judgment are prompt instructions; a small stdlib-only `glossary-utils.py` engine handles deterministic file operations.

## Key Changes

1. New glossary artifact `.specify/memory/glossary.md` (one per project) seeded from `templates/glossary-template.md` (dual-written to `.specify/templates/`).
2. Initialization hook in `scripts/bash/generate-instructions.sh` — non-destructive create-if-absent, preserving user-authored entries across re-runs.
3. Ambient wiring: Documentation Map row in `templates/instructions-template.md` → glossary loaded by every agent through the `.specify/instructions.md` symlinks (same mechanism as the constitution).
4. Shared protocol `shared/workflow/glossary.md` (mirrored) + a lightweight `## Glossary` reference step on `requirements`/`plan`/`tasks`/`implement` command templates (modeled on the `## Feedback` step): correction/anchoring, checkpoint enrichment, conflict detection + mandatory user confirmation, user precedence.
5. New engine `scripts/python/glossary-utils.py` (stdlib-only) with actions init/list/add/remove/detect-conflict/validate; contract + unit tests.

## Implementation Notes

- Documentation/prompt framework only (Principle IX): fuzzy homophone/meaning judgment stays prompt-side; the engine handles structural file ops and enforces "no conflicting write without user confirmation" (FR-009) as a single choke point.
- Non-destructive guarantee (FR-011/FR-013): `origin=user` rows preserved byte-for-byte on regeneration; mirrors the script's existing `## Project Overview` preservation.
- Mirror-sync discipline: `templates/` ↔ `.specify/templates/`, `shared/workflow/` ↔ `.specify/shared/workflow/`, and per-tool command copies each updated separately.
- No new runtime dependencies; must not regress the existing pytest baseline.
- Test-First is a justified Partial (template-heavy per Principle VII); the engine follows TDD.

## Future Evolution Suggestions

- Optional export of the glossary into a per-tool prompt include for agents that don't auto-load the Documentation Map.
- Confidence scoring / provenance for auto-proposed variants to prioritize user review.
- Cross-project glossary seeding (import a domain starter set) while keeping the single-per-project rule.
