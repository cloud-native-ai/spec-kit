## Overview

为 spec-kit 增加「执行量化数据回传与汇总」能力:`/speckit.feedback package` 打包流程把客户项目的 exec-quant 记录作为一等载荷一并收回,包经人工送达 spec-kit 后由入站包接收路径解出到本仓聚合层并按源项目归因,维护者可对聚合层执行跨项目汇总得到机器可读的聚合视图。三条腿:打包(客户项目侧,只读)、接收(spec-kit 侧,幂等)、汇总(显式动作,本地)。本特性是 059(Recording Only)的直接后续:059 显式排除的跨项目聚合进入本特性范围,059 FR-011 被显式修订且**仅打包一条腿**——「排除于一切上送路径(零自动传输)」子句原样保留。安全底线继承 059:凭据零出现、采集遮蔽与封顶不变、记录只读不重写、全链路非阻塞。

## Key Changes

1. 打包腿:`/speckit.feedback package` 将 exec-quant 存储中全部可读记录纳入包内载荷(全量包含,无增量水位),MANIFEST 显式声明;空 feedback 条目时载荷独立成包(FR-019)。
2. 接收腿:既有 `/speckit.feedback` 入站包处理路径承接 exec-quant 载荷(零新增命令),解出、按包级源项目身份归因、幂等去重进聚合层;feedback 条目处理语义不变。
3. 聚合层:exec-quant 存储自有派生子目录 `aggregated/`(与 `records/`、`scores/` 平行),按条落盘、可重建、多流程可并写,零可变聚合单文件。
4. 汇总腿:显式动作产出按源项目/单元维度的机器可读聚合视图,逐数字可对账、未测字段显式计数零臆造、产物仅本地零外发。
5. 边界:零自动传输红线按子句拆分修订 059 FR-011(仅手动打包腿放开);不新增确认门;既有 feedback/exec-quant 契约与集成套件零新增失败。
