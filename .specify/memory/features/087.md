# Feature Detail: 架构图为核心的文档空间（Architecture-Diagram-Centric Documentation Space）

**Feature ID**: 087
**Name**: 架构图为核心的文档空间（Architecture-Diagram-Centric Documentation Space）
**Description**: 把 `docs/` 文档空间从「按散文文档类型组织」改为「按架构图组织」：每份正式文档必须配套一张架构图或一条具名豁免；图以「可再编辑源 + 渲染产物」两面交付并被文档引用；义务落到 `create-docs` 的期望态基线与其写作流、以及 `improve-docs` 的内容改进流；新增一个确定性、只读、幂等的配套图检查器（封闭 verdict 集），由既有验证步骤触达；所有图经既有 `draw-diagram` 技能生成并携带引擎层 / 选择理由 / 语义模型摘要 / 交付契约验收的追溯记录——不新建第二引擎、第二渲染器、第二交付契约，也不新增 `/speckit.*` 命令。
**Status**: Planned
**Created**: 2026-11-06
**Last Updated**: 2026-11-06（checklist 阶段后：`/speckit.checklist` 生成 67 条 CHK 并消解 `OI-087-01`；`/speckit.tasks` 落 `tasks.md`；再经 `analyze` 质量门 round 1 的有界修复轮。Feature 维持 `Planned`，状态不变）

## Overview

`/speckit.docs` 今天是一层薄编排：结构归 `create-docs`、既有文档的内容归 `improve-docs`、可选站点归 `create-pages`，三者以 `create-docs` § Desired-State Baseline 为静态基线的唯一 owner。与此同时，本仓早已拥有统一的绘图前门 `skills/external/draw-diagram`（语义建模 → 六引擎层路由 → 渲染 → 对照 LDM 与交付契约验收）。**两者今天互不相识**：`create-docs` / `improve-docs` / `templates/commands/docs.md` / `docs/concepts/documentation-model.md` 对 "diagram" 零命中。结果是文档空间里没有任何一份文档带图，读者拿到的是纯散文，而图能力存在却无人消费。

本特性把这两条线接起来，并且只做接起来这一步：把「文档必须配套架构图」变成**可判定的事实**，而不是一句倡议。可判定性由三件东西支撑——写入流程在同一运行内产出图（或报具名失步）、期望态基线把「有图」写成合规的必要条件、一个确定性只读检查器给出按路径具名的 verdict。图的定义不在本特性里重写：一份东西算不算架构图，仍由绘图能力自己的语义模型判据决定。

## Key Changes

1. **期望态基线追加配套图义务**：`skills/external/create-docs/SKILL.md` § Desired-State Baseline（唯一 owner）把「有配套架构图或具名豁免」写成合规正式文档的必要条件；读者面向的解释在 `docs/concepts/documentation-model.md` 同轮对齐，不成为第二个规则 owner。
2. **两个写入流程都在同一运行内交付图**：`create-docs` 的 Authoring Flow 与 `improve-docs` 的 Workflow 在图的范围内产出或更新「源 + 渲染产物」两面，并由文档以解析得到的相对路径引用；失步时报具名 finding，不得绿灯收尾。
3. **新增确定性检查器**：封闭 verdict 集 `satisfied / missing / stale / recorded exemption / not evaluated`，逐条按文档路径具名；只读、幂等、覆盖不变空间时两次同 verdict；由既有验证步骤触达，不新增命令。
4. **复用绘图前门且只复用**：所有图经 `skills/external/draw-diagram` 生成，携带 FR-013 追溯记录（引擎层 + 选择理由 + LDM 摘要 + 交付契约验收结论）；仓内不出现第二引擎 / 第二渲染器 / 第二交付契约。
5. **负向可观测**：文档写完后移除图源或渲染产物，框架自身的验证必须转红并点名缺失的那一面；一直绿的检查在主体损坏时也绿，即为未验证而非满足。
6. **具名豁免而非静默缺失**：确实无可绘结构的文档走「记录在案的豁免」，未记录的缺失是 finding、记录的豁免不是 pass，失效的豁免可被报出。
