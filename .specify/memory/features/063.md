## Overview

062 的过程评审报告（`.specify/specs/062-humanize-command/review.md`：P0=0 / P1=6 / P2=2，15 条建议）暴露的不是 062 的个体失误，而是框架机制缺口：证据已写在树里却没有阶段消费（F1 引用组字符集/覆盖核算旁路、F2 checklist 无人作答）、生命周期最昂贵产物成为死信（F3 评审建议无所有者/无入口/路径不可移植）、AUTO-GENERATED 文本不可按原文执行且锁死欠测量记录（F4 编译 face 缺参）、封闭枚举与裸引用让事实在载体之外漂移（F5 环境判据载体、F8 gate 引用）、绿是声明而非证据（F6 声称 PASS 无归档证据绑定）、冻结值在消费侧无人重读（F7 基线重冻结只在生产侧声明）。

本 Feature 以机制修复收口：每条 finding 落到产生它的框架源（`shared/definitions/`、`templates/`、`skills/`、`scripts/`、`tests/`、`docs/`），`.specify/` 运行时副本经既有 sync/init 流程落位（两顶帽子）；062 的规格/计划/任务/评审报告是证据，不是编辑对象。两条决策类异常已裁决并保持：E1 保留 `(unit_id, run_id)` 幂等锁、不自动另铸 run-id（机制修复是让编译 face 首次调用即完整）；E2 `Implemented → Ready for Review` 转换归 `/speckit.review`。
