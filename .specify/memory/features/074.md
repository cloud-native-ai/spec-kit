## Overview

框架现有两条交付路径：Goal → Team → Agent 顶层链，以及独立的 SDD 开发流程（`sdd-loop-driver`）。二者只在 070 的 driver 内阶段团队预设处相遇，Goal/Team 层不知道 SDD 的存在，SDD 运行也不知道自己在推进哪个 Goal/Target。

本特性建立显式上下层：授权席位可启动有界嵌套 SDD 运行；Agent 能力（`sdd-invocation`）与 Team 席位策略（`team.md` frontmatter `seats` 映射）构成 AND 授权；确定性引擎按输入取值域输出三值裁决并记录理由码；反嵌套谓词收窄为深度 2 链（团队编排者 → 成员 driver host → 阶段执行者 leaf），virtual 成员不得承载；嵌套运行止于 review，交回集成身份与证据，合并/push 归外层。所有 SDD 概念均引用既有 owner，不复制阶段名册或 Goal/Target 模型。

## Key Changes

1. **控制层级与术语**：定义 Goal > Team > Agent > SDD Invocation 的上下层；SDD 永不创建、重绑或改范围 Goal/Team/Roster；同时定义「直接修改」为无 SDD 工件链但仍受既有质量门与确认门约束的变更。
2. **双层授权**：Agent 定义以中性键 `sdd-invocation` 声明能力，Team 席位以 `team.md` frontmatter `seats` 映射声明策略；有效授权为 AND，缺省 `forbidden`，派发载荷携带 team slug，按 (team, seat) 解析。
3. **确定性分流**：5 个输入（变更性质、可追溯性、影响面、可逆性、复杂度档）各有封闭取值域；固定优先级 `adjudicate > sdd > direct`；每次裁决记录输入与理由码；单点 owner 为 `shared/definitions/sdd-routing-definitions.md`。
4. **有界嵌套**：合法链深度 2（团队编排者 → 成员 driver host → 阶段执行者 leaf）；virtual 成员禁承载；阶段执行者仍是叶子；SDD-within-SDD 禁止；并发上限默认每成员一。
5. **交接与归因**：嵌套运行止于 review，handoff 携带 outcome / stages / 工件与证据路径 / 未决 findings / anomaly line / line id / branch / worktree / HEAD；team supervisor 写一条带 Target 引用的 ledger 归因行；嵌套运行不写 tracked 工件；不 merge、不 push。
