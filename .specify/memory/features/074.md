# Feature Detail: Goal/Team/Agent 与 SDD 开发流程统一（Unified Goal/Team/Agent Control Hierarchy with SDD Invocation）

**Feature ID**: 074
**Name**: Goal/Team/Agent 与 SDD 开发流程统一（Unified Goal/Team/Agent Control Hierarchy with SDD Invocation）
**Description**: 把 Goal → Team → Agent 控制链与 `sdd-loop-driver` 的 SDD 开发流程统一为上下层关系：Goal/Team/Agent 高于 SDD，授权团队席位可启动一次有界嵌套 SDD 运行；并以确定性三值判据（sdd / direct / adjudicate）明确何时走 SDD、何时直接修改。
**Status**: Draft
**Created**: 2026-10-28
**Last Updated**: 2026-10-28 (requirements + clarify: Feature 074 bound; 5 ratified decisions; 3 bounded corrections; validator exit 0)

## Overview

框架现有两条交付路径：Goal → Team → Agent 顶层链，以及独立的 SDD 开发流程（`sdd-loop-driver`）。二者只在 070 的 driver 内阶段团队预设处相遇，Goal/Team 层不知道 SDD 的存在，SDD 运行也不知道自己在推进哪个 Goal/Target。

本特性建立显式上下层：授权席位可启动有界嵌套 SDD 运行；Agent 能力（`sdd-invocation`）与 Team 席位策略（`team.md` frontmatter `seats` 映射）构成 AND 授权；确定性引擎按输入取值域输出三值裁决并记录理由码；反嵌套谓词收窄为深度 2 链（团队编排者 → 成员 driver host → 阶段执行者 leaf），virtual 成员不得承载；嵌套运行止于 review，交回集成身份与证据，合并/push 归外层。所有 SDD 概念均引用既有 owner，不复制阶段名册或 Goal/Target 模型。

## Key Changes

1. **控制层级与术语**：定义 Goal > Team > Agent > SDD Invocation 的上下层；SDD 永不创建、重绑或改范围 Goal/Team/Roster；同时定义「直接修改」为无 SDD 工件链但仍受既有质量门与确认门约束的变更。
2. **双层授权**：Agent 定义以中性键 `sdd-invocation` 声明能力，Team 席位以 `team.md` frontmatter `seats` 映射声明策略；有效授权为 AND，缺省 `forbidden`，派发载荷携带 team slug，按 (team, seat) 解析。
3. **确定性分流**：5 个输入（变更性质、可追溯性、影响面、可逆性、复杂度档）各有封闭取值域；固定优先级 `adjudicate > sdd > direct`；每次裁决记录输入与理由码；单点 owner 为 `shared/definitions/sdd-routing-definitions.md`。
4. **有界嵌套**：合法链深度 2（团队编排者 → 成员 driver host → 阶段执行者 leaf）；virtual 成员禁承载；阶段执行者仍是叶子；SDD-within-SDD 禁止；并发上限默认每成员一。
5. **交接与归因**：嵌套运行止于 review，handoff 携带 outcome / stages / 工件与证据路径 / 未决 findings / anomaly line / line id / branch / worktree / HEAD；team supervisor 写一条带 Target 引用的 ledger 归因行；嵌套运行不写 tracked 工件；不 merge、不 push。

## Implementation Notes

- 反嵌套义务在其既有 owner（`subagent-definitions.md` § Dispatch-Time Governance Obligation）中一次性收窄为深度 2 链与 virtual 禁令；`run-agent` 派发前探针按 FR-005 谓词 fail-closed。
- 新中性键 `sdd-invocation` 需加入 `NEUTRAL_AGENT_METADATA_KEYS` 与其校验允许集，且不渲染到任何宿主工具；`seats` 是 `team.md` frontmatter 扩展，缺省不减损既有团队。
- 复用 064 的 line registry / worktree-per-write-line / ownership，复用 070 的 work package 分解；不新增第二 registry / ownership / integration queue / state spine。
- `sdd-project-setup` 与 `sdd-house-keeping` 在同一路由面登记为 bootstrap/maintenance 路径；它们派发子代理时同样满足有效授权谓词，但只有 `sdd-loop-driver` 构成 SDD invocation。
- 不新增自动 merge/push、调度器、第二道确认门或自动反馈传输。
