# Feature Detail: Probe-Handler 体系

**Feature ID**: 056  
**Name**: Probe-Handler 体系  
**Description**: 把 probe 泛化为全框架可查询、可修改的一等实体，并新增 Handler 层使一个探测点可挂接 N 个已注册反应。  
**Status**: Planned  
**Created**: 2026-10-13  
**Last Updated**: 2026-10-13

## Overview

Probe 目前只在 feedback 域完成实体化（028 的 Class×Object 注册表，6 Class / 72 Object）；其余探测→反应机制（050 升级探测、运行判定四轴、证据 lane 探测、满意度识别等）硬编码在引擎代码里，无 id、无注册表、无查询面。同时 wrap-up 收尾点已自发演化出五个反应机制（feedback 记录+阈值提示、token 自评、运行判定、docs-sync 评估、wrap-up 反思），以手工嵌入段接线——每加一个机制 = 全框架模板手术（040 实测传播足迹 194 文件）。

本特性建立三层实体模型 Probe Class × Probe Object（既有，扩格为伞形）+ HandlerBinding（订阅+次序+模式）+ Handler（跨单元可复用反应），配共享引擎 `probe-utils.py` 的 `compile-embeds` 编译动作：从注册表渲染每单元单一 AUTO-GENERATED `## Wrap-up` 收尾段，由既有 regen/sync 机制传播。**加一个 wrap-up 反应 = 注册一行 + 重编译**。行为真源文件保持行为规则不动，注册表只接管接线。宿主项目对体系为只读（查询面可用，注册/编译写面仅框架侧）。

## Key Changes

1. `shared/definitions/probe-definitions.md` 扩格为全框架 Probe 真源（伞形）：feedback 6 Class/72 Object 语义不变，050/运行判定/证据引擎探测点以声明性元数据入册，纯代码微探针以纯指针目录收录。
2. 新增 Handler（六字段封闭集：handler_id/kind/action/mode/order/behavior_owner）与 HandlerBinding（selector 订阅，1 probe ⇒ N handler）两个实体。
3. 新建共享引擎 `probe-utils.py`：自 feedback-utils.py 抽出 probe 族动作（probes/map/probe-inject 三 action，validate/reconcile 为 flag），新增 handlers/compile-embeds 动作。
4. 23 命令模板 + 46 技能的手工嵌入收尾段迁移为编译产物，传播走既有 regen/sync 机制，五项语义零回退。
5. 对账守卫扩展：编译产物↔注册表双向零缺漏、engine action 封闭集 import 对账、门控预算 total 23/violations 0 零扰动、order 次序契约测试钉住。
6. 词汇表三新术语（Probe 伞形/Handler/HandlerBinding），Feedback Probe 降为域实例；docs/reference probe 体系文档更新。
