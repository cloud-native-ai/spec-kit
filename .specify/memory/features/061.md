# Feature Detail: 子代理 CLI 配置管理与按派发量化

**Feature ID**: 061  
**Name**: 子代理 CLI 配置管理与按派发量化（Subagent CLI Config Management & Per-Dispatch Quantification）  
**Description**: 为子代理派发补齐配置分层解析、CLI 能力校验与按派发量化记录——让 `_defaults.yaml / configs/<slug>.yaml / 内联参数` 真正生效，并让每次派发落一条带 `config_id` 的 `agent:<slug>` 记录  
**Status**: Implemented  
**Created**: 2026-10-18  
**Last Updated**: 2026-10-20

## Overview

060 已定义 Agent 三层分类法与外部派发契约，并在 `.specify/agents/execution/configs/` 预留 `model / reasoning_effort / context_window / extra_flags` schema，但无解析、校验、透传实现——配置写了不生效。059 已实现 `exec-quant.py` 的单元级量化，但 `collect_llm()` 只硬编码 qoder 宿主机配置面适配器，无法区分不同子代理/不同 CLI 配置，也没有「声明配置 vs 实测生效值」的区分。

本 Feature 补齐两件事：**子代理命令行工具配置管理**与**每次派发一条量化记录**。配置按 `_defaults.yaml < configs/<slug>.yaml < 内联 dispatch 参数` 三层合并，按 CLI 能力矩阵校验并产出可复现的 effective config、`config_id`、`source_chain`、`cli_args` 与配置快照；派发后 `collect-dispatch` 以 `unit_id=agent:<slug>`、`run_id=派发 label` 落一条记录，按 `auto / declared / qoder-settings / none` 解析量化方法并将声明值与实测值分开标注。

## Implementation Notes

- CLI 能力矩阵在解析引擎内拥有唯一 owner；文档只引用、不复制表格。
- qodercli 支持 `--model / --reasoning-effort / --context-window` 全量；claude 仅 external + `declared / none`（显式旗标值被拒，`declared` 当前不可达；见 plan Phase 0 裁定 3）；codex/opencode 的 external stream-json 未验证 → 拒收并留扩展点。
- 量化非阻塞、append-only、凭据脱敏、64 KiB 单记录封顶沿用 059。
- stream-json 的 usage/duration 字段未经本机验证：存在才取，否则显式未采集，不猜测事件格式。
- 本特性会修改 run-agent / preflight / exec-quant，而无人值守驱动循环依赖这些面派发后续阶段；implement 后必须重新读取更新后的派发契约再派发 review。
