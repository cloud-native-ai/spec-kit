## Route R1 的缺陷:按体积比较会把「项目应填的骨架节」误判为漂移

R1 原文写的是「逐节比较活动文件与模板的同名节体积,活动侧明显更大即压回模板形态」。实测在本仓命中 4 节:

| 节 | 活动 | 模板 | 差 |
|---|---|---|---|
| Documentation Map | 5264 | 1969 | +3295 |
| Tech Stack & Resources | 3174 | 497 | +2677 |
| AI Tool Compatibility | 779 | 228 | +551 |
| Project Overview | 436 | 236 | +200 |

**其中 3 项是假阳性**:这三节在模板里是**带占位符的骨架**(`[Other Doc]`、`{{PROJECT_NAME}}`、`[Detected tech stack...]`、`[Brief summary...]`),项目**本来就该把它填大**——「活动侧比模板大」正是它的正确终态,不是漂移。按 R1 原文压缩它们等于删掉真实项目内容。第 4 项(AI Tool Compatibility)也不是 R1 候选:活动侧比模板**多**了 tier 分层与 canonical 来源指引(`AGENT_CONFIG` / `_ASSISTANT_TIERS`),而模板侧没有承载这些细节的 owner,压缩即丢失——正是 R1 前置条件要挡的那种情况。

⇒ **R1 的假阳性率在本次运行中是 4/4**。已就地修 R1 措辞,加两道过滤器:① **先排除项目填充节**(模板版本仍含占位符 token 的节不参与体积比较);② 前置条件补上**否定结论**(owner 未承载该细节 ⇒ 该节**不是** R1 候选,要么不动、要么先把细节移进 owner 再压)。并给 `test_instructions_size_budget.py` 加了对应断言——该测试随后立刻抓住我改 R1 措辞时把被钉字面量 `actually carries the detail` 改掉的事实,是一次真实的红。
