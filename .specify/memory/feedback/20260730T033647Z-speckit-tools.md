## Review
Restructured /speckit.tools into a single-entry intent router matching the team/agents/skills pattern: five modes route define->create-tools and modify->improve-tools, view/list are read-only, invoke keeps the preview->confirm->execute gate. Created both skills with the full SKILL.md skeleton, moved the four type templates into skills/create-tools/templates/ (registered as obsolete top-level assets, resolver updated with fallback + missing webhook case), added a 25-assertion contract test, and dogfooded the command by registering refresh-tools.sh / feedback-utils.py / evidence-utils.py as Verified records with populated params, returns and RFC 2119 rules. Exercising the real pipeline exposed and fixed four tools defects plus a rewrite_paths path-mangling bug. Validation: zero new failures vs the pre-change baseline (73 vs 84), 11 baseline failures fixed.

## Optimization Points
- The tools pipeline had four latent defects that only surfaced when the flow was actually executed end-to-end (`save_record` IndexError on shallow dirs; `create` conflating a discovery hit with an existing record; `sed` substitution breaking on slash-containing paths and never filling three header fields; `load_record` hard-coding `arguments=[]` so no `Verified` record could round-trip). All four were invisible to "files exist / headings present" checks. Dogfooding a command by running its real pipeline should be a standard step when restructuring a command, not an optional final touch.
- `rewrite_paths` in `src/specify_cli/__init__.py` rewrote any occurrence of `templates/` or `scripts/`, including nested ones, so `skills/<name>/templates/` became `skills/<name>/.specify/templates/` in every generated per-tool command copy. This had already silently corrupted `speckit.agents.md` before this run. Path-rewriting rules need boundary anchors, and the regen `--check` output should be read as a correctness signal rather than just a drift report.
- `regen-command-copies.py` computes the repo root as `parents[2]` of its own path, so running the `.specify/scripts/python/` mirror copy crashes with a doubled `.specify/.specify/` path. The script should either detect that it is running from the mirror or fail with a clear message pointing at the canonical `scripts/python/` copy.
