## Review
create 模式一次跑通:8 项决策经 interview-utils 决策 DAG 收敛(前沿计算/冲突收窄/退出门就绪判定全部交引擎),goal-utils create+validate+targets --check/--add 全绿,新术语 evaluation form 无冲突入表。范围守本地:未越界写 goal.md 以外的制品——用户追加的 goal-definitions.md 属性 2 修订被识别为超出本命令写权限,单独上报而未顺手改。发现的机制缺口见优化点:GD-2 词面检测挡不住阶段化措辞,导致引擎判定被误读为定义合规;goal.md 三段结构无处安放范围边界排除项。token-efficiency:同一文件多次小窗口重复读取。

## Optimization Points
- # /speckit.goal create 运行优化点（draw-two-layer-structure，2026-09-16）
- **[引擎判定与定义背离] `goal-utils.py` 的 GD-2 检测是纯词面的，挡不住"有序阶段伪装成切片"。**
- `_STEP_VERBS` 只有 `首先/然后/接着/step 1/then /next,`，`_TASKLIST` 只匹配行首编号或项目符号。
- 本轮实证：三条切片命名为"重构阶段/自测阶段/公测阶段"，`check-statement` 第①条直接 `verdict: ok`，
- 第②③条仅因含"然后"被驳；用户去掉"然后"重述后，三条在 `targets <slug> --check` 全部 `verdict: ok`
- 并落盘为 T-001/002/003 —— 而 `shared/definitions/goal-definitions.md:86` 属性 2 明写 Target 集合是
- **无序集**、"an ordered target list is an implementation plan wearing a goal's clothes"。
- 语义规则引擎判不了，词面规则又被轻易绕过，结果是"引擎通过"被误读为"定义合规"，全靠 agent 人工
- surfacing 才暴露。建议：给 `targets --check` / `check-statement` 增一条阶段化措辞探测
- （如 `阶段|第[一二三]步|phase \d|stage \d`）作为 GD-2 的词面补充，或在 verdict 输出里附一行
- "语义规则（无序集）不在本判定覆盖范围"的显式声明。
- **[定义文件缺口] `goal.md` 的固定三段结构没有"范围边界/排除项"的安放处。**
- `_render()` 只产出 `## Objective` / `## Success Criteria` / `## Targets`（有切片时）/ `## History`。
- 本轮访谈定出一条明确排除项（arena 竞技不再作为优化手段，但其 team 与结论账本保留，前门对账本的
- 三处活引用不在本目标范围内），却无处落盘，只能留在 `.specify/memory/session/` 的访谈台账里；
- 只读 `goal.md` 的下游消费方（团队 evaluator、summary 映射）读不到这条边界。
- 建议：增可选 `## Boundaries` 段，或在文档中明确"边界排除项可作为 Objective 的从句承载"。
- **[可读性] `create` 无 `--title` 参数，标题被强制等于 slug。**
- `create_goal()` 把 slug 直接当 title 传入 `_render()`，产出 `# Goal: draw-two-layer-structure`。
- slug 受身份文法约束只能 ASCII，中文项目的 goal.md 标题因此不可读。建议 create 支持可选 `--title`，
- 缺省回落 slug（向后兼容）。
- **[token-efficiency] 本轮对同一文件做了 4 次小窗口重复读取。**
- `goal-utils.py` 被分四次读取（`--help`、GD-2/GD-3 文法段、`_render()`、`create_goal()`），
- 其中渲染器与 create 路径本可一次定位读完；另 `interview-utils.py` 的 init/add 签名也单独跑了一次
- `--help`。属于"重复读取同一内容"的可避免消耗，量级为个位数次工具调用（不编造精确 Token 数）。
