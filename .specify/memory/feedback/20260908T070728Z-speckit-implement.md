## Optimization Points
- **Single-pass writes over ~300 lines need a self-review pass before the first test run.** The 1480-line engine went out with four defects that a re-read would have caught: a dead `if False else` branch that also referenced `expanduser` (forbidden by C-19's source scan), a nonsense `return True is False` in `is_suppressed`, a 21st `--snapshot` flag that broke C-10's closed set of 20, and a `resolve_root` precedence bug. Cost: ~13 avoidable round-trips out of ~75 tool calls (~17%).
- **The `resolve_root` bug was the most expensive single item and had a repo-pollution blast radius.** Because this framework repo itself contains `.specify/`, my first precedence rule ("nearest ancestor containing `.specify`") resolved EVERY invocation to the framework repo instead of the caller's workspace. Every subprocess-based test therefore wrote into the real repo: it created `.specify/memory/trigger/` and appended a telemetry entry to `.gitignore`. It surfaced as 23 simultaneous test failures. Lesson: when a resolution rule is tested inside the framework's own repo, the repo is a pathological case for any "walk up to find the project marker" heuristic — assert the negative case (canonical copy must NOT self-resolve) as its own test, which I only added after the fact.
- **Front-loading the single-file engine saved roughly two implement-verify-mirror cycles.** tasks.md schedules edits to `scripts/python/trigger-utils.py` across Phases 4/5/6 with a mirror-parity task after each. Since all three stories' tests are marked `[P]` and parallel-eligible, I wrote all 8 test files RED first (observing 21+12+17 integration failures), then implemented the engine once. Red-first was preserved per story. This also dissolved a real inconsistency in tasks.md: T027 demands the engine contract be fully green at Phase 4, while T035 says C-16…C-18 only turn green at Phase 5 — both are satisfiable only if the engine lands whole.
- **Batch verification calls.** Several round-trips ran one command each (sync-mirrors, then diff -q, then pytest). These are independent and belong in a single call; each separate call also risks re-injecting large ambient context.
- **Delegate file-disjoint artifacts.** tasks.md's Parallel Team Strategy describes a two-developer split and I ran the whole thing single-threaded. T044 (Tool record), T045 (drift-guard liveness experiment) and T049 (verification.md consolidation) are file-disjoint and fully specifiable from the contracts; the T036/T043 walkthroughs are scriptable the same way T028's was.
- **Well-spent, do not optimize away:** the T013 investigation (4-5 calls) proved `specify init` never writes `.specify/instructions.md` nor any symlink — a premise defect in quickstart scenario 1, corrected in the artifact. Cheap calls that invalidate a design assumption are the highest-yield spend in an implement run.
- **Honest limit on T050:** it requires >=20 turns of ordinary work with the mechanism live. This session was building the mechanism, not doing ordinary work under it, so those turns are not genuine samples. The plan already lists this as a foreseeable `[~]` deferred candidate; it should be deferred with that reason rather than fabricated from build-session turns.
