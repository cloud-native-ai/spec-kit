## Review
First real exercise of the size-budget control added earlier the same day, run on the framework repo itself with empty arguments (full reconcile). The control worked end to end: the setup script opened by reporting 34,059 B against a 32,768 B budget, over by 1,291 B, and ranked the largest sections — so the convergence trigger came from the command rather than from the user relaying the host CLI's warning, which was the whole point of the change. Route R2 then relocated the largest section (Recurring Operational Lessons, 6,961 B) to the owner document it already named, by scripted extraction with both directions asserted, landing the file at 28,168 B with 4,600 B headroom. All 19 bullets were accounted for by an asserted classification (8 moved verbatim into new owner sections, 1 folded into an existing owner section that lacked it, 9 deleted as restatements after verifying a distinctive literal in the owner, 1 container label), and the coverage check against all six backups attributed all 16 difference items instead of declaring nothing lost. Contract suite 22 failed / 2067 passed with comm -13 empty against both the frozen baseline and this run's own pre-command state. The run also falsified part of the change it was exercising: Route R1's raw size comparison flagged four sections and all four were false positives — three are placeholder scaffolds the project is supposed to fill, and the fourth is thicker because no owner document holds its detail. R1 was corrected in place with two filters and the correction was guarded by a new assertion, which then immediately caught my own rewording dropping a pinned literal. One environment obstacle: three files under .specify/ needed by this run were root-owned from an earlier external process, repaired by rm-plus-restore with sha256 verification since no sudo is available.

## Optimization Points
- **The command has no `## Artifact Commit` step, so a run that materially rewrites the ambient instruction file ends with no commit guidance.** `requirements`, `clarify`, `plan`, `tasks` and `analyze` all embed `shared/workflow/artifact-commit-step.md`; `instructions.md` embeds Feedback, Documentation and Handoffs but not that. This run converged 5,891 B out of `.specify/instructions.md` and migrated 19 bullets into an owner document, then had to decide by hand what to stage — and the tree also held three files from an unrelated `specify` CLI refresh (`.specify/source.json`, `.specify/agents/.render-manifest.json`, and a skills mirror heal), so "just commit everything" would have folded another actor's state into this run's commit. Add the canonical Artifact Commit step: deletion-surface audit first, explicit paths, never `git add -A`, and report uncommitted artifacts that are not this run's as an upstream deviation rather than absorbing them.
- **Action 2's section inventory is prose-only, but it is the exact measurement Routes R1 and R2 consume.** Action 2 asks the agent to "list the base's top-level sections and note, for each, whether it is auto-derivable or hand-authored" — a judgment made by eye. Route R1 then needs "is this section template-owned and has it drifted", and R2 needs "is this section project-owned and over the threshold". Both are the same classification, and doing it by reading is precisely what let R1 mis-fire on three placeholder-scaffold sections this run. Make Action 2 emit a **scripted** table — section, live bytes, template bytes, delta, placeholder-token present, project-owned — as the mandatory observation artifact, and have R1/R2 read candidates off it instead of re-deriving. One measurement, two consumers, and the false positives become visible in a table before anything is compressed.
- **Route R1's size comparison needs its candidate filter stated as data, not as a caveat.** The fix landed this run (exclude sections whose template version still carries a placeholder token) is correct but lives in prose inside a long bullet. A run under time pressure reads "live is materially larger → compress" and acts. The exclusion should be the first clause of the route and should name the discriminators mechanically (`[` + `]` bracket tokens, `{{VAR}}`), because the failure it prevents is silent: compressing `## Documentation Map` back to its 1,969 B skeleton produces a smaller file, a green budget report, and a project that has lost 15 navigation rows.
- **Backups accumulate with no pruning guidance.** This run created three more `.specify/instructions.md-<TIMESTAMP>` files (two of them from a controlled attribution experiment), bringing the total to nine. Action 3 treats the whole set as the recovery source and correctly warns that the most recent may itself be post-damage — but nothing says when an old backup stops being worth keeping, so the set grows one file per run forever. Suggest a retention note: keep the newest N plus any backup that still holds a heading the live file lacks, and say so in the residual report.
