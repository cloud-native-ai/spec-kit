## Review
Clarified the Tool concept across the project after a full audit. Found three gaps: the rationale (stability+efficiency abstraction layer absorbing environment variance and replacing throwaway LLM-generated scripts) was absent everywhere; ToolRecord could not express version/platform/arch/fallback/preflight; and the reuse-before-generating discipline existed only inside the tools domain. Fixed by writing the canonical definition in shared/definitions/tool-definitions.md, adding EnvironmentApplicability with full round-trip plus the section in all four templates, propagating the gate as shared/workflow/tool-reuse-gate.md and Constitution Principle XII (v1.8.0), and disambiguating the three senses of 'tools' at every collision hotspot. Dogfooded on three records with execution-verified preflights. Validation: full suite 73 failures vs 84 baseline, zero new failures, 11 baseline failures fixed; contract test at 38 assertions.

## Optimization Points
- The tools domain shipped a complete schema with no recorded rationale: the only documented "why" was "override the LLM's built-in knowledge", while the actual purpose (absorbing environment variance; replacing throwaway generated scripts) existed nowhere in the repo, and the schema had no field able to express it. A capability whose stated purpose cannot be represented by its own data model is a design gap that no test would ever catch. When a command is restructured, the concept's rationale should be audited alongside its mechanics.
- A cross-cutting discipline documented only inside its owning domain has no effect. "Reuse an existing tool before writing a script" lived solely in the tools domain's own shared definition — no other command, skill, or constitution principle referenced it — so nothing would ever trigger it. Propagation (shared convention + constitution principle + instructions surface) is what turns a stated rule into an enforced one.
- Terminology collision was load-bearing: "tools" carried three distinct meanings (Tool record / AI agent CLI / an agent's `tools:` call-list), with all three co-occurring in AGENTS.md, and 16 test files named `test_ai_tools_*` that have nothing to do with Tool records. Disambiguating at the definition site plus each collision hotspot is cheaper than repeatedly re-deriving which sense a document means.
- Verifying preflight commands by executing them caught a wrong record before it was persisted: `refresh-tools.sh --help` exits 1, so the obvious preflight would have been a false negative on every cycle. Environment fields must be populated from observed runs, never from what the command "should" do.
