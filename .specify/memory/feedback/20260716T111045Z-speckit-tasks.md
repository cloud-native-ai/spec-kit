## Optimization Points
- The `tasks-template.md` sample tasks and Path Conventions are app-shaped (`src/models/`, `src/services/`, endpoints, `backend/`/`frontend/`). For a documentation/prompt-framework feature the real work is templates + mirror dual-writes + a small stdlib engine; mapping onto the app skeleton required heavy manual reshaping. A framework-flavored task shape (or an explicit note that "models/services/endpoints" are illustrative) would cut adaptation effort and reduce the risk of forcing an ill-fitting structure.
- Mirror-sync is this repo's top rework source, yet the tasks template has no first-class concept of a "dual-write + diff-verify" task pair. Every template/shared edit here needed a paired mirror+`diff -q` task (T004/T014/T019/T027/T033/T036) authored by hand. A template affordance for paired mirror tasks would make the discipline harder to forget in downstream `/speckit.implement`.
