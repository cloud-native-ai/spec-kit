## Optimization Points
- Checklist Format 一节把「Description with file path」列为强制,但命令没有给出可执行的校验方式,也没在 Outline 步骤 6 的 "Format validation" 里给判据。本次首轮生成有 **31 行(101 行中约三成)** 缺少显式文件路径——全部集中在两类:承接上一任务文件的测试用例行("Add an FG-6 case …")与承接模块的实现行("Implement the `phases` mapping …")。这类行在人读时靠上下文可推断,但直接违反"每个任务必须自足到 LLM 无需额外上下文即可完成"的目标。建议:命令给出一段可直接运行的行级校验片段(正则匹配 checkbox + ID + 可选 [P] + 可选 [Story] + 反引号路径),并把它列进步骤 6 的必跑项;同时明确"路径由兄弟任务隐含"不算满足。
- 步骤 5 只要求校验 DoD 节的 checkbox 格式,但 `## Completion Gate` 节用的是同一条格式规则(`- GATE-N:` 前缀、禁用 checkbox),却没被纳入校验。两节的失败后果相同(`grep -cE '^- \[ \]'` 统计开放任务时会被污染)。建议:把步骤 5 的校验范围从 DoD 扩展到"所有使用 `- X-N:` 前缀约定的节",或直接表述为"`## Definition of Done` 与 `## Completion Gate` 两节均不得出现 checkbox 语法"。
- `[blockedBy: …]` 是 `/speckit.implement` 拓扑排序的唯一依据,但命令没有要求校验引用完整性。本次 99 处 blockedBy 引用需要逐一确认目标任务存在,否则 implement 会在运行期才发现悬空引用而拒绝启动任务。建议:步骤 6 增加一条——所有 blockedBy 目标 ID MUST 在本文件内存在且形成 DAG(无自引用、无环),并给出校验片段。注意校验器需排除 `## Format` 说明性散文中的 `[blockedBy: …]` 字面量(本次即产生一次假报警)。
- Environment Prerequisites 一节要求"probe at generation time"并"pre-validate named targets",本次照此发现了一条只有真跑才暴露的坑:`render-plantuml.sh` 的用法是 `<input> [output_dir] [prefix]`,省略 output_dir 时会把 `diagram.{puml,svg,png}` 写进**当前工作目录**——首次探测直接在仓库根留下三个未跟踪文件(已清理)。这类"探测本身产生副作用"的情况命令未提示。建议:该节补一句——探测外部渲染/构建工具时在仓库外的临时目录执行,并在探测后校验仓库工作区仍干净(`git status --short`),避免把探测产物当成实现产物提交。
- Doc-feature phase shape 要求把 plan.md 的 Mirror Obligations 每一行变成"dual-write + verify"成对任务,但本项目的 dual-write 实际由**单一入口** `sync-mirrors.py --write` 一次完成全部 6 行,逐行拆 dual-write 任务会产出 6 个内容相同的任务。本次采用的折中是:每个编辑阶段末尾放一个 sync 任务,Polish 阶段放 6 个逐行 verify 任务。建议:该节补充"当项目存在统一同步入口时,dual-write 可合并为每阶段一个任务,但 verify MUST 保持逐行"的裁剪规则,避免生成器在"照字面拆"与"合并"之间临场取舍。
- token-efficiency: 本次未重读 plan.md / data-model.md / contracts/(同会话内自己产出,已在上下文),只用 `grep -nE` 做测试模式判定(命令已明确要求 program-first,执行到位)、用 `sed -n` 定向取 tasks-template 的 DoD/Gate/Sigil 三段而非通读 348 行,并用两段 Python 一次性批量校验格式/ID 连续性/story 标签/路径/blockedBy 完整性而非逐行人读。可改进点:格式校验的正则写得过严(要求路径必须是不含空格的反引号 token),对 `` `python3 -m pytest -q tests/...` `` 这类含空格的命令行产生 5 处假报警,来回调整了两轮;应一次写成"反引号内含 `/` 或已知扩展名即视为含路径"。
