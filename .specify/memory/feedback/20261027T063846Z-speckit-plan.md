## Review
Plan stage for the review x code-review composition: contract set written in the canonical C-N clause form, FR lane 28/28, six contracts / 73 clauses, plan gate pass with 20 expected missing-path advisories.

## Optimization Points
- [token-efficiency] pre-analyze-check.py's clause registry matches `^- \*\*([A-Z]{2,4}-\d{2})\b`, so a contract set written in the canonical `**C-N**` form declared by shared/definitions/contract-clause-definitions.md § 3 reports `clauses=0`. The gate reads clean while registering none of the clauses; the plan-stage evidence had to explain the zero in prose. Either the pattern should learn the canonical form or the gate should name the canonical form as out of scope.
- The clause/FR coverage engine's citation extractor (`clause_citations`) returns FR ids only, so an SC-level coverage assertion cannot be built from the engine even when contracts cite SCs in their citation groups. The SC half of traceability stays prose-only by construction.
- account-clause-coverage.py's clause lane cannot pass before tasks.md exists (its claimed set is the `[green:]` declarations), and its docstring does not state that stage boundary; a plan-stage run therefore reads 73 "beyond the frozen baseline" items whose meaning has to be re-derived by the caller each time.
