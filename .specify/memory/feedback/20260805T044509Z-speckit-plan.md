## Review
Planned requirement 037-goal-registry (42 FR / 18 SC / 5 user stories) against Feature 041 Goal Registry. No arguments, so no scope restructure was requested — but the mandated exploration pass refuted two documented spec measurements, which forced a spec amendment before the plan could be trusted: the migration surface is 24 live source files rather than the cited 37 (with 18 historical files that must not be rewritten), and SC-011's whole-repo zero-residual target was unachievable by construction because the spec's own Clarifications entry quotes the old path verbatim. Both were corrected in requirements.md with a fifth dated Clarifications session recording old value, measured value and method. Exploration also established that .specify/project/goal/ was never materialized, so the migration moves no data, and that territory has zero executable validation today (prose-only, member-level, parallel-pattern-only) — which reframed US5 from 'extend a validator' to 'write the first one', and located its ride-along inside resolve_goal(), the function that already enumerates every team sharing a goal_slug. Delivered plan.md (13-principle Constitution table rendered from constitution.md v1.9.0: 12 Pass / 1 Partial on Principle IX with both causes justified in Complexity Tracking), research.md (E-1…E-10 findings, D-1…D-12 decisions), data-model.md (11 entities with the authored/derived split as the load-bearing invariant), 4 contracts (goal definition, goal command, team territory + overlap, write-set + migration), quickstart.md, feature-ref.md, and a frozen test baseline (40 failed / 1308 passed / 1 skipped) with the one new failure diagnosed as branch-state-dependent rather than a regression. Generator behavior was verified by execution against the shared-goal fixtures rather than read from source, which revealed the report already emits contributing_teams — a proto-roster the design extends instead of duplicating. Feature 041 advanced Draft to Planned in both index and detail; requirement status advanced likewise. Plan integrity gate passed: single top-level heading, stamp present, zero residual placeholders, zero deliberation markers across all nine artifacts.

## Optimization Points
- ## Optimization Points
- **The command mandates a codebase exploration pass but gives it no output contract, so its findings have nowhere to bind — and this run proved the pass is where spec defects surface.** Phase 0 says "run a dedicated exploration pass … use the findings to confirm or refute the spec's documented assumptions in one round". It did exactly that and **refuted two**: the migration surface was cited as 37 files when the real live surface is 24 (with 18 historical files that MUST NOT be touched), and SC-011's "whole-repo residual references = 0" was **unachievable by construction** because the spec's own Clarifications entry quotes the old path verbatim as the user's directive. Nothing in the command says what to do when the pass refutes an assumption — only step 2's spec-restructure rule, which is scoped to `$ARGUMENTS` changing scope, not to measurement being wrong. I amended `requirements.md` and logged a fifth Clarifications session, but that was inference. **Proposed fix**: extend step 2's spec-restructure trigger to include "exploration refuted a documented assumption or measurement", and require each refutation to land as (a) a corrected spec statement and (b) a dated Clarifications entry recording the old value, the measured value, and the method — so the correction is auditable rather than silent.
- **"Verifiable acceptance criteria" needs a feasibility check, not just a testability check.** SC-011 was testable (`grep | wc -l == 0`) and still impossible, because the artifact under measurement necessarily contains the string being counted. The requirements checklist asks "success criteria are measurable" — it never asks "is the target value reachable given what the repository must retain". This class of defect survived four clarify sessions and one checklist re-validation because every reviewer, including me, checked the *form* of the criterion instead of executing it. **Proposed fix**: the plan's Phase 0 should execute each success criterion's stated collection method once against the current tree and record the observed baseline value. A criterion whose baseline cannot move to its target is a spec defect found in minutes rather than at verification time.
- **`create-new-plan.sh` still overwrites `plan.md` unconditionally, and the command's step 1 tells you to run it before step 2 tells you the spec may need restructuring first.** I checked for `plan.md` before scaffolding, but only because this repo's AGENTS.md carries the scar. The script has no `--force` gate and no existing-file guard (documented in the repo's Recurring Operational Lessons after it destroyed hand-authored plan content in 036). **Proposed fix**: either add an existence guard to the script (refuse without `--force`) or make the command's step 1 read "verify `plan.md` does not exist; if it does, amend in place and do NOT run the scaffold". Relying on each agent's memory of a past incident is not a control.
- **[token-efficiency] Delegating the exploration to a subagent was the right call and the command should say why, not just that.** The pass consumed ~2.4M subagent tokens and returned ~900 words of structured findings with exact paths and line numbers — work that would have cost far more in my own context, and would have polluted it with dozens of file reads I never needed again. The command says "use an Explore subagent when available" without explaining the economics, so the natural failure mode is doing it inline. Two things made the delegation pay off and belong in the guidance: a **numbered question list** (seven questions, each answerable with paths and counts) rather than an open brief, and an explicit instruction that **file-list completeness matters more than brevity** — which is what produced the live/historical split that corrected the spec. **Proposed fix**: give the exploration step a required shape — enumerated questions, "paths and counts over prose", and a note that the findings must be persisted to `research.md` rather than held in context.
- **[token-efficiency] The Post-Generation Quality Gate's deliberation-marker scan should be a script, not a reading pass.** The command lists ten marker phrases and asks for a review pass over every generated contract. Re-reading five artifacts to look for ten fixed strings is precisely the "fixed-rule text judgment" that Program-First assigns to a program; I scripted it (one pass, all nine artifacts, zero hits) instead. The same script also covers the plan integrity gate's three checks (single `# Implementation Plan:` heading, the `Requirement → Feature` stamp, residual `[UPPER_SNAKE]` placeholders) and the constitution-row tally. **Proposed fix**: ship these as one validator invoked by the gate, so the gate produces a verdict rather than asking the agent to re-read its own output.
