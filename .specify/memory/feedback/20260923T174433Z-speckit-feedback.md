## Optimization Points
- **派发禁令 MUST 禁「效果」而不是禁「命令名」,否则会把可完成的审计逼成移交**。本轮把 T058 交给子代理时,禁令写成「`regen-command-copies.py`(任何模式)」与「`feedback-utils.py` 的任何写入类 action」,子代理据此把两项本可完成的核验记为 NR、T058 记为 `[~]` 移交,连带 GATE-7/GATE-1 停在红。实测:`--check` 是**只读**模式(EXIT=0、输出 `OK: all per-tool command copies match the source templates.`);`--action record --workspace-root <mktemp -d>` 完全不触及真实存据(隔离根内 `count = 1`、真实库 `total_entries` 前后均为 3、临时根删净残留 0)。二者一解禁即核完,T058 改判 `[X]`、九项门禁全绿、Feature 052 得以推进 `Implemented`。建议:派发里凡禁引擎,禁的应是**效果**(「MUST NOT 改动真实存据 / MUST NOT 写镜像 / MUST NOT 再生副本」)并**显式点名允许的只读模式**,而不是禁命令名;否则子代理会诚实地把可做的事判为不可做,而编排者收到的是一个看起来合规的移交。这与 § 十二 的盲检同族:回传形态正确,却不是关于它被写来判定的那个命题。
- **凡对真实仓库状态取样的契约测试,都会在每个特性的 requirements→plan 窗口内变红**。实测 `tests/contract/test_specify_script_paths.py::test_review_prerequisite_flags_are_supported` 以 `check=True` 对真实仓库跑 `check-prerequisites.sh --include-plan`,而该脚本把当前特性解析为**编号最高**的 spec 目录;新开的 053 只有 `requirements.md`、无 `plan.md`,于是 exit 1、测试变红——而其 docstring 声明的命题只是「这些旗标被接受」。后果:任何一次 `/speckit.requirements` 都会让契约套件红一条,直到 `/speckit.plan` 跑完;而这条红会被误当成上一个特性的回归(本轮它就一度让 Feature 052 的 GATE-1 判红、阻断状态翻转)。已按该命题重修:拒旗标表现为 usage / `Unknown option`,而「缺 plan.md/tasks.md」恰是 `--include-*` 被解析执行的**证据**,两种结局都通过,并配反空真哨兵(容忍的非零退出 MUST 匹配 `(plan|tasks)\.md not found`);变异演练注入 `--include-bogus-flag` → 哨兵变红并点名 `Unknown option` → 精确反向替换复原 → BYTE-IDENTICAL、7 passed;exit-0 臂另在临时 worktree 中实跑取证。**建议把「MUST NOT 对真实仓库状态取样」写成契约测试的一条通用规则**——同族风险不止这一处:任何断言「当前特性的某制品存在」的测试都有同样窗口。
