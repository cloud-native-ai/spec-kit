## Review
Ran improve-skills on the docs skill family after the user asked to move create-docs' higher-order operations out of it. Two user decisions redirected the target: the Hugo presentation layer went to the pre-existing create-pages skill (not improve-docs), and all Hugo-related hard constraints were to be removed rather than relocated. Delivered: 11 files git-mv'd create-docs -> create-pages (scaffold-hugo.py + assets/hugo/ + references/hugo-site.md) with ownership strings corrected; create-docs stripped to basic structure (198->171 lines, baseline item 5 and the Hugo dispatch section deleted, R1/R5/R6 site hooks removed, site triggers dropped) while keeping the protective site-tooling-skip rule the reconcile loop still needs; create-pages restructured into two explicit modes with a mutual-exclusion guard; improve-docs rewired to a three-way ownership boundary; spec 033 C-13 narrowed and C-14..C-17 withdrawn with numbering preserved; contract test retargeted to create-pages and made skip-when-absent so no docs space is required to have a site; _OBSOLETE_SKILL_FILES added so init reclaims the moved paths. Verified: shape gate exit 0 on all three touched SKILL.md, mirrors byte-equal (sync-mirrors --check exit 0), moved scaffolder executed from both source and mirror paths (drift clean), docs-utils validate unchanged at 1 pre-existing violation, and a clean-worktree failure-set diff attributed both deltas to working-tree artifacts (gitignored tmp/e2e-* scratch dirs reproduced the c10 failure on clean HEAD; __pycache__ residue caused the summarize mirror failure, green after clearing).

## Optimization Points
- ## Optimization Points
- **Add a contract-conflict escalation branch to Step 3/4.** The hard rule "never slim a section that a feature spec or contract test mandates inline" fired correctly here (spec 033 C-13…C-17 pinned the Hugo layer to `create-docs`, and `tests/contract/test_hugo_scaffold_contract.py` asserted its files), but the rule's only prescribed outcome is "keep it inline and slim elsewhere". This run needed a third path the playbook does not describe: surface the conflicting clauses to the user, get an explicit decision, then amend the contract **and** its tests in the same change. Concretely: extend `references/loop-playbook.md` §Step 3 with a "contract conflict" branch — quote clause IDs + test paths, ask once, and require contract-clause amendment (withdraw/narrow, numbering preserved) plus test retarget as one atomic edit.
- **Cover cross-skill asset relocation in the Step 5 downstream-wiring checklist.** The checklist covers rename/consolidation/removal of a whole skill/command/template, but not "files move from skill A to skill B", which has two extra obligations discovered only by reasoning from the recorded init-reclaim lesson: (a) `sync-mirrors.py` never deletes, so the mirror copies under the losing skill must be removed explicitly, and (b) the additive `copytree` in init leaves the moved files behind in every upgraded workspace, requiring a per-file reclaim registry (this run had to add `_OBSOLETE_SKILL_FILES` + cleanup step + test, since only whole-directory `_OBSOLETE_SKILLS` existed). Add it as a named case with both steps.
- **Baseline must be captured from a clean worktree before the first edit.** Step 6 prescribes a clean-baseline failure-set diff but does not say *when* to capture it. This run launched a background full-suite baseline and then started `git mv`-ing files while it was still running, producing a contaminated failset (55 failures vs the true 43) that had to be discarded and re-run in a `git worktree` — two wasted full-suite runs (~2 min). State the ordering explicitly: capture the baseline in a `git worktree` of clean `HEAD` **before** any write, or treat the failset as void.
- **token-efficiency**: validating that the relocated script still runs was done with `--action mounts`, which dumped the entire computed module-mount TOML block (~2.5KB of machine payload) into context when only "exit 0 / no traceback" was needed. Step 6's "reference code is executed, not eyeballed" rule should add: assert on exit status or a projected field (`>/dev/null; echo $?`, or a `python3 -c` field projection) rather than piping a script's full structured output into the conversation.
