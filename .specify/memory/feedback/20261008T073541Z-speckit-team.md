## Optimization Points
- 1. **共享文件的整文件 staging 会折叠并行流的内容**:两支流水线同改一个文件(如 .specify/instructions.md)时,按路径 staging 必然把对方的行带进自己的 commit —— 本轮 70721de7 夹带了并行会话 418 B 导览行,而文件清单层的核查(我只 add 了我改的路径)拦不住它。建议:commit 前对共享文件做「foreign-content 检查」—— git diff 该文件并核对每处改动是否出自本 run 的编辑清单,非本 run 的行要么先由对方提交、要么在报告里显式声明出处;这条应进 00-cross-cutting-lessons(现有「git diff 三态核查」条目未覆盖跨流共享文件场景)。2. **交互式 shell 别名使删除/复制类操作静默不生效且返回 0**:本轮 rm 被 rm -i 别名拦下、EOF 读入后放弃删除却 exit 0,链条误报成功 —— 与早前 cp -i 同类,已是本 session 第二次。建议:代理环境的关键写操作(删除/覆盖)一律走 python os.remove/os.replace 或 command rm,并把「别名使 shell 语义失真」并入现有 shell 陷阱课程(00-cross-cutting-lessons 的 grep/shell 陷阱域)
