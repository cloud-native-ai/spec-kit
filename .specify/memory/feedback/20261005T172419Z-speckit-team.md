## Optimization Points
- **`Overlap:` 字段与 `verify-territory-disjoint.py` 同域,跨 goal 的写域冲突对两者均结构性不可见。** 本轮实测:本团队 write 含 `templates/commands/improve.md`,并行会话的 `command-logic-as-classified-skills` 团队 write 含 `templates/commands/*.md`,后者**包含**前者;而 verify 脚本的检查集按其 docstring 明写为「proposed teams ∪ existing teams under the same `goal_slug`」,run 报告的 `Overlap:` 字段同样只统计共享同一 goal_slug 的团队。两团队 goal_slug 不同,故这一对**从不进入比较** —— 不是"跑过了没报",是**不会跑**。后果:两个并行会话可同时持有对同一文件的写权而互不知情,且该状态在两份制品里都显示为干净。建议先裁定 territory 的语义是「同 goal 内互斥」还是「全仓互斥」,再据此扩 verify 的检查集或给 Overlap 增加一档 cross-goal 计数。
- **`run-checks` 的 exit 0 容易被读成「可以开工」。** 本轮引擎五项检查全部通过(且 check 2/3/4 正确记 `not-evaluated` 而非 `ok`),`blocked: false`,但 run 仍必须在预览阶段停止 —— 四项阻塞全在引擎判定域之外(命名须走用户批准通道、判据四量之一无口径、一条规则的现状身份不明、跨 goal 写权冲突)。命令模板已明写「`blocked` 才是『本次 run 必须停』的字段」,却没有说明**引擎不阻塞 ≠ 可以派发**。建议 Run Mode 步骤 6 补一句:派发前另需过一道 agent 侧的 fast-fail 判据检查,引擎 verdict 只覆盖 Target/goal 绑定轴。
