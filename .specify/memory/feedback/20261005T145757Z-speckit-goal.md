## Review
本轮为 modify 相:写入一条判据(前值 None provided.),并处置了对 objective 范围与 Target 归属的翻供。objective 未改——用户举证「标注是 skill 化不可或缺的一面」(skill 化必然产出大量从 command 提炼的新技能,不标注则干扰既有分发与处理体系),我撤回上一轮「objective 范围不再含标注」的误读,该误读未落盘故无跨度可回滚。三条 Target 经用户裁定全部保留,递进顺序 S1→S2→S3 移交团队计划(goal 层无处记顺序:表结构无顺序/依赖列,概念明禁切片间依赖边)。实测发现判据复述档只做归一化字面相等,语义复述放行,用户知情后选择保留 T-003,构成对概念 MUST 的一次实际穿过。术语条目 技能分类标注 (Skill Classification) 扩写纳入上述因果。引擎动作全部 exit 0,validate 通过。

## Optimization Points
- **复述档只做归一化字面相等,换词复述检不出(盲检类)。** `_validate_target_statement` 的判据复述检查是 `normalized == _normalize(criterion)`,而 `_normalize` 只转小写并剔除非字母/数字/CJK 字符(真源 `goal-utils.py:693-704` 与 `:252-254`)。本轮实测:判据写入后,一条与判据语义同义但措辞不同的 Target 陈述,`targets --check` 仍报 `verdict: ok`、`scope: shape+criteria-restatement`。该 scope 字面量会让读者以为语义复述已被守卫。建议:要么把该档如实渲染为 literal-only,要么在概念文档明写这条诚实边界——与 §判据主体指代形 里「散文枚举与指代形同现检不出」同一处置口径(记录取舍,不假装守卫)。
- **规则与守卫之间有一道已被实际穿过的缺口。** 命令 step 5 与 `goal-definitions.md` 都把「Target 不得复述判据」写成 MUST,可执行守卫只覆盖逐字拷贝。本轮用户在知情下选择保留一条语义复述判据的 Target(T-003),缺口从"理论存在"变成"本仓已有实例"。后果在总结层:里程碑是判据的投影,与判据同义的 Target 会让「范围覆盖」与「终态达成」两条轴重复计数。
- **`criteria` 的整集替换语义在命令模板里没有讲。** 该动作以传入的 `--criterion` 全集覆盖既有判据集(缺参一律 exit 2,不是查看入口),多条判据必须一次传全;这一点只出现在 `--help` 与缺参报错文本里(真源 `goal-utils.py:1293-1299`)。本轮靠读源码确认。建议 step 4 的读/写分组处一句话点明,避免调用者分两次传而静默丢掉前一批。
- **`targets` 没有改写陈述的动作,这一点命令模板也没讲。** 措辞写错只能 `--set dropped` 再以新序号 `--add`(身份单调发放、永不复用),废行永久留在定义文件与 `## History`。建议 step 5 明示这条不可逆性,使「先定措辞再 add」成为通用落盘前纪律,而不是每次靠现场查 `--help` 发现。
- token-efficiency — 本轮为查证复述档行为定点读了 `goal-utils.py` 两段源码(约 45 行),属必要;但同一轮里把 `goal.md` 整篇读了两次(create 后、criteria 写入后),第二次可由 `validate` + `targets --list` 的结构化输出替代,整篇重读是重复读取。
