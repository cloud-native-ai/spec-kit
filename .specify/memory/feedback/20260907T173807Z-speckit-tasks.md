## Optimization Points
- **命令自身的 Feature 列表复审义务差点被我写成一条实现任务(T051),而这是范畴错误**:outline 的 Feature Integration 段说「the tasks phase MUST review the Feature list — task breakdown may expose new Features or invalidate old ones」,我起初把它落成 Polish 阶段的一条 `- [ ] T051 Feature 列表复审(tasks 阶段义务)`,等于把**生成期义务**推给实现期。后果是具体的:我还在该任务里**预写了结论**「未触碰 032/008/001/022/028/046 的能力面」,而真正现在做这次复审立刻发现了反例——T011 补齐 `HERMES.md` / `.opencode/instructions.md` 闭合的正是 **Feature 022「所有官方支持工具获得完整初始化覆盖」范围内**的既有缺口(`_check_instructions` 对这两个 key 恒 fail),需要同步记入 `features/022.md`。若按原样留给实现期,这条预写结论会被当成已核实的事实照抄进 Feature 记录。建议在 Feature Integration 段补一句显式禁令:**该复审是生成期义务,其结论可能改变任务列表本身,MUST NOT 作为任务行下沉到 tasks.md**;并要求把复审结论(含"无变动")写进报告而非工件。
- **plan → tasks 的制品面漂移没有归口:命令只说"加载 plan.md",没有说"分解结果与 plan.md 记录不一致时同批订正 plan.md"**:plan.md 的 Technical Context / Scale&Scope / Source Code 树 / Principle IV 证据行都写着"3 个新契约测试文件",而任务分解阶段依 Principle IV(纯函数必须有单元测试)与"一契约一测试文件以保 `[P]` 资格"确定实际需要 **8 个**(4 契约 + 1 单元 + 3 集成)。我发现后回改了 plan.md 四处,但**流程里没有任何一步提示要做这件事**——outline step 2 是"Load design documents"、step 3 是"Load plan.md and extract tech stack, libraries, project structure",都是单向读取。若不主动回改,漂移会留给 `/speckit.analyze` 事后发现,而那时 tasks.md 已经按 8 个文件写完、plan.md 成了误导后续读者的陈旧记录。建议在 step 3 或 step 4 增一条:**当任务分解隐含的制品清单与 plan.md 记录的数量/形态不一致时,在同一次运行内订正 plan.md 并在报告中列出订正点**(与 requirements 阶段"spec-restructure first"的既有纪律同构,只是方向相反:这里是 tasks 反向修 plan)。
- **Tests Mode 的 ON/OFF 二分与 template-only 门,对"混合型特性"没有给判据,导致豁免范围容易被整体误用**:命令说 Tests Mode 由 constitution 的 test-mandating 原则决定(ON),又说「Template-only / doc-feature gate: if the constitution carries a *template-only features* principle … emit **structural contract tests** — not unit/integration tests, which have nothing to run against」。本特性恰好两面都有:`templates/instructions-template.md` 章节、`shared/guidelines/*.md`、种子 JSON 是**文档/模板制品**(结构契约测试即可),而 `scripts/python/trigger-utils.py` 是**可执行运行时代码**(Principle IV 的"纯函数必须有单元测试""验收场景转为自动化测试"完整适用)。照字面读"if the constitution carries a template-only principle → emit structural contract tests, not unit/integration",很容易整体豁免掉引擎的单元与集成测试——而 `constitution.md:95` 的原文限定是「features with **no executable runtime code**」,是按**特性有无运行时代码**判定,不是按特性是否**含有**模板制品判定。建议把该门的表述改为**按制品面逐个判定**:同一特性内,文档/模板面走结构契约测试,运行时代码面照 Principle IV 走单元 + 集成,并在 banner 里同时声明两面(本次 banner 即按此写)。
