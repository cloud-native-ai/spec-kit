## Optimization Points
- **`_write_intersections` 从不减 `forbidden`,使 schema 自己规定的冲突解法在机器下不成立。** create-mode.md 的 schema notes 明写「a write intersection is a contested area that must be resolved to a single owner **or a forbidden-write entry**」,但 `build-summary-input.py:608-609` 的实现是 `[[x,y] for x in wa for y in wb if scopes_overlap(x,y)]` —— 只比 write×write,`forbidden` 仅在 `:170` 被 expand 后序列化,从不参与 overlap 判定。后果:按 schema 指示用 forbidden 条目解开的争用,`verify-territory-disjoint.py` 仍会报 overlap 并 exit 4 阻止落盘,**同一 goal_slug 下也如此**。本轮实测:在对方 team.md 加了 `templates/commands/improve.md` 到 forbidden 后,write×write 的 glob 包含关系依旧成立。建议二选一:要么让 `_write_intersections` 从两侧 write 里减去各自 forbidden,要么把 schema notes 的「or a forbidden-write entry」删掉并明写只有「单一 owner」是机器认可的解法——两者都需要先定,不能维持文档说可以、代码说不行。
- **确认门控预算是 territory 表达不了的共享约束:两个写域不相交的团队可以共同耗尽同一个预算。** `scan-confirmation-gates.py` 的 total 上限 23、实测 23、余量 0,而 SCAN_DIRS 是 `templates/commands`、`skills`、`shared` —— 任何团队在这三个目录下新增一个 BLOCKING_PATTERNS 命中都会打爆两个契约测试,与它的 write 路径是否和别的团队相交**无关**。本轮两个团队各自在 `territory.non_path` 里独立记了一份 `type: ceiling`,于是同一个字面量 23 现在有两份副本 —— 这正是 One Source of Truth 要消灭的形态(改一次要改两处,且漂移不可见)。建议:该数字的 owner 应是 `shared/guidelines/confirmation-gates.md` 或直接是那两个契约测试里被 pin 的字面量,两份 non_path 改为引用而非复述。
- **本轮直接编辑了两个 team.md,绕过了 modify 的既定路由(`improve-team`)。** 依据是用户对 B4 的明示授权,改动也限定在 territory 与裁定记录,但 `/speckit.team` 的路由表把「修改团队」归 `improve-team`,本次是手工编辑。缺的是一条**轻量授权改动路径**:为一行 forbidden 排除条目走完整的 improve-team 流程与其证据要求不成比例,于是现实里就会出现绕过。建议要么给 territory 级的裁定类改动开一条具名的轻量入口,要么明写这类改动也必须经 improve-team、并接受其成本。
