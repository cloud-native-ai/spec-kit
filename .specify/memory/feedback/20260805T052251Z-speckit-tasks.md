## Optimization Points
- ## Optimization Points
- **The Mirror Obligations → task-pair rule doesn't survive a repo with a single fan-out command, and the command gives no escape hatch.** The doc-feature phase shape says "for **each row** of plan.md's *Mirror Obligations* table, emit a **paired task set**" — one dual-write task plus one parity-verify task. This plan's table has 10 rows, but all fan-out is performed by exactly one command (`sync-mirrors.py --write`), so a literal reading produces 10 identical write tasks. I emitted one fan-out task per phase plus **grouped** verify tasks (skills / templates+per-tool copies / scripts), which preserves the rule's actual intent — mirrors are first-class tasks, never implicit side-effects — without 20 rows of ceremony. **Proposed fix**: reword the rule as "every mirror row MUST be covered by an explicit write task and an explicit verify task; rows sharing one fan-out command MAY share the write task, but each verify task MUST enumerate the rows it covers". As written, the rule reads as per-row and quietly punishes repos that solved fan-out properly.
- **Nine of my 68 tasks initially had no file path, and only a script caught it — the format rules should be validated, not just stated.** The command spells out the checklist format with ✅/❌ examples including "❌ WRONG: missing file path", then asks the agent to self-confirm in the report ("Format validation: Confirm ALL tasks follow the checklist format"). Self-confirmation by re-reading is exactly the wrong instrument: I *believed* the tasks were compliant, and a 20-line validator found nine that named only behavior ("treat criteria as measured-by-degree", "fan out and verify mirrors"). It also caught that `[blockedBy: Txxx]` in my own Format documentation looked like a dangling reference, which is a useful false-positive class to know about. **Proposed fix**: ship the validator (checkbox+ID+optional [P]+optional [Story]+file-path regex, ID contiguity, story-label-by-phase, `blockedBy` resolution and no forward/self references, DoD/GATE prefix purity) and have step 6's format validation report its output rather than the agent's opinion.
- **The Tests-Mode banner has no vocabulary for the hybrid case, which is the common case in this repo.** The command offers two shapes: tests ON, or the template-only gate citing structural contract tests. This requirement is genuinely both — a validator plus overlap detection plus path normalization are real code needing unit and integration tests, while the command template, skill prose and references are template-only artifacts whose "tests" are content and mirror-parity assertions. Picking either banner alone would have misdescribed half the work and mis-shaped half the test tasks. I wrote a hybrid banner naming both principles and which deliverables each governs. **Proposed fix**: document the hybrid explicitly and require the banner to partition the deliverables — "structural contract tests for {artifact classes}, unit/integration for {artifact classes}" — because a spec that adds both a template and an engine is the norm in a prompt framework, not the exception.
- **[token-efficiency] The environment-prerequisites probe is well specified but its cheap negative result has no home.** The command requires probing external environments at generation time and emitting per-phase prerequisite blocks. I probed (Python, pyyaml, sqlite3, pytest, and confirmed no docker/network is needed) and everything passed — so there was nothing to defer and no phase needed a prerequisites block. That "all clear" is still worth one table, because the *next* run would otherwise re-probe from scratch, and because "no network needed" is a non-obvious conclusion here (the invoked `summarize-project` skill can reach a PlantUML server, just not on any path this requirement exercises). **Proposed fix**: state that the probe result is recorded even when fully satisfied — a single table with the probed versions — so the negative result is reusable evidence rather than discarded work.
- **[token-efficiency] Generating tasks from artifacts I had just written was near-free, and the command should say to exploit that ordering.** Because `/speckit.plan` ran immediately before in the same session, `data-model.md`, the four contracts, and `research.md` were already in context with exact line numbers (`build-summary-input.py:577`, `SKILL.md:666`, `test_summary_trigger.py:215`), so tasks could name precise insertion points without re-reading anything. Step 2 says "Load design documents … Read from REQUIREMENTS_DIR" unconditionally, which invites re-reading files whose content is already present. **Proposed fix**: add a load-skip clause — if an artifact was authored or read earlier in the same session and is unmodified since, cite it instead of re-reading, and re-read only on a detected mtime change. The savings scale with how well the preceding plan phase did its job.
