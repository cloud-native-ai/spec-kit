## Optimization Points
- Run mode executes one stage-batch per invocation, but the preview gives no way to know how many batches remain. The team design accumulates over N dispatches (S0: 5 batches; S1: one command -> one package; S3: 5 batches), yet nothing in the preview surfaces "this run will finish batch k of N" — I had to reconstruct the denominator myself from the stage's `task` prose plus a fresh `find templates/commands | wc -l`. The five engine checks answer whether the run is *allowed*; they say nothing about how much of the chain is left, so a user asking "run this team" cannot tell whether they are getting 5% or 100% of the work. Surfacing the resolved batch denominator (and the stage's completion ratio) as a sixth disclosure line would make the preview honest about cost.
- A handed-off stage is invisible to the receiving team's run until someone reads the other team's progress file. The previous run split its S-layer into "B1/B2a/B2b/B2d done here" and "B2c/B2e/B3-B7 handed to skill-layer-install-separation", and this team's S1 was gated on that handoff. The gate was real but had no representation: S1's `blockedBy` names only S0, and the precondition existed solely as prose in a git-ignored progress file. I could only establish "the precondition is satisfied" by closing the other team's goal and cross-reading both progress files. Cross-team stage dependencies deserve a declared form — at minimum a named precondition that the run preview can resolve and report as met/unmet.
- The command census drifted between the ruling and the run, and the stage gate's "don't use literals, re-scan" rule is what caught it. S0's rulings carry as-of counts (25 commands, 34 SKILL.md) that no longer match reality (26 commands, 26 SKILL.md after a six-skill merge). Because the stage gates are written as "re-run the command to get the denominator, never use the literal", the mismatch was detectable rather than silent. That pattern is worth generalizing: any gate that divides by a count should be required to name the command that produces it, as these do.
