## Optimization Points
- ## Optimization Points
- **The shell-hygiene rule covers aliased `rm`/`cp` but not content substitution, which fails the same way and bit me twice in one task.** T011 rewrote 41 path literals across 9 test files. My first pass reported a perfect result — every file went "N -> 0" residual occurrences — and was **wrong**: the rule `.specify/project/goal/` → `.specify/goal/` silently dropped the `summary/` segment, so every test would have looked for `.specify/goal/demo/data/...` while the generator wrote `.specify/goal/demo/summary/data/...`. The absence of the old string proved nothing about the correctness of the new one. I caught it only because I inspected the resulting forms before running anything, reverted, and redid it with a slug-aware regex. Then a *second* instance evaded even that: `delivery_dir()` built the path in pieces (`root / f".specify/goal/{SHARED_GOAL}"`), so no literal matched and four concurrency tests failed with FileNotFoundError. **Proposed fix**: extend the shell-hygiene clause to bulk content rewrites — a substitution task's verification MUST assert the **new** form is present and correct (not merely that the old form is gone), and MUST include one behavioral execution, because piecewise construction is invisible to any text search.
- **"Migrate paths only, never weaken assertions" needs a third category: assertions *about* historical documents.** FR-024 and the migration contract gave me two faces, live and historical, and I applied them to files. But one *live* test (`test_summary_writeset.py`) reads a *frozen* 036 spec contract, and the blanket rewrite changed its assertion to expect the new path from a document that legitimately still says the old one. Neither "migrate it" nor "leave it" is right at file granularity — the test is live, its subject is historical. The correct resolution was to keep 036's wording, document why in the docstring, and point at where the live truth is now pinned instead. **Proposed fix**: the migration contract should classify by **assertion subject**, not by file: an assertion whose subject is a frozen artifact keeps that artifact's wording and gains a comment naming the live replacement pin.
- **A migration sweep flags its own guards, and nothing in the task shape anticipates that.** My `test_no_live_face_file_retains_the_old_path` swept the repo for the old path and immediately failed on three files: the two suites I had just written plus `test_summary_trigger.py` — all of which must *name* the old path in order to assert its absence. The finding was real from the sweep's perspective and meaningless in fact. I fixed it with an explicitly-listed `GUARD_FILES` tuple rather than a silent pattern filter, so a future reader can see what the sweep does not cover. **Proposed fix**: when a task authors a repo-wide absence sweep, the task should require an explicit, named exclusion list for the guards themselves — the alternative (a regex that happens to exclude `tests/`) would quietly stop covering real test-side offenders.
- **[token-efficiency] The canonical runner plus `comm` is dramatically better than what I did earlier in this same session, and the command should make it the only sanctioned form.** `run-tests.sh --names-out` + `comm -13 baseline current` gave an unambiguous zero-regression verdict in one call, and it caught something a count comparison would have hidden: at one point the suite showed *more* passing tests and *more* failures simultaneously (45 failed / 1336 passed), which only makes sense as "33 new tests added, 6 broke" — a count-only check would have read the rising pass count as progress. Earlier in this session I used `pytest -q | tail` pipelines whose exit code is masked by the pipe. **Proposed fix**: the command already prefers the runner; it should go further and state that a regression claim expressed as counts is not acceptable evidence — only a name-level `comm` diff is.
- **[token-efficiency] Phase-boundary committing worked, and the commit gate should say to do it at every phase rather than "after each task or logical group".** Phase 2 touched 30 files across canonical sources, four mirrors, five generated copies, nine tests and two new suites. Committing it as one unit gave a reviewable, self-contained increment matching the plan's own sequencing caution, and it means the audit trail survives even though 55 tasks remain open. The current wording ("commit after each task or logical group") is vague enough to permit both per-task noise and a single end-of-run mega-commit; the phase boundary is the natural unit because that is where the regression gate sits. **Proposed fix**: name the phase boundary as the default commit unit, with the phase's own gate task as the commit precondition.
