## Delegation

`/speckit.measure` is a **thin entry**: it names the script and the action to run, and it renders nothing itself. Every
record read, every figure, every exclusion count and every exit verdict belongs to the script — a second projection
authored in this command would be the defect the measure contract names. The rules themselves are owned by
`measure-report.contract.md` (C-53…C-62) and by the store engine `scripts/python/exec-quant.py`; this command
reaches them by name and restates none of them.

**Script**: `scripts/python/measure.py`, run from the repository root with plain `python3` (stdlib only). It writes
nothing, spawns nothing and reads the store only through the engine's own read path.

**The two actions** (closed set — neither a third nor a missing one is legal):

| Action | Invocation | What it answers |
|--------|------------|-----------------|
| `summary` | `python3 scripts/python/measure.py --action summary [--since <start> --window <span>] [--unit <id>/<type>]… [--cap <n>]` | the human-readable report — resolved window, selection, printed cap, per-unit figures with provenance, the exclusion counts |
| `json` | `python3 scripts/python/measure.py --action json …` | the same computed result under the exact top-level key set the contract owns |

**Inputs the script resolves for itself** (this command passes none of them): the store location under the workspace
(the current directory unless `--workspace` says otherwise), the per-unit record cap (its declared default, printed on
every run), the newest-record selection and the exclusion classification. `--since`/`--window` must be given together
or neither; an unbounded run measures all records.

**Exit statuses** (closed four-value set; the script is the owner of the meanings, this table only names them):

| `0` | `1` | `2` | `3` |
|-----|-----|-----|-----|
| a report was rendered (including `0 figures measurable` when every quantity is not-evaluated) | any other failure | input error — the offending value echoed | nothing to analyse — the explicit `no measurements` rendering |

Run the action the input selects, print the script's output verbatim, and report its exit status. Do **not**
paraphrase a figure, re-render a row, or soften `no measurements` into an empty result: a store with no matching
record answers explicitly with status `3`, and that is the correct answer, not a failure.
