# Spec Kit Framework Map

Single source of truth for the `.specify/` layout map. Referenced from the `## Spec Kit Framework Map` summary in `.specify/instructions.md` — keep that summary a pointer; the table lives here.

This is a **map, not a manual**: it tells you *what* exists and *where* it lives; the *how* belongs to the documents each row points to. The framework state lives under `.specify/`:

| What | Where | Notes (what lives there — not how to use it) |
|------|-------|-----------------------------------------------|
| Project anchors | `.specify/constitution.md` + `.specify/features.md` + `.specify/glossary.md` + `.specify/register.md` | Canonical project-level anchors at the `.specify/` root (2026-11-10 anchor-layout move); the features index plus per-feature details under `.specify/features/<ID>.md`; the durable-identifier register; the canonical-terms glossary |
| Session memory store | `.specify/session/` | Agent-context memory, short-term and forgettable — one Markdown entry per record, index derived on read; seeded by `specify init`; owner: scripts/python/memory-utils.py; lifecycle: memory-tier; content class: agent-context memory (short-term) |
| Knowledge memory store | `.specify/knowledge/` | Agent-context memory, long-term and distilled — one Markdown entry per record; seeded by `specify init`; owner: scripts/python/memory-utils.py; lifecycle: memory-tier; content class: agent-context memory (long-term) |
| Feedback store | `.specify/feedback/` | Feedback records plus store bookkeeping, one Markdown entry per record; owner: scripts/python/feedback-utils.py; lifecycle: runtime-record; content class: feedback records |
| Evidence store | `.specify/evidence/` | Evidence run findings, one run directory per record; owner: scripts/python/evidence-utils.py; lifecycle: runtime-record; content class: evidence runs |
| Exec-quant store | `.specify/exec-quant/` | Per-unit run measurements, one JSON record per unit-run, plus `aggregated/` views; owner: scripts/python/exec-quant.py; lifecycle: telemetry; content class: run measurements |
| Trigger store | `.specify/trigger/` | Proactive-flow state index (tracked) plus the ignored `telemetry.jsonl` stream; owner: scripts/python/trigger-utils.py; lifecycle: telemetry; content class: proactive-flow state |
| Retention store | `.specify/retention/` | Retention receipts, plans and ledgers, one file per run artifact; owner: scripts/python/record-retention.py; lifecycle: receipt; content class: retention artifacts |
| Renumber store | `.specify/renumber/` | Renumber plans and ledgers, one file per run artifact; owner: scripts/python/renumber-utils.py; lifecycle: runtime-record; content class: renumber artifacts |
| Sanitize store | `.specify/sanitize/` | Machine-regenerable findings cache and cleanup plan; never authoritative; owner: scripts/python/sanitize-utils.py; lifecycle: cache; content class: machine-regenerable cache |
| Housekeeping store | `.specify/housekeeping/` | Housekeeping run reports, one YAML per run; owner: skills/external/sdd-house-keeping/SKILL.md; lifecycle: run-report; content class: run reports |
| Coaching store | `.specify/coaching/` | Coaching run products, one directory per run; owner: skills/external/coaching-skills/SKILL.md; lifecycle: run-report; content class: coaching run products |
| Todo store | `.specify/todo/` | Human idea queue, one Markdown entry per parked idea; owner: skills/internal/manage-todo/SKILL.md; lifecycle: queue; content class: parked ideas |
| Tools store | `.specify/tools/` | Tool definition records, one Markdown entry per tool; generated `*.json` inventories are ignored; owner: scripts/python/tools-utils.py; lifecycle: definition-record; content class: tool definition records |
| Migrate receipt store | `.specify/migrate/` | Migration receipts, one JSON per run under `receipts/`; owner: src/specify_cli/__init__.py; lifecycle: receipt; content class: migration receipts |
| Tombstone — retired store root | `.specify/memory/` | Historical catch-all bucket; retired. Agent-context memory is carried by `.specify/session/` (short-term) and `.specify/knowledge/` (long-term); no engine may treat it as a live store. |
| Long-lived runtime state | `.specify/state/` | per-entry state kept across sessions (never one shared aggregate); e.g. SDD loop-driver line spines — owner: `shared/guidelines/directory-governance.md` §5 |
| Temporary workspace | `.specify/.tmp/` | git-ignored scratch, cleaned at work-item end; e.g. `.specify/.tmp/sdd-loop/` (worktrees, cache, tmp) — owner: `shared/guidelines/temp-directory-discipline.md` |
| Anchor archive | `.specify/anchoring/<slug>/` | Anchor definitions at `anchor.md` plus the derived `summary/` tree; the one anchor archive layer (`.specify/specs/` holds no definition subdirectory); owner: `/speckit.anchor` + `goal-utils.py`; concept: `definitions/anchor-definitions.md` § Archive Layers |
| Goal archive | `.specify/goals/<slug>/` | action-level Goal definitions at `goal.md` — short-horizon executable guidance with completion conditions, never a project-level objective; owner: `/speckit.goal` + `goal-utils.py`; concept: `definitions/goal-definitions.md` |
| Anchor archive destination | `.specify/archive/anchoring/<slug>/` | archived anchor entries, one `migration-receipt.json` per acted entry, archive-not-delete, never a definition read surface; owner: the engine's anchor archival action (`goal-utils.py` `cleanup --apply`, invoked from `/speckit.anchor`); concept: `definitions/anchor-definitions.md` § Anchoring Archive |
| History knowledge base | `.specify/history/` | distilled, theme-aggregated conversation knowledge; owner: `/speckit.history` + `history-utils.py` |
| Review reports | `.specify/review/` | archived code-review reports; owner: the `code-review` skill |
| Project summary | `.specify/project/` | `summary/` delivery directory plus legacy manage-project artifacts (read-only); owner: the `summarize-project` skill |
| Study reports | `.specify/studies/` | archived `study-code` output per target (`<target>-study/`: indexable `docs/overview.md`, outlines, strip manifest, figures, self-check evidence, target commit; the stripped source copy is not archived); owner: the `study-code` skill |
| Spec archive | `.specify/archive/spec/` | archived feature specs; owner: `/speckit.sanitize`'s archive-spec disposition |
| Goal/team archive history | `.specify/archive/goal-team/` | migration receipts (`receipts/`) and archived source trees (`trees/`), archive-not-delete; never a definition read surface; owner: `/speckit.anchor` `migrate-archive` (STR-003) |
| Migrate archive | `.specify/archive/migrate/` | objects archived by `specify migrate` applies — one tree per run at `<run-id>/<relative path>`, archive-not-delete; the run's receipt (`migrate/receipts/`) enumerates each entry with its recovery path; owner: `specify migrate` |
| Artifact templates | `.specify/templates/` | requirements/plan/tasks templates rendered by `/speckit.*` |
| Automation scripts | `.specify/scripts/` | bash/python engines invoked by commands and skills |
| Installed skills | `.specify/skills/` | one directory per skill (`SKILL.md` + references/ + scripts/) |
| Skills system guide | `.specify/skills.md` | how skills are discovered and created — no registry |
| Tools system guide | `.specify/tools.md` | how tools are recorded and discovered — no registry |
| Git workflow state | `.specify/workflow/git.md` | framework-level git workflow: branch-role managed block (the `.specify/workflow/` directory holds workflow state files), machine-maintained by the `git-utils` skill |
| **Agent Templates** | `.specify/agents/templates/` | capability descriptions — shipped role set installed by `specify init`; each `.agent.md` is self-contained |
| **Agent Instances** | `.specify/agents/instances/` | responsibility-bound agents authored in this project; reference a Template |
| **Agent Execution** | `.specify/agents/execution/` | dispatch `configs/` + `scripts/` (tracked); runtime `logs/` (gitignored, never committed) |
| Team archive | `.specify/teams/<slug>/` | team definitions at `team.md` + `runs/` reports; run intermediates in git-ignored `.work/`; owner: the team's own definition, team side owned by `skills/internal/create-team/references/conceptual-model.md` |
| Derivations | `.specify/derive/` | one derivation archive per topic (`<topic-slug>/derive.md`) plus the project-level reasoning-move library `moves.md` (engine-written, accumulating); record semantics in `definitions/derivation-definitions.md` |
| Shared definitions & conventions | `.specify/shared/` | canonical concept docs — e.g. agent taxonomy (`definitions/agent-definitions.md`), subagent modes (`definitions/subagent-definitions.md`), tool definitions, workflow conventions; two meta-skill owners (`definitions/mechanism-policy-definitions.md`, `definitions/skill-reference-definitions.md`) |
| Super Agent role | `.specify/shared/definitions/superagent-definitions.md` | single owner of the relative superagent/subagent role model — edge predicate, role depth, super↔sub protocol, `role-transition` injection, state-sync/recovery and visualization mapping; sibling pages carry pointers only (framework source: `shared/definitions/`) |
| Declaration layer contract | `.specify/shared/declarations/contract.yaml` | value domains the declaration layer is read through — schema and subset ids, five fact kinds, two completeness states, three exclusion reasons, three exit codes, required key sets, gate call sites; the discipline itself is `definitions/harness-triple-definitions.md` (framework source: `shared/declarations/`) |
| Declaration facts | `.specify/shared/declarations/facts/` | one fact per file, one file per fact — `<fact-slug>.yaml`, the path IS the identity; no index, no manifest, no cache (framework source: `shared/declarations/facts/`) |
| Declaration exclusions | `.specify/shared/declarations/exclusions/` | one file per exclusion reason (`<reason>.yaml`), each row carrying `unit` / `carrier` / `anchor`; rows are appended, never reordered (framework source: `shared/declarations/exclusions/`) |
| Context-management owner document | `.specify/shared/definitions/context-management-definitions.md` | Single owner of the context model — categories, layers, forms, landing contract, layout table, composition protocol, trigger set, composer roles, concept-pointer slot and presence vocabulary; the audit engine's declared input (framework source: `shared/definitions/`) |
| Context value-domain facts | `.specify/shared/declarations/facts/` | The four context facts — `context-categories.yaml`, `context-layers.yaml`, `context-forms.yaml`, `context-classes.yaml` — read by the audit engine through the declaration reader (framework source: `shared/declarations/facts/`) |
| Context audit entry | `.specify/scripts/python/context-audit.py` | The read-only audit invocation — `--action check` (layout integrity, nine rules) and `--action manifest --layer <layer>` (one declared layer's presence rows); no command or skill wrapper ships (framework source: `scripts/python/`) |
| Script interface contract | `.specify/shared/definitions/script-interface-definitions.md` | owner page for the rule every directly executable `*.sh` / `*.py` script obeys — candidate screen and classification, the mandatory flags and their mandatory content, the zero-side-effect boundary, the unknown-option rejection, and the `## Declared Exceptions` register; the checker `scripts/python/script-interface-check.py` and the guard `tests/contract/test_script_interface_contract.py` consume it, and the template/live constitution, instructions and generator mandate are pointers to it (framework source: `shared/definitions/`) |

| Feature specs | `.specify/specs/<ID>-<slug>/` | requirements / plan / tasks / verification per feature; a split parent MAY hold `slices/<slice-dir>/` — archived split-slice trees kept as data inside the parent spec (never a spec candidate; move and record owned by `/speckit.seal`'s `archive-apply` plus the parent's `archive-manifest.json`); no goal/team subdirectory — the definition kinds live in the archive layers above |
